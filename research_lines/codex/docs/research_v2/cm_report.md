## 1. 假设与 estimand

假设（§4.1）：routine 路由流形是一个**条件分布**——给定当前 token（C1）、局部可见文本（C2）、prefill 上下文
（C3），routine 的路由比无条件分布紧得多。任务偏移的离开由 (a) 词汇/上下文新颖与 (b) 同样的 token 被不同地
路由 两部分组成；把 (b) 从 (a) 中分离，既可能压低 benign/resist 误报，又回答 routing 是否有独立贡献。

Estimand（§4.2）：`s_t` 回答"最近 w 个 decode token 的路由，相对于'这些 token 在 routine 中通常怎样被路由'，
偏离了多少"。词汇新颖度（未见词比例）作为并列侧信道单列（= 基线 T2），不混入路由分数。

分数（预注册 §2；实现 `src/research_v2/scorers/cm.py`）：

```
ind_t  ∈ {0,1}^{L×64}                       逐层 top-8 入选指示（中间层 5–11 时 448 维）
E[ind|tok] = (n_tok·mean_tok + 5·μ)/(n_tok+5)     经验贝叶斯收缩，n_tok < 5 时退化为 μ
r_t    = ind_t − E[ind|tok_t]               （C1+C2 时再减去 ridge f(x_t)）
r̄_e    = mean_{t∈[e−w+1,e]} r_t
z_e    = (r̄_e − μ_R)/σ_R                    μ_R、σ_R 为训练侧 routine 的窗口残差统计量
s_e    = ‖z_e‖²                             （C3 时除以 exp(ĝ(prefill_i))）
```

因果性：`s_e` 只用 decode token ≤ e 的路由、prefill 路由、workflow 与离线 routine 统计。
推理时不读 `positive`、`evidence_onset`、`completion_boundary`、`scenario_domain`、`channel`
（单元测试 `tests/test_research_v2_cm.py::C1Tests::test_score_is_causal_prefix_stable` 用前缀截断验证因果性）。
拟合只接收 routine trace（harness 按 routine 定义筛好后传入 `fit`）。

## 11. 机制诊断

### 11.1 T-H 能量分解（覆盖 vs 未覆盖 token）

`‖z‖²` 按内积精确分解为三项（覆盖 token 贡献 + 未覆盖 token 贡献 + routine 基线偏移贡献，三者之和恒为 1）：
`‖z‖² = ⟨z, r̄_cov/σ⟩ + ⟨z, r̄_unc/σ⟩ + ⟨z, −μ_R/σ⟩`。窗口取：drift 的 onset 后全部窗口、drift 的严格

## 12. harness 的两个 bug 与修复（必须写明）

预注册要求主表打开 `--b1-present-calibration`（§1.6）。第一次运行时它直接崩溃，追查后发现两个问题，
都在本轮修复（commit **`cc0e41d`**，修复后 169 个单元测试全绿）：

1. **`io.load_b1_present` 无法加载。** 规范 §1.1 说 B1 `brief=present` 的 120 条"全部行为正常"，
   但冻结的 `sample_index.jsonl` 里有 **3 条 `goal_plan_deviation_started == True` 的 attack 臂 trace**
   （behavior_label = `goal_drift`）。harness 对此 `raise`，于是该池完全不可用。
   修复：丢掉这 3 条（校准材料里绝不能有 drift trace），保留 117 条（40 clean / 40 benign_control /
   37 resisted attack），并保留原有的 index sha256 校验。
2. **额外校准池没有遵守 routine 定义。** `run_case` 把整个额外池并进模式 D 的校准池，
   `routine=cb` 时那 37 条 resisted attack 也会进入 conformal 阈值。修复：在 `run_case` 里先按
   routine 定义过滤额外池（回归测试 `tests/test_research_v2_cm.py::ExtraCalibrationFilterTests`）。

修复的影响范围：只影响打开 `--b1-present-calibration` 的运行（本报告的"主表"列）。
关闭该开关的全部运行与 harness 报告 §5 的数字逐格一致（例如 T2 `_nb1p` B2→B1 persist2：
FARall 0.104、R8 0.333、R16 0.458、RF 0.792，与 harness 报告 §5.1 完全相同），说明修复没有改变其他路径。
另一个后果：`cb` 定义下额外池只贡献 80 条（每半 40），因此 B2→B1 的每半校准池是 **80 条而不是
§1.6 期望的 100 条**。要到 100 条必须用 `all_normal`（候选 11 的开关组合），或修改 routine 定义——
本轮不改预注册。
