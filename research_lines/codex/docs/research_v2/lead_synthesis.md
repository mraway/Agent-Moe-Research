# Sequential v2 单类流形研究：组长综合报告

日期：2026-09-05（America/Los_Angeles）

作者：研究组长（Claude Fable 5.1）。实现与实验由三个 Claude Opus 5 执行者和一个 harness 执行者完成
（`docs/research_v2/harness_report.md`、`wgm_report.md`、`cm_report.md`、`pdm_report.md`）；本文只做综合，
所有数字取自这四份报告与主分支的 P1–P3 / P1-LF 报告。

性质：B1/B2 上的 exploratory development。任何候选的"通过"都不是独立确认；§6 说明下一步为什么必须是
冻结后的 B3。

## 0. 一页结论

问题（澄清后的方向）：只用正常客服流量学习 MoE 路由流形，在线路由显著、持续地离开流形时报警。

1. **信号存在且与边界时间对齐（Q1：是）。** 在部署侧校准、无经验尾部封顶的协议 v2 下，三种流形定义
   （窗口几何、token 条件化、路径 surprisal）在 B1↔B2 两个方向都在 evidence onset 后 4–8 token 内产生
   可校准的报警；同一 token 在 drift 与 routine 中被不同地路由（anchor-token AUROC 0.90–0.94），信号不是
   纯词汇读出；最快的候选中位延迟 3.5–6 token。
2. **三个预注册 primary 各差一项没有通过 gate（Q2：接近，未达）。** WGM 主配置在 B1→B2 的 onset+8
   召回 0.286；CM 主配置在 B2→B1 的总误报 0.156；PDM 主配置在 B2→B1 的总误报 0.177、resist 臂 0.375。
   主分支的 P1/P2/P3 在同一 gate 下为 onset+8 0 / 0.125、0 / 0.583(FAR 0.20)、0 / 0.042。
3. **在 36 个预注册候选中，有 5 个在两个方向同时通过主分支的 gate**（FAR ≤ 0.15、onset+8 ≥ 0.35、
   延迟 ≤ 8）：WGM C2、WGM C4、PDM C12、PDM C7、CM 候选 3。这些是看到结果后挑出来的，必须按"事后选择"
   对待：B2→B1 方向只有 40 个 scenario、召回区间 ±0.2、resist 臂只有 16 条；候选之间 0.15 以内的差异不可
   分辨。它们的意义是"协议 v2 把整个单类方法族推进了 gate 区域"，不是"某个候选已被证实"。
4. **稳定的负面发现**（两方向一致、跨方案一致）：benign 臂误报高于 clean 臂且条件化无法压低（routing 对
   话题提及敏感，RASET 边界在单类框架下成立）；误报集中在最长三分之一的回复（全程最大值统计量随长度
   累积机会）；programming 域是系统性盲区（代码/JSON 路由与客服工具调用路由不可分）；resist 臂误报在
   B2→B1 方向偏高但样本太小；源批校准（模式 T）对 kNN 与路径 surprisal 完全不可迁移。
5. **建议**：不宣布 `no promising method`；也不在 B1/B2 上继续挑候选。冻结两个候选（§6.2）与协议 v2 的
   三项修订（长度分层校准、≥100 条部署侧 routine、预报警审计上下文），然后设计并生成 B3 做一次性确认。

## 5. 稳定的发现与失败带来的理解

### 5.1 跨方案、跨方向一致的发现

1. **校准机制是 P1–P3 失败的主因。** 同一几何在源批经验尾部（P1）与部署侧 raw-score conformal（协议 v2）
   之间 onset+8 差 0.29–0.46；主分支自己的 P1-LF（取消 cell、连续 z、仍源批校准）在 B2→B1 得到 +8 0.50
   但 FAR 0.22，与本轮"尺度不跨批"的判断一致。模式 T 下 kNN 误报 0.42–0.67、路径 surprisal 0.35–0.56：
   **部署侧 routine 校准是硬性要求，不是可选项。**
2. **窗口宽度是及时性的瓶颈。** w=16 的 +8 为 0.17–0.29，w=8 为 0.29–0.54，w=4 为 0.43–0.63，w=1（路径
   surprisal + persist2）的中位延迟 3.5–4 token。这证实了 v2.1 文档的假设（E29 的推断）。
3. **benign 臂误报高于 clean 臂，且条件化不能压低**（CM 判据 2 两方向触发；WGM、PDM 同样 benign > clean）。
   能量分解显示 benign 误报不来自未覆盖词，而来自覆盖 token 的路由本身：**路由流形对"提到域外话题"敏感，
   RASET 的 topic-vs-intent 边界在单类框架下成立。** 这不是 bug，是估计量的性质。
4. **误报随回复长度累积。** PDM 主配置按长度三分位的 non-drift FAR：0.000 / 0.061 / 0.206（B1→B2）、
   0.061 / 0.125 / 0.355（B2→B1）；主分支 P1-LF 审计给出同样的 4% → 43%。原因是"全程最大值"统计量的
   报警机会随长度增长，位置桶标准化无法消除。**长度分层校准是最明确、尚未做的改进。**
5. **programming 是系统性盲区。** WGM 的 8 条无任何报警的漏检中 5 条是代码（SQL×3、JavaScript、Rust），
   LODO 下 WGM/CM 的 programming 召回为 0，PDM 为 0.25/0.75；代码与结构化 JSON 的路由与客服工具调用
   路由不可分。主分支 P1 审计也把 SQL 列为表示层弱例。
6. **同 token 路由随任务变。** anchor-token within-token AUROC：CM 0.933/0.936、G1 0.896/0.931、T2
   0.864/0.902（对文本基线也高，说明该诊断本身对分数类型不够挑剔；但对 routing 分数它稳定 > 0.9）。
7. **持续性只在逐 token 尺度上区分 task 与 mention。** w=1 的 ≥8 窗口连续偏离比例：drift 后 0.77/0.92，
   benign 0.04/0.00，resist 0.02/0.06；w=4 时 resist 升到 0.20/0.375（PDM F4 在 B2→B1 触发）。
8. **normal 定义（含/不含 resist）几乎不影响结果**（WGM C9、CM 候选 11、PDM C11 与各自 primary 差 ≤ 0.05）。
9. **routine 不是低维的**（WGM 判据 5 触发：重构误差随秩每翻倍下降 17–21%，无拐点），但低秩残差（r=16）
   作为分数并不差（C3/C4），r=32 在模式 D 下也没有崩溃（E19 的崩溃只在源批校准下出现）。

### 5.2 只在单方向或小样本上出现、不能下结论的

- resist 臂误报：B2→B1 0.25–0.375（n=16），B1→B2 0.09–0.18（n=45）。CM 的 prefill 条件化把它降低
  （0.250→0.125）但降幅不足预注册的 30%（判据 3 触发）。
- CM 判据 1（"routing 只是词汇新颖度"）在 B2→B1 触发（只用覆盖 token 的检测器容差 +16 0.458 ≤ T2 0.542
  +0.10），在 B1→B2 不触发（0.514 vs 0.343）。两个子条件方向相反（anchor-token 说不是词汇；报警级说
  在该方向不优于 T2）。
- CM 判据 4（文本映射 R²）在 B1→B2 以 0.0086 之差触发，且 λ 网格在下界被选中——网格设得太窄，是
  预注册失误而非结论。
- Q1 面板的"首个分离偏移"对 primary 在 B1→B2 为 +13，对更快的候选为 +4…+7，与 +8 召回一致。

### 5.3 被证伪或修正的假设（本轮新增）

| 假设 | 结果 |
|---|---|
| 中间层 5–11 是最好的层带（v2.1 预诊断） | 5–15 在三个方案中都更快；5–11 的优势只在严格 pre-onset FAR 上 |
| token 条件化能压低 benign 误报（方案 2 核心假设之一） | 未压低，反而略升；条件化保住/提高了召回但不改变 topic 敏感性 |
| prefill 上下文条件化能显著降低 resist / 边界前误报 | 方向正确、幅度不足（9.7% / 26.5%） |
| 路径 surprisal 是"任何不寻常"的探测器（方案 3 的主要风险） | 在 B2→B1 的 resist 臂成立（0.375），B1→B2 不成立（0.133）；中间层子链 C12 把两者都压到 ≤ 0.125 |
| 静态几何不够（方案 1 判据 1） | 触发（B1→B2 +16 0.486），但换层带（C2/C4）即通过；"不够"的是 5–11 层带而非静态几何 |
| CUSUM 适合作为主读法（v2 文档） | 对 +8 有害（0.01–0.20）；persist2/max 正确；runlen 按固定 c 定义时误报不受控（harness 决策 D5） |

## 6. 决定与下一步

### 6.1 对 Q1 / Q2 的回答（在"只学习 routine 流形"的方向下）

- Q1：**存在**稳定、跨 batch 复现、与 evidence onset 时间对齐的离开信号；在 token 身份相同的条件下仍然
  成立；它同时对"提到域外话题"敏感（benign 臂），这是路由估计量的固有边界。
- Q2：**最有希望的算法形态**是"低容量的静态或路径流形分数 + 部署侧 raw-score conformal 校准 + 位置/长度
  分层标准化 + 短窗口或逐 token + persistence 读法"。它把主分支 P1–P3 失败的 gate 变成多个候选可达；
  但 primary 未通过，候选是事后挑选，因此**证据足以支持冻结候选并设计 B3，不足以宣布得到可用 detector**。

### 6.2 冻结建议（进入 B3 前不再在 B1/B2 上调参）

冻结两个候选，各自作为独立的 B3 primary（预先写明两者都失败/一个失败/都通过的解释）：

1. **WGM C2**：白化欧氏距离，top-8 入选率，层 5–15，w=8，routine = clean+benign，模式 D，α=0.10，persist2。
   理由：最简单、两方向全部门槛通过、模式 T 误报也可接受（0.11/0.15）。
2. **PDM C12**：深度链（层 5–11 子链）top-1 专家路径 surprisal，α=0.5 加性平滑，w=4，其余同上。
   理由：两方向误报最低（0.078/0.083）、resist 臂最低（0.111/0.125）、延迟 6；代价是模式 T 不可迁移、
   计数表稀疏（77–82% 的深度格未见）。

不冻结 kNN（模式 T 崩溃）、不冻结 w=1（resist 与 FAR 偏高）、不冻结 CM（收益在噪声内且需要 embedding 权重）。

### 6.3 B3 的设计要求（由本轮结果直接推出）

- **部署侧 routine 校准 ≥ 100 条 trace / 校准半**（本轮 B2→B1 只有 40，区间 ±0.2；B1 brief=present 池
  实际只能补 80 条 cb）。B3 应包含 ≥ 200 条 routine（clean+benign）。
- **长度分层的 conformal 校准**（按 decode 长度三分位或按位置的 anytime 规则）写入协议；本轮误报的
  长度依赖是可操作的最大改进项。
