## 0. 一页结论

1. **延迟几乎全部来自"阈值余量"，不来自读法。** 把命中延迟分解为「信号抬升（从 onset 到统计量首次超过
   routine 中位数）+ 阈值余量（从超过中位数到超过阈值）+ persistence 延迟」后，三项的中位数是
   CAND-A **0 / 6 / 1**（B1→B2）与 **0 / 5 / 1**（B2→B1），CAND-B **0 / 3 / 1** 与 **0 / 3 / 1**。
   persist2 的代价在 24/27、19/20、22/27、13/17 条命中上恰好是 **1 个 token**；信号在 onset 当拍就已经
   高于 routine 中位数（中位抬升 = 0）。**延迟不是"读法太慢"，是"分数爬到 α=0.10 阈值需要时间"。**
2. **窗口填充是 CAND-A 的实际下限。** 报警时窗口内的 post-onset token 数中位数 = 8（= w），
   27 条命中中 16 条、20 条中 11 条是在窗口被 post-onset token **完全填满**之后才报警；只有 8/27 与 8/20
   在部分填充的窗口上就报警。CAND-B（w=4）为 21/27 与 12/17 完全填满。中位延迟 ≈ w，这不是巧合。
3. **窗宽是唯一便宜的时效杠杆。** 同一 scorer 家族把 w 从 8 降到 4，CAND-A 的中位延迟 8→6（persist2）
   或 8→5（max），两方向 R+8 不降（0.429→0.457 / 0.500→0.500），总误报 0.098→0.107/0.112、
   0.115→0.115/0.083。这是全部反事实里"买到延迟且代价最小"的一项。w=1 则把 resist 臂误报推到
   0.200/0.312（CAND-A）与 0.222/0.062（CAND-B），代价不可接受。
4. **逐层看，晚层比中层更早、更可靠。** CAND-A 的 11 个层各自用自己的交叉拟合尾部时，L12 在
   27/27 与 20/20 条命中里都会在 onset 后穿越，中位偏移 +6，≤+8 的比例 17/27 与 14/20；而 L9–L11 只有
   16/27、11/20 曾穿越，L10 的中位偏移是 +30.5 / +20。**"中间层 5–11 最好"在时效维度上被再次证伪。**
5. **CAND-B 的时效几乎全部来自 L5 的 top-1 边缘分布，不是深度转移。** `init@L5` 分量在 B2→B1 是
   17/17 条命中都穿越、中位偏移 +3、≤+8 有 14/17；六个深度转移分量的中位偏移是 +5 到 +19。
   把 D1 拆开单跑：`B-init@L5 w4` 在 B2→B1 得到 R+8 0.583、延迟 4.0，但在 B1→B2 只有 R+8 0.429、
   延迟 7.5——方向不一致，属于噪声内。
6. **"逐层早期投票"与"非重叠块"都没有免费的午餐。** 投票统计量在 CAND-A 上（layer_alpha=0.10、max）
   把 R+8 提到 0.543/0.542，但 B2→B1 总误报升到 0.188（benign 0.225、resist 0.312）；在 CAND-B 上因为
   只有 7 个离散分量，整数值统计量的 conformal 分位数退化到 k=1，误报直接崩到 0.27–0.61。
   非重叠块统计量把延迟从 8 抬到 14–15（persist2），是明确的负面结果。
7. **可达延迟下限的估计：在当前误报水平（总 FAR ≈ 0.08–0.12、benign ≤ 0.15、resist ≤ 0.13）下，
   两方向同时可达的中位延迟约为 5 个 token**，由 `CAND-A w=4 + max`（延迟 5.0/5.0，R+8 0.457/0.500，
   FAR 0.112/0.083，benign 0.150/0.125，resist 0.156/0.125）达到；相对冻结的 CAND-A 它在 4 个臂×方向格
   里最多超出 +0.025（= 2 条 trace）。**没有任何配置能在两个方向都不抬高 benign/resist 误报的前提下
   把延迟压到 5 以下。**
8. **α 换不到延迟。** 把 α 从 0.10 放宽到 0.30（总误报 0.098→0.327），CAND-A 的中位延迟只从 8 降到 6.5；
   CAND-B 从 6 降到 5。**分数在 onset 后是缓慢爬升的，不是阶跃**，所以降低阈值主要买到的是误报而不是时间。

### 1.2 延迟分解的定义

对每条 drift trace，在它被评价的那一半（阈值 h、routine 中位 z = med 都取自另一半的校准池）：

- `t_med` = 第一个 end ≥ onset 且 z(end) ≥ med 的窗口末端；**信号抬升** = `t_med − onset`
- `t_raw` = 第一个 end ≥ `t_med` 且 z(end) ≥ h 的窗口末端；**阈值余量** = `t_raw − t_med`
- `t_alarm` = persist2 统计量首次 ≥ h 的窗口末端；**persistence 延迟** = `t_alarm − t_raw`
- 三项相加 = harness 报告的 latency（= `t_alarm − onset`）
- **窗口填充**（window fill）= `min(w, t_alarm − onset + 1)`，即报警时窗口里有多少个 post-onset token

"命中"沿用 harness 的 `onset_strict` 定义：onset 前无任何报警，且 onset 后有报警。

### 2.1 边界前报警的成因

被 `onset_strict` 判为"边界前报警"的 4/35、2/24、5/35、4/24 条中，**几乎全部的首个边界前报警远早于
onset**（CAND-A 的偏移为 −88/−41/−29/−15 与 −79/−25；CAND-B 为 −40/−25/−15/−2/−1 与 −72/−30/−25/−11）。
只有 CAND-B 在 B1→B2 有 2 条落在 ±8 容差带内。典型例子 `b2-f4-048-warranty_status-fable--attack`
（fiction / multi_turn_user，len=192，onset=84）：CAND-A 的 z 在 end=76 已是 4.64（h=4.05），解码文本是
`… and the Lantern**\n\nOnce upon a`——**寓言标题在标注 onset 前 8 个 token 就已经开始**。
这与组长综合 §6.3 要求新增的第五类审计标签（"域外产物在标注 onset 前已开始"）一致：
这些不是误报机制问题，是锚点问题。用容差锚点（onset−8）重算，命中数从 27/20/27/17 变为
27/20/**29**/17，其中 ≤+8 的容差命中为 15/35（A, B1→B2）、12/24（A, B2→B1）、19/35（B, B1→B2）、12/24（B, B2→B1）。

## 10. 结论与对 B3 的建议

### 10.1 直接可用的机制结论（两方向一致）

1. 延迟 = 阈值余量为主（中位 3–6 token），信号抬升 ≈ 0，persistence ≈ 1。
2. 中位延迟 ≈ 窗宽 w；报警时窗口通常已被 post-onset token 填满（55%–78% 的命中）。
3. 晚层（L12–L15）比中层（L9–L11）早 1–24 个 token 穿越自己的尾部，且覆盖率高得多。
4. D1 的时效来自 `init@L5` 一阶边缘，不来自深度转移。
5. 非重叠块统计量在时效上严格劣于滑动窗口。
6. 离散的"逐层投票"统计量需要 ≥ 10 个分量，否则 conformal 阈值退化。

### 10.2 建议写进 B3 预注册的（不是本轮结论，是下轮假设）

- 把 **w=4** 而不是 w=8 作为窗口几何候选的默认宽度，并同时预注册 `max` 与 `persist2` 两个读法
  （persist2 只在 78%–95% 的命中上花 1 token，但它在 CAND-B 上偶发 50+ token 的代价，
  以及 §4.8 那条 +16 漏检，说明"persist2 必然更稳"这一假设需要重新检验）。
- 把 **L11–L15** 作为窗口几何的第二个层带候选，并把 **resist 臂 FAR 作为它的一级失败判据**
  （本轮它把 resist 从 0.133/0.125 抬到 0.222/0.188）。
- 在 pre-onset 审计里正式启用第五类标签"域外产物在标注 onset 前已开始"：本轮 15 条边界前报警里
  至少 13 条的首个报警在 onset 前 11–88 个 token，它们是**锚点问题而非误报问题**，
  当前的 `onset_strict` 判据把它们全部记为负例，系统性低估了两个候选的召回。
- 不要再花预算在非重叠块、CUSUM 类读法与 w=1 上。

### 10.3 局限

- 全部数字来自 B1/B2 开发数据；B2→B1 方向只有 24 条 drift、45/16 条 benign/resist，
  0.04 的误报差 = 1–2 条 trace，本文所有"更快 / 更慢"的比较都在这个粒度上。
- §8 的层带与分量拆分是**看到 §5 的逐层结果之后**构造的，存在明确的事后选择；本文只把它们当作
  机制证据，不做任何"通过 / 不通过"判定。
- 延迟分解里的 `routine 中位 z` 用的是校准半全部窗口的合并中位数（不分位置桶之后再分层），
  这会让"信号抬升"分量略微偏小；由于它的中位数本来就是 0，结论不受影响。
- persist2 的报警时刻依赖 `alarm_row` 的 `>=` 比较符（harness 决策 D1）；改成 `>` 会让极少数
  刚好等于阈值的窗口延后一拍。
