# 反驳报告 · 透镜「逐层边缘 vs 跨层联合结构」

日期：2026-09-05 · 角色：对抗性复核（refuter） · 数据：B1/B2 开发集 · **事后诊断，不是检测成绩**

被审对象：`docs/research_v2/zoom/code_blindspot/joint_vs_marginal.md`（支持度 moderate）。
本文所有数字用**我自己的实现**重算（`scripts/research_v2/zoom/code_blindspot/refute_joint_*.py`，
不 import 对方脚本，只读对方脚本以确认定义），缓存写在
`artifacts/agent_v2/research_v2/zoom_code_blindspot/refute_joint_{recompute,decomp}.json`。

**结论：部分反驳（refuted = true）。**
描述性的一半成立且我独立复现：**代码的逐层边缘几乎不动、成对（跨层）统计量动得多、且信号迟到**。
但支撑该透镜"解释力"的三条断言全部不成立：

1. 「联合是**代码专属**的新颖性所在」——**否**。联合统计量对其他域 drift 的分离度是代码的 2 倍
   （成对未见率 15.73x vs 7.29x）；把"区间自身边缘"作为零模型扣掉之后，代码的**纯联合过量**
   （observed / independence-expected）是 9.53x，其他域 10.01x，**51/51 条其他 drift ≥ 代码最小值**。
   联合新颖性是一切 drift 的共有性质，代码在 8 个域里排第 7（只有 legal 更低）。
2. 「"熟专家的新组合率"是唯一代码高于其他域的统计量（4.57x vs 1.92x）」——**是算法伪影**。
   该率恒等于 `P(两端都是熟专家) × P(未见 | 两端都是熟专家)`。代码对其他域的 2.38 倍差距
   拆成 **1.97x（熟-熟机会占比，一个逐层边缘性质）× 1.23x（每机会的真实"重接线"倾向）**，
   log 意义上 **79% 来自边缘因子**。按每机会的条件率排名，programming 只排第 3
   （cooking 5.60x、fiction 5.33x、programming 5.19x）；跨 batch 切分下同样第 3（3.66x，落后 cooking 5.42x、fiction 4.05x）。
3. 「联合放大系数 A 说明代码更依赖联合」——**A 就是"边缘弱"的另一种写法**。
   仅用 51 条**非** programming drift 拟合 `log joint = 1.705 + 0.452·log marginal`（斜率 0.45 ≪ 1），
   把代码的边缘比值代进去，**6/8 条代码 trace 的联合比值落在 ±1 个残差 sd 内**（残差中位 +0.20 sd，
   3/8 条低于预测）。`corr(log A, log marginal) = -0.836`。A 高只是因为分母小。

## 2. 反驳一：联合不是"代码专属"，它对其他域更有效

判据（任务书）：*若同一量对其他 drift 也分离，它就不是代码特殊困难的解释*。

* 成对联合（J1）对**其他域** 15.73x，对代码 7.29x —— 联合把代码抬高，但把其他域抬得更高。
  逐域中位：fiction 18.21、poetry 17.18、general_knowledge 15.86、cooking 14.89、mathematics 13.95、
  travel 11.11、**programming 7.29**、legal 5.30。**代码在联合上排倒数第二**。
* 更干净的检验（J3，独立性零模型）：把区间**自身的逐层 top-1 边缘**做外积，问"如果层间独立，
  未见对率会是多少"，再用观测值除以它，得到**纯跨层依赖**的成分。
  routine 0.047（观测比独立性预测低 21 倍 —— routine 的链高度定型），
  代码 0.452（9.53x routine），其他域 0.500（10.01x routine）。**代码与其他域在"联合结构被打破的程度"上无法区分**；
  逐 trace：51/51 条其他 drift ≥ 代码最小值 0.140，28/51 ≥ 代码中位 0.452。
* 同时 J3 的另一半说明：代码区间的**边缘外积**几乎和 routine 一样（期望未见率 0.439 vs routine 0.448，0.98x），
  其他域是 1.52x。**这正是"代码边缘不动"的独立确认**，也是本透镜唯一站得住的核心。

**修正后的表述**：代码不是"新颖性搬进了联合"，而是"**只剩联合**"——联合成分代码 9.53x、其他域 10.01x（相同），
边缘成分代码 1.60x、其他域 6.35x（差 4 倍）。**特殊的是缺失的边缘，不是多出来的联合。**

## 3. 反驳二：「唯一代码领先的统计量」是分母造成的

`熟专家新组合率 = ff_frac × 条件未见率`（恒等式，两侧数字对得上：代码 0.573×0.0348=0.0199）。

| 分解 | 代码中位 | 其他域中位 | 代码/其他 | log 占比 |
|---|---|---|---|---|
| 熟专家新组合率（对方的头条量） | 0.0198 (4.57x) | 0.0083 (1.92x) | **2.38x** | 100% |
| ├ ff_frac＝两端都是熟专家的机会占比 | 0.573 (0.87x) | 0.290 (0.44x) | 1.97x | **79%（边缘性质）** |
| └ 条件未见率＝每次机会真的"重接线"的概率 | 0.0348 (5.19x) | 0.0284 (4.23x) | 1.23x | 24%（联合性质） |

对方的机制叙事是"代码用老专家的新接线"。但**其他域也在用老专家的新接线，而且每次机会的概率一样高**；
它们只是**同时**去用了 routine 罕见的专家，于是"熟-熟"机会只剩 routine 的 0.44 倍，无条件率被稀释。
按每机会的条件率排名（pair-group 二折 / 跨 batch 二折）：

| 排名 | pair-group 切分 | 跨 batch 切分 |
|---|---|---|
| 1 | cooking 5.60x | cooking 5.42x |
| 2 | fiction 5.33x | fiction 4.05x |
| 3 | **programming 5.19x** | **programming 3.66x** |
| 4-8 | general_knowledge 4.81 / travel 4.17 / legal 4.08 / poetry 3.96 / math 3.33 | travel 3.57 / poetry 3.29 / math 2.69 / legal 2.67 / gk 2.33 |

n=8 脆弱性：8 条代码 trace 里 **6/8** 高于"其他域中位"，但只有 **3/8** 高于 cooking 中位；
按无条件率算，其他域 12/51 ≥ 代码最小值、3/51 ≥ 代码中位（这一条对方成立），
按条件率算 **38/51 ≥ 代码最小值、16/51 ≥ 代码中位**（分离度消失）。

**"全部 20 多个统计量里唯一代码高于其他域的一个"** —— 这句话只对**无条件**版本成立；
换成正确归一化（每机会），代码不是第一，且跨 batch 下差距进一步缩小。

## 4. 反驳三：A =「联合/边缘」不含边缘之外的信息

* 只用 51 条非 programming drift 拟合：`log(joint ratio) = 1.705 + 0.452 · log(marginal ratio)`，残差 sd 0.340。
  斜率 0.452 ≪ 1 ⇒ **A ≈ marginal^-0.55 是这批数据的普遍规律**，与代码无关。

## 5. 我试过但**没能**推翻的部分（保留反证）

1. **token 类别不是混杂因子。** 把 routine 参照按每条区间的 token 类别混合（word/punct/space/digit）重新加权后：
   代码成对未见 7.29x → **7.24x**，熟专家新组合 4.57x → **4.46x**（其他域 15.73→12.76、1.92→1.69）。
   routine 各类别的成对未见率本身很平（word .0274 / punct .0164 / digit .0173 / space .0166）。**该攻击失败。**
2. **锚点不是混杂因子。** evidence_onset 变体：边缘 1.59x、联合 7.37x、新组合 5.05x、条件 5.55x
   （cooking 条件 5.62x 仍在代码之上）。结论不变。**该攻击失败。**
3. **基准率（base rate）攻击两头都咬。** 我把边缘统计量调到与成对未见相同的基准率再比：
   (a) token 级"最罕见专家集合，routine 质量 = 0.0211"：代码 3.38x、其他域 11.68x —— A 从 ~5 掉到 2.16，**支持我**；

   两种同基准率的边缘化给出相反结论 ⇒ **"边缘 vs 联合"的倍数比较本身对统计量形式敏感，不能只报一个 A。**

## 8. 局限

* n=8；所有代码中位数背后只有 8 个数，逐 trace 值已全部给出。
* 与被审报告一样：**没有任何部署侧 conformal 定阈、位置桶标准化、persist2、FAR / benign / resist 臂、
  跨 batch 模式 T 报警评估**。§5.4 的 q90 只是自洽 α=0.10 类比，用来定位"信号何时到达"，
  **不能读成任何配置的成绩，也不是改进**。fcm 报告已证明同族未见转移统计量在模式 T 下 FAR=1.000。
* J3 的独立性期望用区间自身 48 token 的经验边缘做 plug-in，含 O(1/T)=2% 的自配对偏差；
  代码与其他域区间长度相同（都是 48），故**组间比较**不受影响，只有"x routine"缩放受影响（§6.2 已量化）。
* 跨 batch 切分（fit B1 routine → 评 B2 drift，反之亦然）只用于稳健性，不是模式 T 的报警评估。
* 我没有重算对方的 rank 1–8 衰减、层带 0–15、平滑 0.5→0.005 三项；它们支撑的是"漏检不是因为 X"的排除性论证，
  与本文的反驳无关，按原样接受。
