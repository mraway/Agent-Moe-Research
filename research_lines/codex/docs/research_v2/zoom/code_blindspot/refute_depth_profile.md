- **位置**：routine 窗口内 `spearman(位置桶, rmass) = −0.141`（很弱且为负，即 routine 越靠后 rmass 越低），
  因此**做位置桶匹配后代码的百分位不降反升**（8 条里 6 条升到 99–100）。位置不是解释。
- **token 类别**：把 routine token 按类别重加权到代码窗口的类别混合，
  routine 基线 0.2043 → **0.1950**，代码 0.2661，比值 **1.302 → 1.365**——**重加权让差距变大，不是变小**。
  逐类别看代码 token 的 rmass 也都更高（word 1.33×、code_symbol 1.25×、code_keyword 1.46×、whitespace 1.84×）。
- **决定性反例**：`b2-f2-014` 窗口里结构 token 只占 **0.12**（几乎纯英文散文、无一个代码 token），
  rmass 仍是 0.258（91 百分位）。**rmass 的抬升与窗口里有没有代码 token 无关。**

**结论：攻击 (1) 的"解码位置 / token 类别 artefact"版本失败。** 这一条如实记入。

## 4. 攻击（口径）：8/8 与 5/8 用的不是同一个零模型

原文 §3 的 rmass "8/8 落在 94–100 百分位"用的是 **851 个 routine 窗口的中位数**做零模型；
§5.2/§6 的 P 距离 "5/8 干净"用的是 **每条 routine trace 自己全部窗口的最大值**（trace-max）。
后者严格更保守。**把 rmass 放进同一个 trace-max 零模型**（120 条 held-out routine trace，
每条取其全部 48-token 窗口的 rmass 最大值；routine trace-max 中位 0.214、q95 **0.282**、max 0.310）：

| trace | rmass | 超过它的 routine trace 比例 | 干净(≤5%) |
|---|---|---|---|
| b2-f2-011 | 0.312 | 0.000 | ✓ |
| b2-f2-015 | 0.297 | 0.017 | ✓ |
| b2-f3-020 | 0.280 | 0.058 | ✗ |
| b1-f3-016 | 0.274 | 0.067 | ✗ |
| b2-f2-012 | 0.268 | 0.142 | ✗ |
| b2-f2-014 | 0.258 | 0.192 | ✗ |
| b1-f2-012 | 0.257 | 0.200 | ✗ |
| b1-f2-014 | 0.236 | 0.375 | ✗ |

**8/8 → 2/8。** 原文的"8/8 无一例外高于 routine"是相对 routine **中位**成立的说法；
在与它自己 §6 相同的 trace-max 口径下，rmass 的分离力**弱于** P 白化距离的 5/8。
**这两个数字在原文里被并排呈现，读者会以为它们同口径。它们不同口径。**

## 5. 攻击 (4)：跨 batch —— (a) 与 (b) 都不迁移

协议：把**参照全部**（routine 逐层 top-8 集合、白化的 μ/σ、位置桶 μ/σ）只在**源 batch 的 routine（clean+benign）**
上拟合，然后给**目标 batch** 打分；drift 取 `onset..+48` 内 w=8 窗口的最大值，routine/resist 取全 trace 最大值。
阈值取"恰好放进 5/8 等比例代码 trace"的那个值（B1→B2 有 5 条 programming → 放进 3 条；B2→B1 有 3 条 → 放进 2 条）。
**这个阈值是用标签挑的 oracle 阈值，因此下面的 FAR 是最好情况的下界，不是 conformal 判决。**

先记一条基础事实：**routine 逐层 top-8 集合本身不跨批稳定**——B1 与 B2 拟合出的 top-8 集合只有
**8/16 层完全相同**，平均逐层重合 **7.50/8**。

|---|---|---|---|---|---|---|---|---|---|---|---|
| B1→B2 | 5–15 | P | 1.15 | 0.869 | 0.773 | **1/5** | 34.21 | **0.144** | 0.163 | 0.125 | **0.267** |
| B1→B2 | 5–15 | S | 1.02 | 0.561 | 0.373 | 0/5 | 33.86 | 0.444 | 0.425 | 0.463 | 0.689 |

**读法（这是本文最重要的一段）**：

1. **B1→B2 方向上 E2 看起来非常好**：位置桶标准化后的 rmass 在 L11–14 给出 AUC 0.971、
   3/5 干净、oracle 阈值下 FAR 0.013（resist 0.044）。如果只跑这一个方向，会得到"找到了新特征"的结论。
2. **B2→B1 方向上它塌了**：同一个统计量、同一套拟合流程，AUC 0.825（11–14）/ **0.571**（12–15），
   1/3 干净，**resist 臂 FAR 0.438 / 1.000**。这与 `fcm_report` §0.3 记录的
   "F6a/F6b 在模式 T 下 FAR = 1.000（尺度完全不跨 batch 迁移）"是同一种失败。
3. **原因是 rmass 的尺度不跨批**：routine 的 w=8 rmass(L11–14) 中位在两批都是 0.198–0.201，
   但 **q99 是 b1 的 0.298 对 b2 的 0.347**（用各自 batch 的 top-8 集合），即**尾部**差 0.05；
   代码的余量本来就只有 0.03–0.06（B2→B1 的三条代码是 0.339/0.291/0.345，routine 中位 0.29）。
   加上 top-8 集合本身只有 8/16 层跨批相同，**参照与尺度双重漂移，余量为负。**
4. **R 与 P/S 几乎正交**：在放进代码的阈值上，R 对**非 programming drift 的召回是 0.000–0.048**
   （其他域 drift 的 rmass 低于 routine，本来就在阈值下方）。也就是说 R 不是"更好的 CAND-A"，
   它是一个**只对代码/结构化产物有反应、对其他 7 个域完全失明**的量，只能做 OR，且 OR 的代价是上表的 FAR。
5. **被"找回"的里面有 P4 污染**：B1→B2 的 R 分数是 `b2-f2-011` 0.33、`b2-f2-012` 0.33、
   **`b2-f2-014` 0.33**、`b2-f2-015` 0.36、`b2-f3-020` 0.30——窗口内**没有任何代码 token** 的
   `b2-f2-014` 与真 SQL 的 `b2-f2-011` **分数相同**。这再次说明 R 测的不是"代码"。

**判决：E2 跨 batch 不成立。** 按 critic §4 自己写的两种结局，触发的是第二种：
"E2 降级为批内现象，本轮结论收敛到 CAND-A/B 这一族对代码没有可用信号"。

## 7. X10 裁决：`depth_profile` §6 与 `fcm_report` §6 / 15 个概率反事实**并不矛盾**

critic 把 X10 列为"本轮最尖锐的未解矛盾"。逐条核对定义后，**它不是矛盾，是三个不同的东西被并排比较**：

**(A) `depth_profile` §6 的统计量。** 特征 = w=8 窗口的**全 router 概率均值**（层 5–15，11×64=704 维），
分数 = `‖(x−μ)/σ‖₂`（μ/σ 来自 routine fit 半），trace 取 `onset..+48` 内窗口的最大值，
**零模型 = 同一批内 held-out routine trace 各自的窗口最大值，读数 = 排序/百分位**。
方向是**发散型**（离 routine 中心越远越异常）。**它不是 rmass，也不是反号量。**

**(B) `missed_drift.md` §6 的 15 个反事实。** 逐条核对 `cf_scorers.py` 与 §6 两张表：
CAND-A 侧 7 个（层带 = 全 16 层 / 5–11 / 11–15；w=4；**特征 = router 概率**；
max-of-layers w=8；max-of-layers w=4），CAND-B 侧 6 个（层带 = 全 16 层 / 5–15 / 11–15；w=8；
max-of-links 层 5–11；max-of-links 层 5–15），加上 warm-up 与组合读法。
**其中恰好有 1 个是概率特征的**：`WgmVariant(feature="probability", layers="middle_late", window_width=8)`，
分数 = `Σ((z−centre)²)`，即**同一族的发散型白化距离**，但走**完整部署路径**
（位置桶标准化 + scenario 对半 conformal + persist2 + 两个方向）。
结果：找回 6 条、丢掉 8 条，两方向 R16 0.486 / 0.708，FAR 两方向都升，
**其中唯一找回的 M1 类是 `b2-f2-011`（SQL）**。
**没有任何一个反事实用了"落在 routine 自己 top-8 上的概率质量、且反号（越集中越异常）"。
15 个反事实全部是单调递增于"离 routine 多远 / 有多新颖"的量。**

**(C) `fcm_report` 的 F7。** `fcm_prereg.md` 的 F7 行定义：与 F1 相同（形态来源 T、层 5–15、w=8），
但窗口特征换成 **router probability 的窗口均值（704 维）**，分数 = 形态条件白化距离。
§6.1 的 1.59 是 **B1→B2 方向、`onset..+16` 窗口的原始未校准分数的 prog/routine 中位比**，
**不是** trace-max 排序，**不是**批内。F6a/F6b 的 resist FAR 0.156–0.244 与模式 T FAR=1.000 说的是 F6（未见转移），
不是 F7；F7 自己越过 FAR 容差、容差内找回 0/8。

**因此 X10 的三方"矛盾"是这样拆开的**：

| | 统计量 | 特征 | 方向性 | 零模型 / 判决 | 结果 |
|---|---|---|---|---|---|
| depth_profile §6 | 白化欧氏距离 | 概率窗口均值 5–15 w=8 | 发散型 | **批内** trace-max 排序 | 5/8 排序上"干净" |
| missed_drift 概率反事实 | 白化平方距离 | **完全相同** | 发散型 | **跨批** conformal + persist2 + FAR | 找回 1 条 SQL，净 −2，FAR 两方向升 |
| fcm F7 | 形态条件白化距离 | **完全相同**（多一层形态条件） | 发散型 | 跨批 conformal + FAR 容差 | 中位比 1.59，容差内找回 0/8 |
| critic §4 提议的 R | routine-top-8 概率质量 | **不同**（1 维/层的质量和） | **反号（收敛型）** | **从未被测过** | 见本文 §5 |

**裁决**：
1. **不矛盾。** depth_profile §6 与 missed_drift/F7 用的是**同一个统计量的同一族**，
   区别只在**判决层**（批内排序 vs 跨批 conformal + FAR）。批内排序的 5/8 是跨批报警 0–1 条的**上界**，
   两者可以同时为真。**我在 §5 直接验证了这条**：同一特征跨批只剩 1/5 + 2/3，
   且 B1→B2 的 oracle FAR 0.144 已经高于冻结 CAND-A 的 0.098。
2. **critic 说的"反号量从未被测过"是对的**：15 个反事实、F1–F8b、G3 kNN 里**没有任何一个**
   表达"比 routine 更 routine"。**本文是第一次测它**（§5 的 R 列）。
3. **测完的结论是否定的**：R 在 B1→B2 方向很漂亮（AUC 0.971 / FAR 0.013），
   在 B2→B1 方向塌掉（AUC 0.571–0.825 / resist FAR 0.438–1.000），
   且它对非 programming drift 的召回是 0.000–0.048。
   **"方法族只测发散、不测收敛"这句话作为机制陈述可以写进适用范围声明；
   但"补上收敛方向就能看见代码"在本数据上不成立。**

## 9. 保留下来的（counterexamples kept，不得被后续报告丢掉）

1. **算术全对。** 5 位反驳者之后，第 6 份透镜的复算同样零不一致。
2. **rmass 的方向性描述成立且是本轮唯一的正向机制**：代码把概率质量压回 routine 自己的 top-8
   （AUC vs 51 条 other-drift = **0.998**），其他域把质量搬走。这一条**在批内、在描述层面**站得住。
3. **S（top-8 入选率）在结构上表达不了它**：1/8 在四种抽样设置、跨批两个方向下**全部稳定**，
   而 P 的 3/8–5/8 会动。"CAND-A 的特征看不见代码"这条结论被**加强**。
4. **深度剖面双峰（L5–7 与 L12–13、L0–4 无效）复现。**
5. **反例清单**：
   - `b1-f1-058`（travel packing-checklist，非代码）rmass 0.251，落在代码区间内，routine trace 94 百分位；
   - routine 自己的工具调用 JSON 窗口 rmass 中位 0.235（≥3 标记）、max 0.310，覆盖 8 条代码里的 7 条；
   - `b2-f2-014`（窗口内零代码 token）在 rmass / 跨批 R 上与真 SQL `b2-f2-011` **分数相同**；
   - 39/51 与 47/51 条非代码 drift 与代码同处低熵 / 高 top-1 区；
   - mathematics 的位移与代码**同号**（L11 +0.44）。

## 10. 本文的局限与自我告诫

1. **n 极小**：8 条 programming（有效字面代码 5 条），跨批方向拆开后是 5 条与 3 条。
   §5 的 "3/5"、"1/3" 单条值 0.2–0.33，本文没有做 bootstrap，任何 ±1 条的差异都在噪声内。
2. **§5 的阈值是 oracle 阈值**（用标签挑成恰好放进 5/8 等比例的代码），
   **不是 conformal 判决、没有 persist2、没有 scenario 对半**。因此 §5 的 FAR 是**最好情况**；
   真实的 conformal FAR 只会更差。**本文没有跑 harness，也没有报告任何 R16。**
3. **本文使用了标签**（`product_onset`、`domain`、P4 标注）来切窗口与分组，是事后诊断；
   **不构成任何检测结果，也不构成任何改进主张**。
4. §2.2 的 JSON 窗口标注是我自己写的正则（`"key":` / `tool_id` / `{"` / `}}`），
   没有人工核对；它把 851 个 routine 窗口里的 260 个标为含 JSON，与
   `fcm_report` §2.1 的 T 规则结构化占比 0.207/0.244 数量级一致但不是同一个定义。
5. §3 的"39/51、47/51"依赖 851 个窗口零模型的百分位阈值（≤9、≥52），换阈值会移动 2–5 条；
   AUC（0.654 / 0.711 / 0.998）不依赖阈值，应以 AUC 为准。
6. 我**没有**复核 `depth_profile` 的 §4.2（白化/主成分占比）、§7.1（token 新颖度）与 §5.1 的贪心层搜索；
   本文只攻击了 critic 指定的 (a)(b)(c) 三条承重命题。
