## 2. 从清单直接读出的事实

1. **一半的误报是"提到域外话题"或"复述 KB 原文"**：(a)+(f) = 27/55 = 0.491；再加 (b) JSON/协议形状
   = 41/55 = 0.745。真正"看不出原因"的普通散文 (e) 只有 7/55 = 0.127。这与组长综合 §5.1.3 的判断一致，
   并把它细化了：benign 臂的 (a) 占 13/27，clean 臂的 (a) 为 **0/13** —— clean 臂的误报几乎全部是
   (b) JSON/协议、(f) KB 复述、(d) 退化尾巴，**没有一条是话题原因**。
2. **误报在 scenario 上高度集中**。55 行只来自 31 个 scenario；其中
   `b2-f0-077-knowledge_qa-economics-explanation`（6 行 = 3 个臂 × 2 个候选）与
   `b1-f4-048-order_and_knowledge-dialogue-scene`（同样 6 行）合计占 12/55 = 0.218。
   这两个 scenario 的 **clean 臂也报警**，说明触发的不是攻击/良性差异，而是该 scenario 的产物形状
   （前者逐字复述 KB-PROOF-001，后者以转义换行尾巴收尾）。**scenario 层面的误报相关性没有被当前协议建模。**
3. **两个候选的误报只部分重叠**：B1→B2 方向 20 与 16 条中共有 6 条（Jaccard 0.20），B2→B1 方向 11 与 8 条中
   共有 6 条（Jaccard 0.46）。共有的 6 + 6 条全部落在上面两类 scenario 上。
4. **误报余量普遍很小，drift 命中余量普遍很大。** 基线 α=0.10 下（persist2 z 超过阈值的峰值余量）：

## 3. 一个必须先讲清楚的结构性事实

**在部署侧 conformal 校准下，总 FAR 被 α 钉死，任何读法或分层都不能"免费"降低它。**

阈值 h 是 routine 校准 trace 上统计量最大值的第 ⌈(n+1)(1−α)⌉ 小次序统计量。换一个统计量（非重叠块、
k-of-m、任何持续性门），h 会自动跟着降低，校准半上的越界比例仍然是 ≈α。§4 的第一轮实验正是如此：
在 α=0.10 重新校准的 k-of-m 非重叠块门，FAR 不降反升（如 B 的 B2→B1：0.083 → 0.177），而 onset+8 召回
大幅下降。这不是补救失败，是**问题被问错了**。

正确的两个问法，本文都做：

- **(P1) 匹配 FAR 的前沿比较**：扫 α ∈ {0.02, 0.05, 0.075, 0.10, 0.15, 0.20, 0.30}，在 FAR 不高于基线的
  运行点上比召回。回答"这个规则是否改善 FAR–召回前沿"。
- **(P2) 固定阈值的严格子规则**：保留基线 α=0.10 校准出的阈值 h，再加一个只会**减少**报警的门
  （持续性 / 非重叠块 / 重复门）。这类规则的 FAR 一定 ≤ 基线，代价出在召回与延迟上。回答
  "每去掉一个误报要付出多少召回"。

## 5. 结论（只陈述事实，不做冻结建议）

1. 55 条误报里 (a)+(f) 占 0.491、(a)+(b)+(f) 占 0.745、(e) 只占 0.127：**这两个检测器的误报绝大多数
   有可见的产物层原因**，不是随机抖动。clean 臂的 (a) 计数为 0/13。
2. 误报按 scenario 高度集中（2 个 scenario 占 0.218，且其 clean 臂也报警），当前协议**没有建模 scenario
   层面的误报相关性**；按 trace 计数的 FAR 因此低估了"每个 scenario 至少一次误报"的部署代价。
3. 在部署侧 conformal 校准下总 FAR 被 α 钉死；**任何在同一 α 上重新校准的读法都不能降低 FAR**
   （§3、§4.2 的四格实证）。组长综合 §6.3 把"长度分层 conformal 校准"列为最明确的改进项——
   在这两个冻结候选上它**不成立**：它只重新分配 FAR，而且在 B2→B1 方向因为 192 token 上限而退化。
4. 真正能换到 FAR 的是**固定阈值 + 持续性/重复门**这一类严格子规则。CAND-B 的 `run2` 是唯一交换比 > 1 的
   规则（FAR −0.037，+8 −0.017，final +0.034）；CAND-A 上同一规则在 +16 口径下免费、在 +8 口径下昂贵。
5. 持续门去不掉 (a) 类（域外话题）与 (d) 类（退化尾巴）误报；(d) 可以被一个只用 decode token id 的
   重复门定点去掉（n=1，不能下结论），(a) 无法用任何路由侧规则去掉。

## 6. 局限

- 全部数字是 B1/B2 开发数据上的事后诊断，且规则是在看过误报清单之后写的（尤其 (iii) 重复门直接针对
  已看到的那一条 trace）。**不能把 §4.5 的排序当作已验证的改进。**
- B2→B1 方向 non-drift 只有 96 条、resist 臂 16 条、drift 24 条；1 条 trace = 0.010（FAR）或 0.042（召回）。
  §4.5 里 CAND-B 的 run2 优势（合并口径 FAR −0.037 = 11 条，+8 −0.017 = 1 条）在 B1→B2 方向占 8 条误报，
  在 B2→B1 占 3 条，方向一致但绝对量小。
- 分类由本审计代理阅读窗口文本与 ±32 token 上下文人工判定，(b)/(f) 的边界（"窗口本身是散文但被包在
  JSON 载荷里"）是本文自己定的规则；换一个划法会在 (b) 与 (f) 之间移动约 8 行。
- 未做 bootstrap 区间；未评估 S2/S3；未触碰模式 T。
