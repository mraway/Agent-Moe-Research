# Codex / 数据集 G：先找机制，再提炼算法

版本 v2（2026-09-08 UTC）。主管已批准在保留访问事故记录、禁用原产物的前提下继续；本轮依据随后讨论转为**机制分析优先**，不预设权重必然优于入选集合。v1 联合几何方案原文归档为 [joint_geometry_plan_v1](research_v4/codex_g_joint_geometry_plan_v1.md)，暂不实施。

唯一权威入口是 [G 入门包](research_v4/dataset_g_onboarding_for_codex.md)，含末尾四条批准修正。OLMoE 只产生假设；本轮真实数据仅来自 GPT-OSS-20B / Agent v3 的开放 G-dev，均为 **development evidence**，不是独立确认。

## 1. 首轮 M1：路由表示与行为阶段

问题：现有选择类读出在 E 附近弱、X 附近强，究竟与离散化丢失权重有关，还是连续变化主要反映注入暴露？同时检查通道、位置与正常转场的解释。

固定三种逐 token / layer / expert 表示，均为32维归一化分布：

- **U**：实际入选的4个专家均赋1/4，其余为0。
- **W**：实际缓存的4个门控权重按 expert id 填回32维，未入选为0；仅修正存储舍入导致的和不为1。
- **P**：对缓存的全部32个 router logits 作 float32 softmax；这是路由偏好，不是实际门控权重。

专家 id 始终使用实际缓存值，不从降精度 logits 重做 top-k。三种表示采用同一 V1/message、全24层、w=8通道内因果窗口与 H=352 looks。先使用同一简单读出：窗口均值与正常参考的逐层 Jensen–Shannon 差异；不改变读出来追求某种表示胜出。

同时记录权重非均匀度、W/U差异、相邻 token 的专家集合更替，以及**集合保持不变时**的 W/P 变化。动态比较排除通道/Agent step 边界。固定按前/中/后各8层作描述性汇总，不择优挑层。

## 2. 参照与机制评价

只加载 G-dev，恢复五路臂别，使用共享 fixture_rank_mod 的3折轮转：k评价、k+1拟合、k+2正常参照；拟合/参照只用 filter_pass=True 的正常臂。路由特征计算不读取文本、事件标签、臂别或未来 token；标签仅进入离线事件对齐与分层。

对正常拟合折按通道估计平均路由分布。以参照折的同通道、同位置桶、同 episode 次序正常窗口计算百分位；稀疏时按预先写定的回退顺序处理，报告回退和缺失。主要诊断为每条 episode 的事件窗口平均百分位，episode等权；重叠窗口不当独立样本。

事件区间固定为 E前16、E至E+16、E+17至X前、X至X+16、X+17至X+64，均受H截止；排除原因与有效数全部报告。阶段间结果不可混作相同分母。静默攻击仅含注入后的 episode，拒绝、合法拒绝与困难正常分别报告。

在同一有效 episode 集合比较 W−U、P−U，报告按实际 attack family 聚类的2,000次 bootstrap 区间及 family×tier 稳健列。这里的百分位/区间是**使用事件标签对齐的描述性诊断**，没有报警阈值、没有在线FAR/召回或确认性检验，不冒称“权重条件互信息”或“专家因果机制”。

## 3. 由结果决定下一步

若 W 相比 U 只发生数值变化、没有行为阶段特异性，不据此设计加权检测器；若 P 的增量主要存在于静默攻击或 E前，不称为参与检测。若权重变化在控制通道/位置后仍与行为一致，再注册简单加权读出；若只在联合或时间结构中有线索，再开展 v1 类结构消融。

任何后续**检测器**评价必须回到入门包 §5 的完整共享 harness：X锚点、首报命中窗 [E_view,min(X+16,H_end)]、严格pre-E罚则、band=0、双分母FAR、正常阶段冻结的实测FAR匹配、家族聚类区间加精确McNemar。不能把本轮窗口诊断替代这一步。

## 4. 执行与纪律

分析细节见 [M1 固定分析规范](research_v4/codex_g_m1_analysis_spec.md)。先提交方案，再提交实现与合成测试，记录代码/方案/开放输入哈希后运行；修复程序错误要留痕，不能按结果改口径。产出完整分母表、反例定位、机制报告及CPU成本。

仅写 main 自有文件，产物仅写 artifacts/agent_v2/codex_g/；不修改 Claude 工作树、共享 loader/harness 或冻结协议。使用独立访问守卫，禁止读取 G-conf 轨迹、路由、标注以及已隔离的事故产物。本轮不使用 G-session/G-medium，不新增数据、不加载模型。

G-conf 保持封存。只有形成值得独立检验的主张后才冻结本线正式预注册，并申请两线联合两阶段解封；后续再验证模型/任务泛化和相对基线的增量价值。
