# Codex G：以论文证据为目标的后续路线

2026-09-08。组长采纳“完整观察 → 机制 → 低误报增量 → 独立泛化”的路线。
GPT-OSS-20B / Agent v3 是当前证据来源；OLMoE 只提供假设。

## 主问题与可证伪主张

研究 MoE 路由何时反映 agent 实际任务偏移，而不是仅识别注入在场或生成词汇变化。
候选主张是：在相同可见前缀、相同实测误报、清晰的计算预算下，路由提供文本/隐状态监测
未提供的及时检出信息；同时说明失效边界。不是“内部特征可分类”，也不以算法复杂度为贡献。

当前 S 已是必须保留的强基线。CW 有机制动机但无可靠在线增益；CH 不因点估计最高而升级。
M4/M5 的匹配残差是条件关联，不是因果效应；完整概率的信息包含关系不保证有限样本读出优势。

## 顺序与停止条件

1. **M7：完整已生成轨迹与词汇混淆检查。** 所有臂均观察到已有 episode 结束；正常完整路径
   同步重新校准。保留旧 M6、不把裁剪后的高召回冒充全覆盖结果。引入无攻击训练的 token
   unigram 新颖性作为弱文本对照；先确定观察限制、低误报分辨率和最基本的增量是否存在。
2. **机制与强基线。** 在 M7 的全轨迹材料上分解正常误报、E/X 阶段差异及文本与路由的不一致。
   同领域合法任务变化/同表面文本不同授权的对照是否存在，要先核查；缺失就报告不可识别，
   不能将 benign_control 的无害提及冒充合法跨任务执行。强文本/隐状态基线须有匹配前缀与成本。
3. **低误报与时效。** 研究 1% FAR 工作点及更低预算的统计可支持性；同时报告 X 前比例、
   延迟/未检出、正常任务损害和二级检查代价。不能将 X+16 命中称为攻击阻止率。
4. **独立检验。** 通用主张稳定后，各线冻结预注册、代码与正常阈值清单 SHA256，申请一次联合
   G-conf 解封。之后的跨模型/跨场景复制另议数据权限；本路线不自动授权生成新数据或解封。

若路由不胜过强文本，也不提供互补/更早/更低成本的信息，应收缩主张为机制与适用边界，
而不是在 G-dev 上持续搜索系数。简单算法可成立，但必须具有独立验证的额外价值。

## 不变的纪律

G-dev 全部读数均为 development evidence；只动 main 的 Codex 文件，产物放 codex_g。
不读取 G-conf 内容或标签；不使用 G-session/G-medium 攻击臂；不修改 Claude 文件或共享冻结代码。
不加载模型、不新增生成、不改标签、不把被观察截断样本直接记为算法漏检。
新观察协议与旧共同口径分开存档；仍按 episode 评价、双正常 FAR、家族聚类区间及配对检验报告。
