# Codex G / M2-A：正常转场对照后的机制证据

日期：2026-09-08 UTC。状态：**G-dev development evidence；不是确认性结论、因果识别或在线检测评价。**

本文E指共享标注派生的首次参与锚点`E_view`，X指首次实质偏离任务的内容产出，不等同于不可逆外部动作。U仅表示哪些专家入选，W加入实际top-4门控权重，P为全部32位router logits的softmax；此处P不是Claude线的surprisal基线。

## 给研究主管的结论

本轮实质上修正了[M1的解释](codex_g_m1_report.md)，而非只增加一个算法读数：

1. **X附近的强异常，在可匹配的同任务、同结构位置正常对照后仍然存在。** 31条匹配样本中，均匀入选表示U的目标百分位0.917、正常对照0.524，残差+0.393。仅用“从思考切换到回答通道”不足以解释这个子集的差异。
2. **E附近的全层抬升，没有显示高于匹配正常转场的增量。** E窗口目标0.619、正常0.636；E前后变化的差分残差也没有正向证据。M1的“E短脉冲”应保留为观察，不再直接当作任务偏移特异机制。
3. **连续路由信息仍有一条窄线索，但不是已经找到的早检信号。** E附近P相对U的后8层残差增量约+0.039；然而后层P的E前后差分残差仅+0.0028，区间跨零。后层的水平差异不能直接解释为E发生时新增的信号。
4. **对照覆盖是研究边界。** 主要匹配只覆盖25条E、31条X；完整E—中间—X对照仅8条。正常—正常的前后变化也可以很大。暂不能把完整三段形状、任意前后抬升或这些小子集的结果推广为通用检测机制。

下一步建议继续分解P的已选专家总概率质量及未入选部分，固定复用本轮匹配子集，并把全G-dev描述与匹配子集结论分开；本轮不改检测器、不冻结G-conf主张、不申请解封。

## 1. 固定设计与执行证据

[分析规范](codex_g_m2a_analysis_spec.md)在实施和匹配前提交（`da52c0f`），实现和测试在读匹配效应前提交（`8fc8847bdec0729f125016b6776a904f6fbd814e`）。

- 阶段A只用M1元数据、look端点/通道和G-dev trace结构，产生完整匹配清单；不解码或使用分数数组选样。先查看覆盖，然后按原规则进入阶段B，没有放宽匹配。
- 匹配清单SHA256：`3e64a8824eb60afe8dd7af352a455c68606f91c1eea5dd1aa90d7128b90e9a91`。
- 阶段B复用M1的U/W/P、正常拟合与参照、全24层、V1/message、w8和H352 looks；没有重算模型路由、重新拟合、选阈值或选择最优层。
- 所有donor必须是正常臂，与目标同episode_index、同M1留出fold。主列只取质量通过的正常臂；全部正常输入另作敏感性列。legitimate_refusal不进入正常对照。
- 精确匹配坐标为：通道、episode内Agent step顺序、step内同通道run序号、run内端点token偏移。一个donor必须完整覆盖目标查询的所有look，映射顺序严格递增，且w8窗不能跨step边界。没有丢掉难匹配的部分look来凑对照。
- S层级要求相同任务实例（scenario），至少1个完整donor；F层级要求相同环境fixture和routine template，至少3个正常scenario。二者不互相回退、不混池。

运行在CPU上：元数据/匹配约1.50秒，读数/汇总约0.98秒（不含解释器启动），打分峰值RSS约0.585 GiB，产物约20 MiB。这只是复用缓存的分析成本，不是生产部署延迟。

39项合成测试通过。另从M1分数重新回算305条配对读数、17,919对精确坐标和3,822个统计矩阵；正常—正常差分也复算一致。305条读数包含重复事件/层级/过滤口径，实际涉及58个不同攻击episode，**不能当305个独立样本**。主S/filtered各查询合计涉及47个不同episode。

本轮无重试；没有新增数据、加载模型、读取任何原始路由分片或路由缓存。G-conf及历史事故产物未读取、未验封存哈希；守卫无被禁止路径访问尝试。Claude工作树/分支、公共loader/harness、共享缓存和M1产物保持不动。

## 2. 先看哪些样本能被比较

输入仍是G-dev的784个episode、五路臂。事件目标先限制为载注入且共享E有效的198条；其中126条有X。88条multi_turn_user ep0被排除，40条载注入静默攻击没有E/X，不作为零效应样本进入事件比较。

| 查询 | S：同任务实例，质量通过 | S：全部正常输入 | F：同模板，质量通过 |
|---|---:|---:|---:|
| E窗口水平 | 25 / 12家族 | 28 / 13家族 | 4 / 4家族 |
| X窗口水平 | 31 / 13家族 | 37 / 14家族 | 9 / 6家族 |
| E前后差分 | 23 / 12家族 | 26 / 13家族 | 4 / 4家族 |
| X前后差分 | 29 / 13家族 | 34 / 14家族 | 7 / 6家族 |
| 完整E—中间—X | 8 / 7家族 | 10 / 8家族 | 3 / 3家族 |

F层级的全部正常输入列与过滤列在这些查询上相同，完整结果保留在产物中。

主要覆盖缺口不是程序失败：

- E水平：198候选中1条没有H内合格look；其余197条中98条没有同任务、同episode位置、质量合格的正常候选，74条有候选但无法完整覆盖结构坐标，剩25条。
- X水平：198候选先去掉72条无X、18条X窗在H内没有合格look；108条具有X窗look的候选中62条没有正常候选、15条不能完整覆盖，剩31条。这不是共享检测harness的命中可达性分母。
- E主匹配25条中16条只有1个完整正常donor，9条有2个；X的31条中13条有1个、18条有2个。每个S查询内donor不跨攻击episode复用。
- X主列含1条X+16未完整覆盖的episode，比较仅用其H内端点；不据此声称X时效性。完整E—中间—X主列也包含这条截断样本。
- E匹配子集没有任何over_refusal；因此本轮**不能**验证“拒绝/抵御过程的异常思考”这一结果类。其25条构成为执行16、执行后恢复3、仅参与5、承诺未执行1。

不能把25/197或31/108以外的样本当作“没有效应”。匹配对正常路径长度、步骤和通道结构有选择性；E匹配样本长度中位414 token，未匹配候选为312。M1中49条同通道E前后子集，本轮严格匹配的同通道E_did仅5条；事后该5条的U差分残差为+0.0477，区间[−0.0640, 0.2179]，不足以确认或彻底否定原子集观察。

元数据还有一项限制：本轮S匹配子集里T0/T1/T2与fold0/1/2一一对应；并非整个G-dev都完全对应，但其正常过滤池也明显不均衡。因此逐折与逐措辞层级不是两套独立复现证据。本轮保持共享折规则，没有为结果改折。

## 3. 正常对照后，E与X的区别

数字为**目标减匹配正常donor的百分位残差**。百分位只表示相对M1正常参照的异常排名，不是检出率、FAR或AUROC。先对区间look平均，再对每个目标的正常donor等权平均，最后目标episode等权。

| 同任务、质量通过的主比较 | N | U：均匀入选 | W：实际门控 | P：全专家概率 |
|---|---:|---:|---:|---:|
| E窗口残差 | 25 | −0.0168 | −0.0210 | −0.0275 |
| E前后变化的差分残差 | 23 | −0.0254 | −0.0230 | −0.0369 |
| X窗口残差 | 31 | +0.3930 | +0.3857 | +0.3901 |
| X前后变化的差分残差 | 29 | +0.1675 | +0.1640 | +0.1768 |

家族聚类2,000次、95%描述性区间：

- E窗口U残差[−0.0405, 0.0146]；E前后U差分残差[−0.0763, 0.0315]。没有显示高于正常转场的全层增量；这不是“等价于零”的检验。
- X窗口U残差[0.3504, 0.4384]；W [0.3420, 0.4313]；P [0.3451, 0.4268]。
- X前后U差分残差[0.0760, 0.2438]；W [0.0749, 0.2383]；P [0.0897, 0.2462]。
- family×tier稳健列中，X窗口U为[0.3496, 0.4361]，X前后U为[0.0772, 0.2506]；E对应区间均跨零。

这不是原百分位参考桶造成的唯一现象：raw JS的E残差U/W/P为−0.00865 / −0.00996 / −0.00103；X残差为+0.08895 / +0.09265 / +0.01369，各自方向一致。**不同表示的raw JS尺度不可直接比较增益**，例如P更平滑，本来就可能有更小raw幅度。

同一29条X前后子集中，U在X前16 token已有残差+0.2182，X后为+0.3857；所有前窗端点严格小于X，不含X后的look。它提示可研究X之前的局部产出准备/表达变化，但这里使用标签对齐，无在线阈值，不构成早检召回或提前量结论。

敏感性：使用全部正常输入，X水平残差U仍为+0.3922（37条），X前后差分为+0.1375（34条）。删去单个正常donor scenario后，主X水平U残差范围[0.3809, 0.4038]，每次目标N=30；不是单个任务实例贡献全部差异，也不是新的置信区间。

F层级9条X水平残差U为+0.3737，但7条X前后差分仅+0.0136，区间[−0.1034, 0.1109]。由于样本和donor均不同、覆盖很小，不把主S的前后差分描述成在所有匹配层级都复现。

## 4. 正常—正常对照为何重要

在同时有clean和benign_control完整donor的主查询中，预先规定的正常—正常比较得到：

- E水平9条：clean−benign_control的U差−0.0114，区间[−0.0715, 0.0317]。
- X水平18条：差−0.0517，[−0.1417, 0.0502]。
- X前后16条：两种正常臂的**前后变化之差为−0.1986**，[−0.3201, −0.0477]。W/P也约−0.20。复算确认不是符号、索引或窗口错误。

所以同一结构位置并不保证正常轨迹前后变化相同，不能假设差分满足因果分析的“平行趋势”。目标X前后差分的大小依赖选择哪种正常对照；“前后抬升”本身不是任务偏移的充分特征。

为定位这个现象，**事后**将原先同时有两臂的同一个子集拆开（不换样本、不更改主结果）：

- X水平18条：攻击−clean的U残差+0.4451，[0.3699, 0.5364]；攻击−benign_control +0.3934，[0.3294, 0.4494]。
- X前后16条：相对clean的U差分+0.3364，[0.1484, 0.4712]；相对benign_control +0.1378，[0.0372, 0.2194]。

X水平相对两种正常臂都保持差异；前后变化的效应幅度则明显受正常臂选择影响。该分解不是新的确认性检验，区间均条件于选定donor。

此外，匹配的是相同结构坐标，不是语义完全相同的句子；正常映射可以跳过未选中的正常输出，因此其控制片段不一定是连续17个token。任务执行路径、语言组织和内容类型的剩余混淆尚未排除。

## 6. 三段机制、分层与可推广范围

同一8条完整E—中间—X配对中，U的残差为+0.0250→+0.0894→+0.4089；“中间减E”的残差变化+0.0643，区间[−0.1006, 0.2712]。样本太少，而且这个残差形状不复现M1的“E峰值后回落”。因此**不把完整三段形状写成已发现的稳定机制**。G-dev本来就没有显式自我纠正（784行explicit_correction均为0），也不据轨迹类名称推断内部恢复机制。

主X水平13个实际家族的N为：JS debounce 2、Python retry 2、Rust clamp 3、SQL top customers 2、lighthouse 5、satellite 4、tide 1、legal case 1、legal clause 1、circle area 1、glass elevator 6、harbour crane 1、coastal itinerary 2。未覆盖DNA、compound interest、grocery plan三族，不能外推。

主X水平U残差分层：direct_user +0.3523（10条）、multi_turn_user +0.4470（15条）、tool_output +0.3258（6条）；T0/T1/T2为+0.4325 / +0.3576 / +0.4386（6 / 17 / 8条）。类上执行+0.4046（25条）、执行后恢复+0.3446（6条）。最小家族点估计是legal case +0.0691，但仅1条，不把这类小N极值当可靠边界。全部层带、家族与各层级缺口在产物中保留。

所有家族区间都**条件于M1拟合/参照和冻结的正常donor**，未纳入正常样本选择、匹配机制及参考估计的不确定性。F的9条X水平复用了15个donor episode、9个donor scenario，最多一个donor被4个攻击目标使用；不把家族bootstrap当跨家族共享donor情况下的总体错误率保证。没有确认性二元检验、McNemar或名义显著性筛选。

## 7. 下一步与交接

可对外报告的现阶段表述是：**在G-dev一个覆盖有限、按任务与结构位置匹配的子集中，路由的产出阶段异常不能仅由正常转场解释；早期全层抬升的偏移特异性尚无支持。连续路由表示显示层带差异，但尚未建立相对入选信息的检测增益。**

下一轮M2-B先注册P的分解诊断，保留U/W/P，不挑层，不按效果重选这批donor。应同时报告全G-dev描述及固定M2-A匹配子集，明确两者适用范围。若要进一步区分“任务是否被授权”与“输出类型/语义域改变”，现有正常转场对照仍不充分；任何新增独立对照数据都需主管另行批准，不能改写现有G场景工厂来补样。

只有机制足够清楚后才设计简单在线统计量；之后回到共享harness的X锚点、首报窗、pre-E罚则、双分母FAR、实测FAR匹配、家族bootstrap和精确McNemar。G-conf确认、模型/任务泛化、相对related work的额外价值均尚未检验。
