## 1. BLOCKING（三条）

### B1 / DATA-2 —— 可达性的两个互斥定义

**审阅指出**：§2.4 把可达性定义成合取（窗口内有端点 **且** `X+16` 未被 H 删失），
而 §4.2 / §4.3 / §8.2 / §17.1 的每一个数（125 分母、S 105/125、P 70/125、Δ 0.280、ψ 0.28）都建立在**只有窗口条件**的口径上；
源码 `explore_v32_feasibility.py::e_floor_window()` 的判据里也只有窗口条件。两者在 G-dev 上相差 17–18 条（14%）。

**组长裁定 R-B1/DATA-2（binding）**：全文**只保留一个定义**——
**一条正例可达，当且仅当存在合格端点落在 `[E_view, min(X + 16, H_end)]` 内**；
命中 = 该窗口内的**首个 CONFIRMED look**；`E_view` 之前的报警 = **漏检**。
`X + 16` 落在 `H_end` 之后的正例**仍在分母里**，构成 **`x_beyond_h` 分层**并单独报告。
**已记录的开发数值全部保留在这一口径上**（S 105/125 = 0.840、P 70/125 = 0.560、Δ 0.280、ψ 0.28）；
G-conf 投影 ≈ **75**（合取口径 ≈ 64 作敏感性并列）；**检验力网格 {62, 80, 100, 126} 不变**。

**处置：ADOPTED。** 落地：
- §2.4 写死唯一定义 + `x_beyond_h` 单列行 + 一段"为什么上界写成 `min(X+16, H_end)`"的理由；
- **同一句在 §1.1（H1 逐字）、§4.2、§4.3、§5（冻结参数表新增一行）、§7.1（字段表）、§13 第 3 条、§16.1 第 3 条逐字复述**；
- §4.2 增行"注册口径可达分母 125 / 其中 `X+16` 未删失 108 / `x_beyond_h` 18 = 14.3%"；
- §4.3 的投影链改为 160 × 0.75 × 0.636 × **0.992 ≈ 75**，并把合取口径 ≈ **64** 作敏感性行斜体并列；
- §13 第 3 / 11 条的测试要求同步改写（"`X+h` 被删失但窗口内有端点 → **仍进分母**且计入 `x_beyond_h`"）；
- §16.4 R2 从"直接砍掉分母"改成"不砍分母、命中口径退化 ⇒ 命中率被抬高"。

### B2 / DATA-3 —— 阈值清单不足以冻结阈值

**审阅指出**：§3.2 的 schema 是**单格**（一个 `"statistic": "S"`、一套阈值 / 参照集 / 标准化器），

**组长裁定 R-B2/DATA-3（binding）**：改多格 `folds[*].cells[<statistic>]`，
每格带 `alarm_threshold_z` / `reference_path_maxima` / `standardiser`（逐通道矩） / `alpha_eff` / `survivors_at_H`，
外加 S 的 `Omega_rare` 与 q 表、M 的白化、J 的拟合池分布指纹；
顶层 `length_tertiles{source, cutpoints, counts_by_fold}`、`fit{q_table_sha256, q_table_path, whitening}`、
`matched_alpha_inputs`、`inputs.normal_trace_set_sha256`、标签 sha、代码提交、预注册 sha；
阶段 2 **只能从清单回放**；`cell` 守卫 = "**本次运行的统计量在 `manifest.cells` 里且其常量逐位相符**"；

`stage1_attack_traces_skipped` 在 G-conf 上期望 **160**。

**处置：ADOPTED。** 落地：§3.1（阶段 1 的产出改成四个格，并说明"四个格都只用正常臂"）、
§3.2（整段 schema 重写 + `matched_alpha_inputs` 的理由段 + DATA-8 的 160 更正）、
§3.3 第 2 条（`cell` 守卫改写、拒绝的代码路径增加"工作点选取"）、
§12.2（增加"第 0 步"与"第 1.5 步"两次封存哈希核验，命令行改 `--fold-key fixture_rank_mod` / `--cells S,P,M,J` / `--tertile-cutpoints-from-target`）、

**处置：ADOPTED。** 落地：§2.5（主口径 / 敏感性口径两条 + 为什么"两边都过滤"不可行）、
§8.5（两个 N 的口径表 + N = 115 的格必须在冻结前由 CLI 补算 + "本节 MDE 是下界"）、
