# A02-D v1：正常极端尾部的定位诊断

2026-09-08，副对话算法线。先登记选择规则，再运行诊断。
这是依据已看 [A01](codex_g_alg_a01_report.md) 提出的 **G-dev adaptive development**，
不是新检测器、确认性检验或新的 FAR/recall 比较。仅正常输入，无攻击评分。

## 1. 问题及允许的下一步

区分三种竞争解释：正常库缺少相应模式；正常局部区域本来较分散；raw 距离经过通道/位置
标准化后被相对放大。数量支持、题材相似和几何支持分别报告，不把其中一个代替另一个。
只有诊断完成后才提名 A02 的单一算法修订；不在本轮调整层、窗口、k、距离或阈值。

## 2. 固定样本和对照

- 目标是 A01 的 U_mean/W_mean 在名义 alpha=.01 下共同报警的全部三个 filtered 正常 episode：
  `g_dev|g-dev-087--benign_control#ep1`、`g_dev|g-dev-087--clean#ep1`、
  `g_dev|g-dev-121--benign_control#ep1`。验证该集合，无事后替换。
- 每条取两个均值格首次报警端点的并集：已知分别 53、54、46/47，共四个 target look。
  每个目标 look 同时描述 U/W，不只选触发更强的一个。
- 对每个 target look，在 **同评价折、同回合、同通道、同 variant、filter_pass=True** 的正常中，
  排除三个目标所属 scenario。每个不同 scenario 选最接近的 look，排序固定为
  `(abs(channel_ordinal差), abs(episode端点差), key, end)`；再选前三个不同 scenario。
  不按原分数、报警与否、文本、最终长度或路由相似度挑这些结构对照；支持不足则如实列出。
  对照可能重复用于不同目标，不能当独立样本。所有选择先落盘，之后才解码和测量路由。

## 3. 固定测量

1. 全408正常的既有 raw/z/p 及三个fold的正常 fit/cal/eval 流，用于复核分母与正常尾部。
   描述每折/通道/回合/角色的距离与z分布、校准路径最大值，以及正常报警的通道/回合分布。
   分位数是相关窗口的描述性读数，不作独立样本推断。
2. 对每个选定 query，保留窗口8个token、此前最多16个和其后最多8个token的上下文。
   后缀仅供事后解释；检测分数始终由截至端点的路由计算。记录通道、step、ordinal、raw/z/p、
   截至该点的running max和路径最大值参考；逐值重放 z/p。
3. 输出实际 top_k_ids、所选4个logit的softmax权重，按8token×24层×4保存，不对bf16并列重排。
   对原三个不同scenario donor同样提供窗口文本及实际路由；每层/坐标的Hellinger贡献全部保存。
   每次更换输入源都核验token ID和输入SHA，重建的距离与A01保存值误差须≤2e-6。
4. 原 donor 的局部半径取其在 **同一正常拟合库** 中排除自身整个scenario后的A01均值分数。
   这是既有fit stream中的数值，不增加k或重选donor。记录
   `query三donor距离均值 / 三donor局部半径均值`，分母数值下限1e-6并记录是否触及。
   这是待检验的局部尺度诊断，不是已校准的新检测分数。本轮query均来自eval折，不在bank中；
   若以后用于fit查询，donor半径还必须排除query scenario，不能直接照搬以免二级近邻泄漏。
5. 同样测量预选结构对照，并报告原距离、局部半径、比值和有效标准化桶的mu/sd/支持数。
   对照不足、半径为零、不同角色分布漂移和不利案例均保留。不先定义“显著分离”的阈值。

不得把三个目标的改善当成总体 FAR 改善，或据正常-only诊断主张攻击召回、授权识别、泛化。
目标与结构对照上的文本解释不能成为题材白名单；不新增正常数据、不改变原质量标签或分母。
