## 0. 研究定位与分工

研究目标是：在生产级 agent 生成过程中，从 MoE 路由读出任务偏移信号，作为组合监测的一部分，
并明确其可检出范围、误报来源、时效、成本和泛化边界。

- **OLMoE 阶段只回答“研究是否值得继续”、提供假设。** 旧算法、最佳层、窗口、阈值和泛化读数，
  均不能作为 GPT-OSS 上的成立证据，也不限制新算法必须沿用稀有专家设计。
- **正式结论从 GPT-OSS 或随后获批的同档模型重新建立。** GPT-OSS 的 G-dev 结果仍只是开发证据；
  重复探索后补写冻结文件，不会使同一开发集变成确认集。
- **主对话负责机制及反证，副对话负责算法及端到端评价。** 机制观察约束算法假设，但不要求机制
  已经完全解释后才允许做算法实验；算法改善也不能反写成机制的因果证明。
- 保留简单算法作基线，但不预设简单或复杂算法必胜。论文贡献应是可独立验证的机制/检测增量，
  不是算法名称、模块数量、格式或题材专用规则。

与[主线分工](codex_g_mechanism_workstream.md)一致：本线使用独立文件命名空间，不改主线、Claude
或共享冻结代码；不创建或切换 worktree/分支。本文件也不自动授权新生成、新模型调用或解封。

## 2. 研究问题与主张阶梯

本线分别回答以下问题，不能用一个高 AUROC 代替全部问题：

1. **表示问题**：权重、跨专家/层联合关系、token 顺序，分别增加了多少可用区分信息？
2. **正常性问题**：误报来自单一正常参照不合适、少数模式覆盖不足、条件/校准漂移，还是不可区分？
3. **在线问题**：局部区分是否能转化为整 episode 低误报下的及时报警？
4. **额外价值问题**：相同可见前缀下，路由是否超越或补充文本/隐状态监测，或具有成本优势？
5. **泛化问题**：算法结构及其校准流程能否跨场景、攻击家族、批次、推理配置和模型成立？

主张按“局部结构 → 开发在线收益 → 独立确认 → 指定范围的泛化/部署”逐级升级。
本轮在线主终点仍为文本执行 X；E 阶段异常、拒绝/参与/未执行分别描述。
任何“识别参与”“识别授权”“拦截工具动作”的新终点，必须另写规范，不从 X 结果顺带推出。

## 4. 表示设计：不提前假定哪种信息充分

每个 token 保留层与专家坐标，不把全网求和作为所有方法的公共输入。设实际入选 mask 为 A：

- `U[t,l,e] = A[t,l,e]/4`：归一化二值选择；每层保留全部 32 坐标。
- `W[t,l,e] = A[t,l,e] * softmax(selected_logits)[e]`：实际入选集合内的归一化混合权重。
- `P[t,l,e] = softmax(all_32_logits)[e]`：完整概率，含未入选尾部；不是 W。
- 需要时把 P 分成入选总质量 m、已选内部 W、未选条件分布 Q，分别消融，不先合成一个标量。

实际缓存 top_k_ids 为准，不因 bf16 ties 重选 top-k。W 重建精度、和为一、缓存 token 对齐均须核验。
专家编号只在同模型同 revision 的同层有意义；不能把编号对应关系外推到另一模型。

三个轴分别消融：

| 轴 | 保留版本 | 删除信息的对照 | 不能声称什么 |
|---|---|---|---|
| 权重 | W/P | U | W 胜 U 只说明该读出利用了连续信息，不证明专家因果作用 |
| 联合结构 | 完整坐标的多模态/协方差/路径表示 | 同拟合条件的层块或对角化 | U 本身并未丢掉组合；不能把二值化和求和混为一谈 |
| 时间 | 截至当前的有序局部轨迹 | 同窗口的顺序不敏感表示 | “有序近邻”不是已学到长期动力学，也不是八份独立证据 |

特别地，窗口均值不仅丢掉顺序，也丢掉 token 间变异与逐 token 共现；有序张量胜过均值，
不能单独归因于时间顺序。若要提出纯顺序增量，需在后续规范中增加保留同一组 token 路由向量、
仅改变排列或使用顺序不敏感匹配的对照，单独校准并检查置换的统计含义。

跨层独立打乱、共同打乱 token 顺序等仅作为事先固定的离线统计结构诊断；保留条件和边际应明确。
它们不是模型干预，打乱后生成的路由也不被当作新的真实攻击样本。

### 6.1 四格、距离与正常库

固定全 24 层、V1/message、w=8、stride=1；窗口不跨通道。复用 M7 全端点，并断言无跨 step 窗口；
若发现新的跨 step 情况，先报告协议差异，不静默删端点。

对每层概率向量 a、b，使用平方 Hellinger 距离 `h2(a,b)=0.5*sum_e(sqrt(a_e)-sqrt(b_e))**2`。

- `U_mean` / `W_mean`：先取 8-token 各坐标平均，再求每层 h2，最后全层等权平均。
- `U_ordered` / `W_ordered`：8 个相对位置逐一比较对应层的 h2，再在 token、层上等权平均。

不扫距离、k、层、窗口或权重系数。首批不加入 P，不使用 PCA、近似近邻、监督训练或额外平滑。
有序版本要求局部相对位置对齐，不是动态时间规整；词序/分词变化敏感性作为限制报告。

正常库仅来自拟合折 filtered 正常，按运行时可知的 `(channel, episode_index)` 划分。
不匹配任务名、fixture、token 身份、最终长度、X/E 或是否报警；不由五个案例提取白名单。
每个库使用该拟合部分的全部合格窗口。先取每个 scenario 内的最近窗口距离，再对最近
**3 个不同 scenario** 的距离求均值；同场景两臂、邻接窗口或多回合不能占多个名额。
同时保存最近场景、episode、端点用于归因，文本只在评分完成后解释，不进入距离。

**自近邻泄漏防线**：构建拟合折标准化流时，必须排除查询的整个 scenario（所有臂/回合/窗口），
不能只删自身窗口而让重叠窗提供近零距离。cal/eval 场景本来不在该库中。
正常阶段检查各条件库在此排除后仍有至少 3 个 donor scenario；不满足则报告该格覆盖/契约失败，
先停止冻结，不返回 0、NaN 或把不支持的评价样本移出分母。

长场景包含更多候选窗的机会优势仍存在；首批如实记录各 scenario 的库大小和 donor 集中度。
场景均衡抽样/原型压缩留到新一批，不在看到结果后改变近邻库。

### 6.2 对照与预设比较

竞争基线原样重放 S、CW、TU 的 M7 原始流及配置；不只比较四个近邻模型彼此。

## 9. 文本、隐状态与组合监测的额外价值

TU 仅是弱词汇基线，不代表强文本监测。按数据与权限分三级推进：

1. **现有缓存可做**：S/CW/TU 同前缀重放；固定的上下文词汇表示/浅层文本模型可在训练场景拟合，
   其输入长度、训练标签预算、模型选择与输出时刻必须和路由明确对齐。
2. **需先审计可用性**：TaskTracker 风格的激活差、隐状态近邻、语义文本监测。只使用已有合格缓存；
   若缺相应隐藏状态/嵌入，不声称完成比较，不自行加载模型或补前向。
3. **组合价值**：固定 text-only、routing-only、text+routing，同训练/校准/评价划分与预算；
   在匹配实测 FAR 下检查额外及时命中、正常负担及计算成本。组合器不能在测试攻击上学习权重。

所有语义/隐状态方法只看截至报警时刻的同一可见前缀。需要重编码完整前缀的监测器，应计入重编码开销；
路由采集、搬运、检索也不能算作零成本。区分“更多信息”“更便宜的替代”“互补特征”三种论文主张。
路由相关工作与 TaskTracker/kNNGuard 的任务、训练监督和观测时刻不同，不能引用其原论文指标充当本地基线。

## 10. 泛化与数据缺口

依次区分下列实验，不用一个“泛化”标签混写：

1. G-dev 内 scenario-group 留出：首轮已采用，但同模板/世界仍可能相似。
2. 开发性 leave-family-out、措辞层留出及 leave-fixture-out：先冻结划分/数据量；模型选择只在训练部分。
   正常单类方法未用攻击训练时，“未见攻击家族”不自动等于跨正常任务泛化。
3. 预先冻结的源库/源阈值迁移到开放正常批，与许可范围内的独立正常重校准分开报告；
   G-bridge 的 agent 协议差异不能冒称只改变批次。
4. G-session/G-medium 正常臂：分别检验所观察会话前缀/推理配置的正常风险，不虚构攻击召回。
5. 独立确认及获批后的另一模型：算法结构/参数选择规则固定；目标模型重新用正常参考拟合与校准，
   明确这是方法迁移，不是专家编号、原型或阈值的零样本迁移。

主线已指出“同领域相同内容、不同授权”和“提及/拒绝/执行”的严格对照不足。
需要新数据时提交缺口、可证伪问题、最小样本设计、采集成本、标签/独立性方案，由主管另行批准。
增加负例可以检验覆盖假设，但不能把已经误报的测试例复制进拟合库再宣称泛化改善。

G-conf 仍只联合开启一次。算法/Claude 各自的正式主张、代码与阈值流程/清单 SHA 必须先冻结，
精确执行已有两阶段规则；同一 Codex 线拆成机制/算法副线不会获得额外确认次数。
在确认之前明确完整观察与 H352 的共同协议；确认后不重新选候选、修改阈值或把失败批改名开发集。

## 11. 主线机制发现如何更新本计划

### 11.1 同步节奏与证据卡

每次算法轮次启动前、主线新增完整报告后、或主管给出新证据时，先只读同步主线已提交报告及审计。
执行依赖在当轮锁定；不读取正在写入的半成品产物作为依据。这里是被唤起时的同步流程，不是后台监控承诺。

每条机制输入记录：`MECH-ID / 来源文件 / commit / sha256 / 数据与分母 / 测量与匹配条件 /
方向与不确定性 / 覆盖缺口 / 竞争解释 / 对算法的预测 / 允许修改的下一轮 / 不允许推出的结论`。
未经审计的口头观察可登记为 hypothesis，不自动改主格。算法发现的反例以 key/端点/路由归因和
复现路径交主管/主线 review；不在本线修改行为标签或把反例解释写成已确认机制。

### 11.2 更新触发与动作

| 主线新结果 | 下一轮算法动作 | 必须保留的边界 |
|---|---|---|
| 残差主要由未匹配的前7 token解释 | 提高上下文文本对照优先级，比较 mean/ordered 的来源 | 不称当前 token 独立意图信号；不删除不利窗口 |
| 当前 token 在更严控制后仍有差异 | 提名局部联合表示/条件读出，检查跨场景支持 | 更长上下文仍可能解释；不直接命名“意图专家” |
| 权重在相同支持/历史下有稳定增量 | 提高 W/P 分解或学习表示的优先级 | 正负方向及尾部抵消均保留，不任意挑专家/层 |

### 11.3 可变总计划与不可变实验

- **本总计划可更新**：每次增加版本号、日期、证据来源、改变的优先级与理由，保留修订日志。
- **已冻结 spec/代码/库/阈值/输出不可覆写**：新发现只产生下一版实验 ID，不让运行中的实验换参数。
- 若发现泄漏、时序或实现错误，立即停止相关运行并标 invalidated；保留旧输出及事故说明，
  另立修正版本。不能把修 bug 与结果后调参混写。
- 新发现与已有设计冲突时，正常完成并报告合法的已冻结比较，或在看结果前明确撤回；
  不因结果不利改变主终点。必须纠正的有效性错误不受“继续跑完”要求保护。
- G-dev 反复被两线使用，主线新发现也属于同一开发数据的适应性信息，不能包装成独立验证。

## 12. 执行、权限与可复现性清单

独立命名：`docs/research_v4/codex_g_alg_*`、`scripts/research_v4/codex_g_alg_*`、
`tests/test_research_v4_codex_g_alg_*`；输出仅在
`artifacts/agent_v2/codex_g/alg_<实验ID>_<版本>/`。本文件是总入口。
主线 `codex_g_mech_*`、旧 M1–M8、Claude worktree/branch、共享 loader/harness 保持不变。
不把模型、轨迹或大型库提交 Git；本次写计划不附带 commit/push、分支或权限变更。

每次执行顺序：

1. 同步并记录机制快照、源码状态；明确本轮数据权限、终点、全格列表与参数。
2. 先写独立 spec，合成测试通过，再冻结源码/配置/种子/输入清单 SHA。
3. 仅正常数据拟合、覆盖检查、校准和工作点选择；冻结库/阈值清单。
4. 禁止重拟合的攻击评分；所有原始分数有限、正常流逐值重放，端点与 M7 网格一致。
5. 独立重算首报/分母/FAR/配对差；近邻的完整scenario排除、距离公式和token对齐另审计。
   A03参数模型fit分数明确为resubstitution，cal/eval场景仍完全隔离；不把参数拟合伪称近邻LOO。
6. 报告全部预设格、失败与资源成本；更新本计划的候选状态和下一轮理由，不覆盖旧实验。

必须测试：前缀不变性（追加未来 token 不改变此前分数）、step/通道边界、分层/权重守恒、
无自近邻/跨折污染、确定性近邻平局、状态恢复不重训、空支持失败、NaN/inf 拒绝、
原始窗口不二次平滑、独立首报重放、封存路径访问拒绝。

Python 数据读取安装 CodexGAccessGuard 并核验实际许可缓存哈希；该守卫不是操作系统隔离。
不得通过其他工具绕过封存边界。当前只用缓存和 CPU；新增生成、受控复放、嵌入/隐状态前向及
新模型须另获授权。获批加载模型时仍须绝对路径 `gpu.lock` 的 flock 协议、前后 nvidia-smi、一次一个驻留模型。

两对话共享 main；文件命名隔离不等于全仓 HEAD 冻结。若现有 runner 强制 HEAD 不变，先协调一个
冻结执行窗口或请求独立 worktree，不放宽共享守卫，也不自行创建/切换分支或覆盖他人修改。

## 14. 相关工作入口与适用范围

以下只作为设计依据；后续复现实验必须在同前缀、同数据角色、同评价口径下运行，不能直接比较原论文数字。

- [MoEE：路由权重作为语义表示](https://arxiv.org/abs/2410.10814)：支持研究表示/正常模式，不证明在线偏移检测。
- [Polysemantic Experts, Monosemantic Paths](https://arxiv.org/abs/2604.17837)：跨层路径结构的设计动机，不授权本线把簇直接命名为认知类别。
- [Does the Same Token Mean the Same State?](https://arxiv.org/abs/2606.22798)：同 token 下仍有上下文与历史结构；答案选择任务不同于本项目。
- [TaskTracker / Activation Deltas](https://arxiv.org/abs/2406.00799)：任务偏移的隐状态比较基线；需核验本地可用输入与观测时刻。
- [kNNGuard](https://arxiv.org/abs/2607.02072)：带标注的隐状态/嵌入近邻监测；不是本线正常单类路由检测的同义方法。
- [RASET](https://arxiv.org/abs/2605.29708)：主题相关路由与安全行为可能分离，提醒勿把语义可分直接写成授权/安全可分。
