# Codex G / M8：词汇匹配后仍有局部路由差异，但执行选择性尚未被识别

2026-09-08。**GPT-OSS-20B / Agent v3 / G-dev development evidence。非确认性结论。**
本轮是机制分析，不是新检测器；M7的阈值、recall、precision与FAR未改变，G-conf仍封存。

## 1. 给研究主管的结论

1. **有一个值得保留、但范围很窄的关联。** 匹配词频新颖性、当前token、通道和因果位置后，
   X执行阶段的S/CW仍高于合格正常对照。可是只有28/126条正例、45/2,142个窗口能匹配，
   即22.2%的episode、**2.10%的执行窗口**。这不是“控制文本后普遍成立”。
2. **还不能把M7的“拒绝时少报”解释为识别了执行意图。** 对过度拒绝53条的主匹配结果为零；
   对参与但未执行33条仅匹配5个窗口；合法拒绝臂24条也仅11个窗口。
   样本之间缺乏可比位置/词汇，不是被观测视界截断，更不是检测器漏检。
3. **完整8-token序列相同的严格对照，在X阶段六个池全部零匹配。** 因而当前token一致下的差异，
   仍可能由其余7个token、顺序或更长上下文解释。不能宣布路由提供了超出文本的条件信息。
4. **不应由此再加一个算法项。** 本轮没有检验CW优于S，没有建立提前阻止能力，也没有完成强文本对照。
   下一步应检查残余词汇/上下文解释，并设计真正配对的授权与行为对照；新增数据需另行批准。

可对外表述为：**“路由异常并非在所有可匹配窗口上都能由粗词频和单个token身份解释；
但现有数据尚不足以识别独立于生成内容的任务执行选择性。”**

### 3.1 合格正常对照下的局部关联

原始S差为**+28.23 [13.97,51.76]**，CW差为**+37.39 [18.77,69.09]**。
Δz中位数分别8.30/10.28，25/28个episode均为正；不只是单个正差离群值。
family×tier的Δz区间分别[6.84,17.18]/[8.25,20.86]。但S与CW的z尺度分别由各自标准化器定义，
**CW的数值更大不等于信息更多、算法更优或增加权重就有增益**。

其范围限制很具体：

- 45个匹配窗口**全部是final通道**，28条里19条为creative域、仅2条为code域。
  9家族为JS-debounce、SQL-top-customers、lighthouse、satellite、clause-analysis、circle-area、
  glass-elevator、harbour-crane、coastal-itinerary，大小依次`[1,1,3,6,3,2,5,5,2]`。
  不代表analysis通道或16家族的普遍性质。
- 仅5条episode的7个look能找到3个不同donor；该子集Δz(S)=19.67 [3.89,41.49]、
  Δz(CW)=24.64 [5.00,52.38]，方向保留但覆盖仅0.33%，不能用大效应掩盖小支持度。
- 用到50个donor episode、44个scenario，单个donor最多被复用3个query窗口，
  最大有效权重7.44%；这个权重已计入query episode平权及其内部look平权。
- 配对TU绝对差的episode平权均值为.1244 nats，TU有符号差+.03644，CI[-.01706,.06762]；
  平均端点距离14.80 token、最大50。所谓“控制位置”是固定粗格，不是精确位置或完整上下文一致。
- 全126条X窗口的无匹配原始S/CW/TU均值为39.40/51.04/8.538；L1可匹配子集为31.62/41.00/7.076。
  子集明显偏向词汇较不新颖的窗口，不能外推到全部偏移产出。

### 3.2 在相同查询上比较，避免把覆盖缩小误当成解释量

对合格正常池，固定同一批L1合格的45个query look：L0的Δz(S/CW)=10.78/13.03，
L1为10.91/13.16。控制当前token并没有消除**这批窗口**的差异。

再固定同一批tight合格的23个look、16条episode：L1为10.81/13.29，tight为10.75/13.24。
平均TU绝对差降到.0503 nats，tight家族区间为[4.71,21.34]/[6.06,26.64]。
这里也不能说已排除词汇解释：每个窗口另有7个token及更长上下文未固定。

完整8-token的L8在X阶段六个donor池**全部零匹配**。对正常filtered而言，原45个L1合格look
全部因整窗不符而落空。这是可识别性缺口，不是“严格控制后效应变成零”。

### 3.3 拒绝对照的失败主要不是路由问题

过度拒绝池：2,142个X窗口中，2,105个（98.27%）连共同结构键都没有支持；剩37个中
11个TU超caliper、26个当前token不符。L0也仅有3条episode的26个窗口可比。
因此不能用原M7“0/53拒绝报警”与执行报警率的反差，直接认定算法识别了执行意图。
这里没有按最终长度匹配，失败反映本数据在当前通道/轮次/step/前缀位置上的可比性不足。

其余未执行/拒绝池的L1支持同样很薄：engaged_only仅4个donor episode支撑5个query窗口，
最大donor有效权重40%，全为T2；合法拒绝9个donor支撑11个窗口，最大权重20%。
四个第三类池在X阶段都没有任何≥3 donor的L1窗口。正向点估计不能承担广义“行为选择性”主张。

## 5. 对下一阶段研究的建议

1. **先排查残余解释，不立即融合S和TU。** 检查共享token所处的8-token上下文、词序和更长文本，
   引入具有相同可见前缀与成本说明的上下文文本基线。L1不是“相同文本”的充分控制。
2. **把授权与执行两个轴分开。** 真正需要的是同领域/同内容、不同授权的执行对照，以及
   同任务内容的提及/拒绝/执行对照；原benign_control不等于合法跨任务执行。
   自然生成用于端到端行为/时效，受控相同输出复放用于机理，二者不能共用一个效果量。
3. **新数据先出方案并获主管批准。** 单独的namespace/ID流、固定原G哈希与不触碰G-conf是前提。
   不能通过现有共享场景工厂随手补样，也不能解封G-conf弥补本轮词汇共同支持不足。
4. **算法主张仍未升级。** 本轮只支持“部分局部关联未被弱词汇控制解释”，不支持授权识别、因果性、
   CW优于S、优于强文本/hidden-state监测、跨模型泛化或生产低FAR保证。M7所有二元读数仍原样保留。
