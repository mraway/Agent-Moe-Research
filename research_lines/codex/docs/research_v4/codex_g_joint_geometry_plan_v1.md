# Codex / 数据集 G：联合路由结构的增量检验

版本 v1（2026-09-08 UTC）；基座 `12c83b4`。这是实施前的短研究计划，**不是 G-conf 预注册或解封申请**。唯一入口为 [G 入门包](research_v4/dataset_g_onboarding_for_codex.md)，含末尾四条批准修正。当前检测实验暂停，先处理[冒烟访问事故](research_v4/codex_g_access_incident.md)。

## 1. 主张与差异点

**待检验主张：正常任务中的跨层专家联合关系，在单层分布变化之外，能提供在线检测文本任务偏移的增量。** Claude 主线比较稀有选择统计 S 与边际 surprisal P；本线固定一个联合几何候选，直接删除其跨层依赖作为主对照，不搜索稀有阈值、不做题材/格式特例、不重复 Claude 负责的 B-NT / A-w4。

目前 G 的选择类统计在 E 阶段弱、X 阶段强，只作为设计动机；OLMoE 全部降为 hypothesis-generating pilot。联合统计胜出只支持“跨层统计依赖对读出有用”，**不证明专家的因果作用、授权特异性、E 前预警或可部署性**。同样，不显著不等于证明不存在联合信息。

## 2. 一个候选、两个结构对照

输入仅为逐 token 的 top-k 选择指示器，展平为 768 维。保持 V1 / message、全 24 层、w=8，严格使用基类的通道内因果窗口。对正常拟合折的合格窗口向量 \(y\)，按窗口等权估计均值 \(\mu\) 与协方差 \(\Sigma\)，不使用攻击标签；窗口重叠不增加统计推断的样本数。

令 \(D_{ii}=\max(\Sigma_{ii},10^{-3})\)，\(v=D^{-1/2}(y-\mu)\)，\(R=D^{-1/2}\Sigma D^{-1/2}\)。首批固定收缩系数 \(\lambda=0.1\)，不扫参：

- **CJ（主候选）**：\(s_J=v^T[(1-\lambda)R+\lambda I]^{-1}v/768\)。
- **CB（主对照）**：将 R 的跨层块置零，保留全部 24 个层内块；其余公式、拟合窗口、参数完全相同。CJ−CB 专门检验跨层依赖的增量。
- **CD（描述性）**：只保留 R 的对角线，检查层内联合关系是否已经解释差异。另复算共享 S/P/M 作为竞争基线；不得把 CB/CD 冒称与 M 数值等价。

采用正定求解而非显式求逆。统计量只输出原始异常分数，不覆盖 `stream()`；实现为自己的 `GStatistic` 模块和薄注册 wrapper，不修改共用 harness。`config()` 固定全部常量；拟合状态、配置及拟合 episode key 清单序列化并校验 sha256。先测前缀不变性、同一 look 栅格、状态重放、跨层块删除及标签不可访问。

## 3. 校准与评价单元

全部使用入门包 §5 的公共口径：K=3、`fixture_rank_mod`；折 k 评价、k+1 拟合、k+2 构造 C1 全路径最大值参照；拟合/参照只用 `filter_pass=True` 正常臂。通道/位置标准化、稀疏回退和状态规则原样复用。H=352 **looks**，α=0.10；逐折 `alpha_eff` 直接采用 harness 输出，不另实现公式。

主正例为攻击臂中有 E_view 和文本 X、且有合格端点落入 **[E_view, min(X+16, H_end)]** 的 episode；首报早于 E_view 记漏检，band=0。文本 X 不等于外部不可逆工具动作。越界 X 保留原分母并单列；E+16、早于 X 比例及容差带只作描述性。

主比较固定 **CJ > CB**：CB 在阶段 1 的过滤后正常池上匹配 CJ 的实测 FAR，名义 α 相同列并报。按 episode 计算召回和双分母 FAR；另报逐折、逐正常臂、长度档、scenario-group、注入渠道、家族及最差组。静默攻击只包含注入后 episode；同步检查 F1–F5 等适用门，不能用召回提升抵消误报门失败。

输出配对 Δ、家族聚类 percentile bootstrap 95% CI（2,000 次）、family×tier 稳健列、精确 McNemar 的 b/c/p；合取标准为 CI 下界>0 且双侧 p<0.05。落盘实际家族数/大小；不足16家族时重算零假设模拟。区间条件于所选工作点，不含匹配阈值的选择不确定性。S/P/M/CD 比较不新增确认性主张。

## 4. 实施顺序与停止规则

1. 计划先提交；访问事故经主管裁定、严格守卫冒烟通过后，才实现统计量及合成单测。只读开放池，不生成任何新数据、不加载模型。
2. 在看本线检测结果前冻结首批代码、参数与命令的哈希；在 G-dev 做一次共享两阶段排练：正常臂校准并冻结 manifest，再评价攻击臂。结果一律标 **development evidence**。
3. 检查 CJ/CB 增量来自 E 前、E–X、X 附近还是 H 外；检查是否被静默攻击、困难正常或通道构成解释。并报 CPU 拟合/每千 look 打分时间、峰值内存和状态大小。不把高维协方差的估计误差包装成机制否证。
4. 若联合项无稳定增量、收益仅来自更高误报或成本不合算，保留负结果并回到简单边际；若要修订候选，先另写版本，不能覆盖首批结果。是否进入确认阶段交主管 review。
5. 有可检验主张后，单独冻结正式预注册、代码和阈值流程/清单哈希，才申请两线联合解封。当前不读取 G-conf 轨迹、路由或文本标签，不做封存哈希核验；目标批正常臂阈值只能在获批联合阶段1产生，随后冻结，再进入阶段2。

代码与文档仅写 main 的自有文件；产物仅放 `artifacts/agent_v2/codex_g/`。G-fit/G-cal/G-bridge 只作开放正常参考/迁移诊断；本首批不使用 G-session/G-medium，后续也只能用其无标签正常臂。目标批自校准只证明批内 scenario-held-out 读出，不提供未来流量误报保证。若最终需要模型，须另获任务授权并遵守绝对路径 `gpu.lock` 的 flock 协议。
