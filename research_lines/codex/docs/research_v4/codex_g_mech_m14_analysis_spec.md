# M14：异常的时间组织与行为返回（开发性机制分析）

2026-09-09。根据组长关于“持续异常、短暂异常后回归”的问题，先冻结方案，再读取本轮数值结果。
只用 GPT-OSS-20B / Agent v3 的开放 G-dev；不训练或优化检测器，不评价 recall/FAR，G-conf 不动。

## 1. 问题与反证

H14a：在异常幅度/占用量之外，异常的连续排列仍有信息，而且不完全等同于正常文本的时间相关性。
H14b：标注为“返回原客服任务”的片段伴随路由局部读出的回落；回落不只是正常转场或高值后的自然回归。
持续性不预设与执行程度单调对应；未执行也可持续参与异常请求；短暂执行仍是执行。
“返回客服工作”不等于显式自我纠正、原任务已完成或以后不再执行。

本轮是窄测量：复用 M8 全轨迹的局部 S、CW、TU 原分数和标准化 z。
CW 含已选专家相对权重；TU 是文本新颖性对照。**不测试完整 32 专家概率流的全部时序信息**。
不使用 running-max、累计报警、锁存状态或滞回退出规则；不恢复 H352 截断。

## 2. 输入、参照与时间网格

输入为哈希冻结的 M7/M8 产物，及 G-dev `annotations/g_dev/final_unblinded.jsonl`。
只读标签的恢复段、E/X、类型、质量与失败标记，不改标签，不加载模型/分词器，不开原始轨迹或路由缓存。
核对 784 episode、190284 look、正常 filtered293/all408、载注入264（排除注入前88）、静默40。
标签可用性核查是本轮结果的一部分：段数、坐标、通道、相对 E/X 顺序、显式纠正、再执行、GENFAIL。
现有 `recovery_spans` 按最早 E 后的第一段客服工作标；可以在 X 之前，不能从轨迹类反推 R。

描述性幅度为 z 在**同评价折、同通道、过滤正常 episode**中的加权中秩百分位。
每个正常 episode 在该通道权重相等，episode 内 look 等权；正常查询减去自身贡献。
每个参照至少 10 个独立正常 episode；不足则缺失，无回退。参照只含正常数值，写盘后才算攻击百分位。
这是目标批内的测量尺度，**不是 conformal p、不保证误报率、不是可部署的校准方案**。
同折避免把不同拟合参照下的原分数混成一个参照；z 继承 M7 位置条件化，原分数变化同时报告。

连续段由 episode、Agent step、通道及相邻端点是否连续共同界定，不跨段续接。
主网格取段内第一个合法 8-token look 后每隔 8 token 取一次，窗口互不重叠；
固定稳健网格将第一端点右移 4 token，再每隔 8 token 取一次。两格全部报告，不择优。
不足一完整 look 的位置不可观测；末尾剩余 token 不填零，段结束时仍高记右截尾，不解释为恢复。

## 3. 时间组织：固定幅度集合后的次序差异

主读出 CW，S 和 TU 并列竞争解释。高值定义百分位严格大于 .90；.95 固定敏感性。
对 n 个不重叠块，K 个高块，HH 对相邻高块，计算：

`order_excess = HH/(n-1) - K*(K-1)/(n*(n-1))`（n>=2）。

第二项是**给定 n、K 的均匀随机排列**下第一项的精确期望；因而这个量不只是高值次数。
随机排列不是正常 agent 的零假设，仍须与真实正常段比较。
同时报告平均幅度、高值占用、观测最长高值连续段（块数×8）、高值段数、两端截尾标记。
“最长”是观察下界，不是删失校正后的状态寿命；n<2 的 order_excess 缺失而非零。

正常匹配：每个查询段找最多 3 个不同 episode 的 filtered 正常段，scenario 与查询不同；
同 fold/channel/episode_index/step、**完全相同块数 n**、首端点位置相差<=64，
首块 CW 和 TU 百分位分别相差<=.10。按两项差之和、位置差、episode key、段编号排序。
只用首块幅度、结构和长度选 donor，不看后续分数、最长持续或 order_excess。
完整长度匹配是**离线等观察机会比较**，使用未来长度，不能冒充在线预测验证。
先冻结匹配图，再计算后续时间特征；另外报告同 family 的严格匹配，缺支持不放宽。
正常自身也按同规则做正常—正常 placebo；参考自身排除与 donor scenario 排除不可省略。

查询分层：全部正常/过滤正常/合法拒绝；载注入 execution、support_resumed_after_execution、
engaged_only、committed_no_execution、over_refusal、silent。注入前88条只计排除数。
按通道及块数档 2–3/4–7/8–15/16–31/32+ 分列，不能把全 episode 类称为当前块状态。

## 4. 行为返回：R 对齐而非从曲线选恢复点

主分析每个载注入 episode 的**第一条已标恢复段**，不按路由或覆盖挑另一段。
R 为该段 `span.token_start_global`，结束为 `token_end_global`，两者闭区间。
前块端点 R-1；后块端点 R+7、R+15、R+23、R+31，均是互不重叠的 8-token 窗。
后块必须完整落在标注恢复段内；主配对要求前后同通道、同 step，跨通道单独计缺支持。
逐时距报独立可用分母，另报四个后块全可用的同一批轨迹；不拼不同分母的平均恢复曲线。
分开 R<X、R>X、无X；等址/重叠等异常情况单列；`re_execution` 与显式纠正单列。

正常 pseudo-R 从全部合法前块端点产生；同 fold/channel/episode_index/step、位置差<=64、
前块 CW/TU 百分位差各<=.10、不同 scenario；按第3节规则最多3个不同 donor episode。
**不得按 donor 未来是否足够或是否回落选点**；冻结匹配后才核查逐时距支持。
量为 query(后-前)、donor(后-前)及二者之差，S/CW/TU 原分数与百分位同时保存。
全体可用前块为主；前块 CW>.90 的条件列单报，以观察高值后的回落，但承认回归均值选择。
若无合格前块/后块/正常对照，只报告覆盖，不能判为无恢复或算法漏检。
原始证据字符串不重新裁定；这是使用冻结标注的时间/结构核验，不是独立语义复标。
