## 2. Alternative explanations tested and rejected

1. **The residual is the known concentration scalar** (mass in top-8 / entropy / top-1; synthesis §1.3 says that direction is common to all drift and cross-batch unstable). Rejected: the four scalars over L5-15 give AUC 0.76 [0.72, 0.81] for code; rP with the scalars regressed out gives 0.964 [0.95, 0.98]; rP with the per-window {1, S_w} span projected out gives 0.955 [0.94, 0.97]. R2 of P on [S, scalars] is 0.891 in-sample vs 0.878 on S alone, so the scalars add ~1 point of explained variance. The separation is genuinely a distributed re-weighting across experts.
2. **Duplicated positives** (h384 replays): 28% of code windows are byte-identical to b2 windows; dedup changes nothing (0.961).
3. **Whitening leakage / floor**: none (section 1, row 6).
4. **Scenario context / injection**: resist arms and pre-boundary windows of the programming traces sit at the routine level (AUC 0.52).
5. **float16 / top-8 tie effects**: none (section 0).

## 3. Confounds that survive

1. **Token position.** rP grows with position on routine traffic (Spearman 0.38; late-vs-early routine AUC 0.74) and the linear S -> P map degrades with position (held R2 0.879 -> 0.836 from the first to the last band; in-sample 0.885 -> 0.856). Code windows are late (median end 155 vs 59 for held routine) and 27% of them lie beyond any held negative. The position-matched AUC is 0.93 (100-192) and 0.94 (>= 192, vs h384 routine), the position-fair margin is 1.14x the late-routine q95 with 61% of late code windows above it. The 1-D in-set residual mass is position-free (Spearman 0.00) at AUC 0.85-0.88. The other-domain AUC is not affected in the same way (rP 0.977 pooled). Neither the original's kNN control nor its per-layer table addresses this.
2. **Cross-pool tail.** Mean shift and margin ratio (item 4) are the wrong statistic for a threshold; the q99 of rP on b1 is 3.3x the b2 q99 (S 1.6x), the late-band b1 q95 is 3.8x the c1 late-band q95 (S 2.1x), while the plain q95 ratio b1/b2 is 1.24x (S 1.17x) - the excess is in the extreme tail. Both views share the same b1 JSON-action scenario as the tail driver, but the residual magnifies it.
3. **Small n.** 9 scenarios, 4 literal-code; per-scenario rP AUC 0.91-0.995 (S 0.62-0.95), so the ordering is consistent, but the CI already reflects 9 clusters.

## 4. Verdict

* **Stands**: item 1 entirely; item 2 (R2 0.878 / 0.856 / 0.869 routine, 0.70 code; cross-validated); item 3's AUC ordering S 0.77 < P 0.82 < rP 0.96 with the trace-bootstrap CI; the "information absent from S, distributed across experts" reading (controls: scalar removal 0.964, span{1,S} removal 0.955, resist/pre-boundary 0.52); the mean-stability part of item 4; the whitening caveat is unnecessary.
* **Falls / corrected**: the margin "1.35x routine q95, 77% of code windows above q95" is a position artefact; position-fair values are **1.14x and 61%** (AUC **0.93** in the band where code lives, S 0.78 there). The verdict's "not preferentially the part that drifts across pools" is **not confirmed**: the residual's cross-pool tail is 2-3x heavier than the indicator's (b1 q99 3.3x b2 q99 vs 1.6x for S; b2-calibrated q95 FAR on b1 10.3% vs 7.6%). The per-scenario S fractions in the per-trace table are overstated (0.53-0.84 -> 0.32-0.62 once replays are merged). The "14 traces" count is 9 traces (28% duplicate windows), which the original notes in prose but not in its tables.
* **Not independently checked**: kNN residual (0.97), rQ / rPout split (item 5), JS divergence.
* **New**: the 1-D in-set residual mass (P mass on the selected experts minus its S-prediction) gives code AUC 0.88, is position-free, resist-neutral and transfers b2 -> b1 at 5.4% FAR at q95; it is the position-clean core of what rP measures and the natural successor to rmass if this direction is pursued. Everything above remains a window-level representation finding on post-hoc anchors, not a detector result.
