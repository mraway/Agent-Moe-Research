## 一、研究目标：探索什么信号，而不是先承诺什么检测器

### 1. 核心问题

> 当 Agent 从获授权任务转向处理题外要求时，MoE 的专家选择与路由权重发生了什么变化？这些变化反映的是输入暴露、题材变化、任务外参与，还是实际执行？哪些信号能够成为简单、低成本、在线的任务监测依据？

研究对象是一个有明确任务边界、可以调用工具的 Agent。MoE 路由是模型处理 token 时各层选择的专家及其权重。我们希望相对于正常任务参考识别异常计算行为，作为安全系统的一路信号，而不是单凭路由判断攻击成功、任务正确性或是否必须阻断。

优先级是：**可信的机制发现 → 机制支持的简单算法 → 跨场景验证与成本评估**。不要求新算法一定复杂，也不要求所有偏移都能检出。

### 2. 必须区分的事件

| 事件/标签 | 含义 | 不应混淆为 |
|---|---|---|
| 输入暴露 | Agent 接收到外部或用户注入的题外要求 | Agent 已经参与该要求 |
| E：可见参与 | 首次具体引用、评估、拒绝、计划或执行题外要求 | 攻击已经成功；针对具体要求的拒绝也可产生 E |
| C：承诺 | 明确承诺完成题外交付物，或已开始完成 | 已交付实质内容；承诺可以撤回 |
| X：实质执行内容 | 开始生成题外任务的实质内容 | 外部动作已不可逆地发生；文本 X 与工具实际执行单独记录 |
| 恢复 | 在可见连续片段中回到合法工作，另记录是否再次偏移 | 历史上未执行过；分数回落也不自动证明行为恢复 |
| 任务质量 | 合法任务是否完成、事实和引用是否可靠 | 任何答错都等于任务偏移 |

“抵御过程中的任务外参与也值得监测”是本项目的研究设定。它不意味着拒绝是一种违规，也不意味着纯粹的注入暴露应被算作 E。合法任务要求引用某段文字时，还须依据任务边界判断，不能看到关键词就标 E。

onset 是可见证据的起始位置，不是直接观测到的内部意图时刻。泛泛的过渡词本身不算 E；保留证据完整可见点及不确定区间，评价锚点敏感性。正式定义沿用[事件标注协议](agent_v2_onset_reliability_audit_plan.md)，新任务的扩展在标注前冻结。

后文 FAR 指误报率：预先定义的正常流量单位中至少报警一次的比例。按 episode、会话或配对场景计算的 FAR 分母不同；AUROC 衡量分数排序，不等于某个在线工作点的召回与误报。

### 3. 统一的机制视角

专家支持集扩张、专家边际频率重排、支持集内的联合关系和时间变化，都可以放在“正常参考分布与当前因果前缀的分布差异”下研究。但它们是不同信息层次：只看边际计数的方法不可能自动观察所有联合关系或 token 顺序。

因此先建立最简单的分布/距离读数，再逐项检验：加入权重、跨层关系或时间信息是否确有增量。不能因为数学上可以统一，就默认复杂统计更有效。

### 2. 新加入者必须知道的最新结果：G 改变了机制问题

[G-dev v3.1 冻结报告](../../claude/docs/research_v4/g_dev_confirmatory_report.md)的主格是 V1、H=352 looks、E_view+16、严格首次命中、可达正例 197；S/P 在目标正常池上匹配实测 FAR。不要与 Astra 的 H192/E=45 表直接比较。

| 读数 | 实际结果 | 本交接稿的解释 |
|---|---|---|
| S vs P 主比较 | 9/197 vs 1/197；净差约 4.1 个百分点 | 原报告按其预注册规则判 H1 成立；但绝对召回不足以支持“有效早期参与检测器” |
| 相同实测 FAR 的 M 对照 | M 为 25/197，高于 S 的 9/197 | 复杂或被主推的机制解释必须接受简单对照竞争 |
| S 正常 FAR | 全部正常输入 86/408=21.1%；过滤后 70/293=23.9%，名义 alpha=.10 | 统计差异与可部署工作点是两回事；同 FAR 匹配用过目标正常样本，不能当源域固定阈值保证 |
| S 的事件局部诊断 | E 附近 AUROC 0.446；X 附近 0.989 | 该统计量在此批更接近实质内容执行信号；是事后诊断，不证明所有路由表征都不含 E 信息 |

更晚的[可行性探索](../../claude/docs/research_v4/explore_v32_feasibility.md)发现，简单加入 G-session 多轮正常样本没有修好 FAR，目标批正常样本的场景互斥 cross-fit 才改善了实测工作点。它支持“正常参照匹配值得检验”，**不是证明可交换性，也不是无需新测试的修复方案**。

Claude 的[v3.2 设计说明](../../claude/docs/research_v4/v3_2_design_note.md)提出改用 X 相关时效及目标侧校准；该文件明确不是预注册。其事后 `[E,X+16]` 命中约 84% 不能写成 E+16 早检 84%，也不能把文本 X 称作已发生不可逆外部动作。本团队可研究这一方向，但不能将其继承为已确认结果；是否调整 E 的研究目标需要单独决策。

### 3. 当前最值得继承的机制线索

1. **支持集内变化值得优先研究。** 硬 unseen 不具有稳定充分性；简单边际/几何已解释一大部分历史检出。
2. **信号类型可能对应不同阶段。** 概率与硬专家选择、参与与实质执行不必同步；这是跨模型重新验证的核心问题。
3. **层深影响幅度与持续性，但没有万能层。** 旧逐层结果是小样本、事后线索，不能跨模型照抄层号。[逐层报告](agent_v2_layer_zoom_report.md)
4. **窗口可分、及时首报、低误报、正确恢复是四个不同问题。** 加强其中一项不自动解决其余三项。
5. **正常参照的语义与分布是算法的一部分。** 正常输入下的事实错误、自发偏离、合法复杂工作和模型/工作流变化必须明确处理。

仍未证明：普遍的参与前预警、可靠的抵御/恢复分类、路由超出强文本/隐藏状态的独立价值，以及跨大模型、跨环境的稳定增量。

## 四、论文的大致方向

### 1. 推荐主线：机制与能力边界为主，简单监测为验证

工作标题可以是：**What Do MoE Routes Reveal About Agent Task Drift?**（MoE 路由揭示了 Agent 任务偏移的什么信息？）

建议论文围绕三项贡献组织，均视为待完成的证据目标：

1. **行为阶段与路由信息的对应关系。** 分离输入暴露、E/C、X 与恢复，解释硬选择、概率和层深在不同阶段的表现，并给出反例。
2. **排除替代解释后的通用机制。** 通过授权、题材、实验标记、任务复杂度与正常转场对照，回答路由究竟读出了什么；不把相关热图命名为已证明的神经因果机制。
3. **简洁的在线实证。** 从机制选择一个主方法，在相同可见信息、误报和资源条件下，与文本、运行时和内部表征基线比较；报告可用区间、延迟、正常转移风险和成本。

若得到明确、可迁移的增量，再增强算法贡献；若只有 X 后内容变化稳定可检，就把论文收敛为这一边界。严谨的负结果有价值，但是否足以形成 ICLR 论文仍需看问题重要性、证据强度与文献差异，不能保证录用。

### 2. 文献差异必须先确认

“内部激活能检测任务偏移”和“专家与安全行为有关”已有邻近工作：TaskTracker 使用激活差分/探针研究任务偏移，SAFEx 研究安全相关专家，RASET 报告在其研究条件下路由较受题材驱动且安全行为可在路由变化较小时改变。[TaskTracker](https://github.com/microsoft/TaskTracker)、[SAFEx](https://proceedings.neurips.cc/paper_files/paper/2025/hash/bd127877149d4965ad834c75a65b3052-Abstract-Conference.html)、[RASET](https://arxiv.org/abs/2605.29708)

因此，不写“首次利用内部状态检测攻击”之类主张。A 主责最新相关工作矩阵，B 复核基线可比性，重点检查正常参考、在线 token 时序、暴露与行为分离、强模型和成本。这些来源是定位起点，不是穷尽性新颖性审查；他人的暴露分类结果也不能直接当作我们的 E/X 检测成绩。

## 五、未来两位研究员的分工建议

### 1. 主责安排

| 人员 | 实质责任 | GPU 与代码工作 | 必交付物 |
|---|---|---|---|
| **研究员 A：数据与机制负责人** | 问题操作化、任务/模型资格、数据生产、行为标注与机制解释 | 主大模型接入与捕获；配对机制批、自然长任务与外源工作负载；维护数据 schema | 数据卡/哈希清单、标注协议与人类复核、机制实验报告、反例、相关工作与机制/数据章节 |
| **研究员 B：算法与实证负责人，日常整合人** | 统一 evaluator、强基线、有限候选、统计分析、跨模型实证和论文整合 | 先复用旧缓存验证评价；并行接入第二架构；维护 scorer、独立表格复算与成本测试 | 算法预注册、主结果表、跨模型与成本报告、复现包、论文主稿与进度摘要 |
| **主管：review 与独立探索** | 研究范围、关键主张、资源/投稿决策；提出独立反证或候选机制 | 独立探索不占主线必需实验名额，不承担日常采集、代码维护或合稿 | 阶段评审意见、方向取舍、需要时的独立探索备忘录 |

A/B 按实际专长可以互换。两人的角色都包含研究判断和写作，不把 A 固定为数据工程支持，也不让 B 只负责最终评分。B 的日常整合职责不意味着作者顺序。

### 2. A 的首批问题与交付

1. **模型与任务是否合格？** 用固定小批检查合法任务质量、自然长度、工具事件、路由完整性和可观测行为，不以攻击成功率高低决定模型是否值得研究。
2. **实验设置是否制造信号？** 对模型可见实验记账字段/显式输出标记做有无配对；不把标注包脱敏误认为模型输入已经脱敏。
3. **路由区分的是授权还是题材？** 构建以下四格，并保持任务难度与表面内容尽量可比较：

   | | 题材基本不变 | 题材发生变化 |
   |---|---|---|
   | 获授权 | 常规任务/合法复杂步骤 | 合法的新请求或任务阶段切换 |
   | 未获授权 | 同域目标/权限偏离 | 现有典型跨领域注入 |

   四格不是同一 E 标签：先按授权范围标行为，再观察路由。尤其不能预先把“同域违规”判为无任务偏移，也不能把合法换题自动设为阳性。

4. **哪种信息对应哪个时段？** 对同一固定样本比较 top-k 选择、权重/概率、固定相对层段、边际/跨层与非重叠时间信息；多 seed 全部保留。
5. **跨题材对照后还有什么？** 交付一个明确的正机制结论或可重复的失败边界，附原文证据和替代解释。读出打乱只称表征消融；真实模型干预若开展，另预注册并加入随机/等规模干预及能力损伤控制，只用无害沙箱任务。

### 3. B 的首批问题与交付

1. **先重现，不先改进。** 在自己的环境从共同冻结缓存复现 Astra 主表和 G v3.1 指定开发主格，记录原协议差异，不把两表强行合并。
2. **建立同一 evaluator。** 固定事件、分母、时间轴、校准单位和输出字段；A 的机制图也使用这个事件映射。单元测试包含前缀不变性、token 对齐、不可达工作点、经验秩饱和及恢复/历史报警分离。
3. **保留很少的正式候选。** 起步用边际/稀有统计、逐坐标距离、正常 kNN 做固定基线；根据 A 的开发证据选择最多两个正式候选，最终冻结一个主方法。复杂联合、时间或融合模块必须证明同预算增量。
4. **承担强基线。** 同可见前缀的文本语义检测器、因果运行时元数据、固定隐藏状态/激活差分对照；正常单类方法与使用攻击标签训练的 probe 分开记账。路由加文本/运行时的融合规则只在开发集确定。
5. **独立环境验证与主稿。** 在第二模型上使用相同算法形式、重新建立该模型的正常参考；复算 A 的至少一个关键机制结果；负责统一图表、运行成本、附录与完整初稿。

### 4. 不让主管变成日常阻塞点

- A/B 每周直接同步两次；交付的是完整结果包，不只是等待主管批示的想法列表。
- 主管建议每周一次 45–60 分钟证据评审：会前收到两页内摘要，列新增结论、关键反例、可信度、成本及最多两项待决策事项；时间可按实际安排调整。
- 已认领范围内的实现、排错与预声明分析由 A/B 自主完成；涉及解封、换主问题、显著扩预算或外部共享才升级审批。审批未到时继续不依赖该决定的工作，不默认获得权限。
- 主管独立探索用另一个记录/开发数据区。新想法若进入主线，须在下一次冻结前登记；不得在看过确认结果后加入主比较，且记下主管与辅助 AI 的数据暴露。
- 论文写作自第一周开始：A 写机制/数据/相关工作，B 写方法/评测并合稿；主管 review，不作为初稿作者的唯一来源。

## 六、更大 GPU 应怎样转化为有效证据

### 1. 模型矩阵建议

保留 GPT-OSS-20B 为历史桥接参考，选择一个任务能力可靠的较大 MoE 作为主模型 L1，再选不同路由架构/模型家族的 MoE L2 做共同任务验证。L1/L2 的具体 checkpoint 由显存、推理栈、捕获可得性、任务质量与实际吞吐共同决定；本文不在未知硬件上承诺某个模型能运行。

优先矩阵为 **L1 × 原任务与一个外源工作负载，L2 × 公共任务子集**。同家族大小对照有价值，但优先级低于完整的主证据链；不同家族的差异不能单独归因为参数规模。更大模型也可能更少发生偏移或表现出更弱的路由信号，这本身是结果，不按信号强弱淘汰模型。

A 主责 L1 数据与机制，B 主责 L2 和检测实证；共享模型适配器与场景清单，避免各自搭一个不兼容的 Agent。B 在 A 新数据准备时先做缓存复现和基线，不串行等待。

### 2. 先过捕获与成本门

- 首轮 48 小时做固定工程探针，交付显存、稳定吞吐、最长正常上下文、路由可得性和任务质量；仍无法稳定运行的配置转为备选，不无限修内核。
- 多 GPU 捕获核对全局专家编号、完整层集合、共享专家、top-k 权重是否重归一化、路由 logits/概率的真实语义；不同模型的同名字段不能默认相同。
- 在固定机制小批保留完整路由概率/必要内部表征；主批的捕获字段在生成前确定。若概率成为主候选，就要对正式 fit/cal/test 全部采集，不能只有挑出的异常有完整特征。
- 允许较长自然输出，记录自然结束与预算删失，不设强制最小长度、不填充。视界与正常校准覆盖一同设计；显存增加不消除长路径的重复检验问题。
- 分别测“无监测”“轻量在线监测”“完整研究日志”三种条件，记录 p50/p95 延迟、吞吐、显存、CPU 内存与参考库大小；离线 scorer 很快不等于线上开销很低。
- 总预算包含生成、标注、储存、传输和复现。大模型条件下，人类标注与路由日志体积可能先成为瓶颈，不能只统计 GPU 小时。

## 七、共同实验规则与阶段安排

### 1. 两人共用的最小规则

1. **输入来源、可见行为、任务质量分轴。** 不删除困难正常或静默攻击来改善分数；正常输入报警率与行为事件识别分别报告。
2. **严格在线。** 检测只看可用前缀；路由 token 的处理时刻不等于该 token 生成前。文本与路由使用同等通道可见性，若可见性不同则明确为部署设置差异。
3. **E 与 X 不互相替换。** 报 E+16 严格首次命中、pre-E、首次报警相对 X 的分布；若另设 `[E,X+16]` 指标，单列定义。保留全部预定义正例分母及可达性诊断，不只报有窗口的成功机会。
4. **场景级隔离。** 同场景的多臂、多 seed、多轮绑定到同一数据角色；模板/家族共享另记。fit、cal、dev、最终 test 分开；开发集 cross-fit 是开发证据，不会自动恢复盲态。
5. **固定工作点。** 主阈值来自独立正常校准；目标侧正常校准若是部署假设，提前划独立场景/时间段，再评估后续测试，另报不重校准的转移压力测试。低实测 FAR 不是可交换性证明。
6. **统计与长度。** 明确 episode/会话/分组 FAR、各层分母和不确定性，不能把滑窗当独立样本。研究主工作点可先 alpha=.10，另报 .05 与曲线；不据此承诺低于 1% 的生产误报。
7. **有限选择与一次确认。** 精确场景、seed、主要对比、效应目标、样本数/精度、预算、停止规则在新正式批运行前冻结。失败不通过换 seed、换锚点或换阈值改写为成功。
8. **标注可信度。** 两位研究员先对固定校准样本独立标注再解决分歧；正式批设随机、分层的人类复核与重要边界审读。既有 AI 双标不等于人类金标准，记录真实标注来源与验证范围。

### 2. 独立确认如何在两人执行模式下完成

建议新建团队确认批；A 负责按冻结清单生产与保管，机制探索只用 dev，B 在方法冻结前不看 test 的路由分布或检测结果。A 做确认标签验收时也不看检测分数；若 A 已将测试路由用于机制选择，该批必须降级，不能因 B 没看过就称全团队未见。

方法、标签、阈值规则和主比较锁定后，由 A 执行冻结 runner，B 用独立计算路径核对主表。两人都参与过研究，因此准确称“独立数据验证＋跨环境复现”，不冒称外部独立第三方验证。主管无须承担日常保管工作，但解封需按预先约定授权。

不读取 G-conf/B3 来判断哪个新计划更有希望。若确需共享 Claude 的确认资产，须先与原研究线明确协议、访问历史和比较范围；复制代码不等于获得测试集使用权。

### 3. 建议完整周期：六周核心工作，必要时加两周

这是待资源确认的排程，不是已经承诺的截止。

| 阶段 | A 的交付 | B 的交付 | 主管 review 的问题 |
|---|---|---|---|
| 第 1 周：接手与资格 | 数据卡、标注校准、L1/任务小批、邻近工作矩阵 | 旧缓存主表复现、统一 evaluator、L2 捕获探针、文稿骨架 | 我们测量的事件是否清楚？两套环境能否可靠执行？ |
| 第 2 周：机制核心 | 去标记/记账字段、授权×题材对照、E/X 分段结果 | 固定简单基线、文本/运行时/内部表征基线、初始成本 | 信号是否超出实验设置和题材解释？主问题是否值得保留？ |
| 第 3–4 周：外推与收敛 | L1 外源任务、固定多 seed、长正常/恢复子集、机制章节 | L2 公共任务、有限候选增量、误报—延迟分析、初稿 | 哪项主张有跨条件证据？正式确认的主比较是什么？ |
| 第 5 周：冻结验证 | 封存批标签验收、执行冻结实验 | 独立复算、最终成本与主表 | 结果能否在未见数据上成立？负结果是否原样保留？ |
| 第 6 周：论文交付 | 机制与数据限制复核 | 合稿、引用/数字一致性、匿名复现材料 | 主张是否超出证据？是否达到投稿质量？ |
| 可选第 7–8 周 | 只补已明确缺口，如真实多轮或人类标注精度 | 对应复验和文稿完善，不无限增加候选 | 额外实验是否会实质改变主要结论？ |

若仍明确冲 ICLR 2027，官方摘要/全文截止分别为 **2026-09-18 / 2026-09-25，23:59 AoE**。上述完整周期无法在该截止前完成；需在第 1 周 review 时单独决定是否用已有可信证据收缩本届范围，或保留完整研究周期，不默认压缩验证。[官方 CFP](https://iclr.cc/Conferences/2027/CallForPapers)

## 八、补充建议：比再增加几个算法更值得投入的事项

1. **把“授权边界与题材变化能否分开”设为机制优先问题。** 它决定论文是在研究任务完整性，还是仅在研究生成内容分类；两种结果都应诚实命名。
2. **外源环境先接一个。** AgentDojo 提供已有的 agent 注入攻防环境，可作为候选公共任务来源；具体选哪个套件先做能力与捕获资格测试。外部任务/文本不直接提供目标模型的路由，仍需本地重跑与行为标注。先形成可审计子集，不同时重建多个 benchmark。[官方项目](https://github.com/ethz-spylab/agentdojo)
3. **强基线第一周启动，第二周形成完整结果。** B 第一周交付比较协议和最小可运行版本，尤其检查激活差分/隐藏状态与因果文本语义；若路由没有增量，及时转向机制边界，而不是继续叠检测头。
4. **主管只收“主张—证据—反例—决定”摘要。** 每个数值附分母、协议版本、开发/确认身份和复现入口；零误报也必须说明样本量，显著性也必须说明效应量。
5. **建立停止清单。** 未有新证据时，不继续硬 unseen、重叠窗口重复持续性、有限秩封顶后再做路径最大值；FHTS/NTR 则是数据支持不足，可在资格满足后新注册，不混为机制否定。
6. **数据权利、代码归属和贡献记录第一周说清。** 各自工作区/分支独立；Claude 有用部分经允许复制到本线再改，记录来源。对外包只含获授权内容，附代码/模型/数据/标签 hashes、环境与复现命令；任何人的辅助 AI 都遵守相同盲态与数据边界。

启动只需认领三件事：A/B 的实际负责人和可投入时间；两套 GPU/内存/磁盘配置；第 1 周验收的具体日期。算法实现、完整数据生产和论文主稿由 A/B 交付，主管保留 review 与独立探索的位置。

内部链接用于溯源；外部研究员的正式交接包应包含经授权的只读材料副本或可访问仓库。本轮只新增本文，没有发送材料、启动 GPU 任务、修改旧协议或解封数据。
