## 1. 假设与 estimand

**假设（§3.1）**：routine 客服工作的 w-token 专家使用向量（每层每专家的 top-8 入选率）落在专家使用空间的
一个低维、可由少数 routine 样本估计的区域内；任务偏移使该向量沿 routine 中从未出现的方向离开该区域。
最简单的静态几何（白化距离 / 低秩残差能量 / kNN 距离）就足以给出及时、可校准的离开分数。

**estimand（§3.2）**：时刻 t 的分数回答"最近 w 个 decode token 的专家使用，距离本业务 routine 使用区域
有多远"。只用 decode token ≤ t 的路由与离线 routine 统计量，因果、可部署。

**实现**：`src/research_v2/scorers/wgm.py`（注册名 `wgm`），三种度量 `g1` / `g2` / `g3` 加三个设计轴
（层带、窗口宽度、中心条件化）与 `sqrt` 变换。拟合只接收 harness 按 routine 定义筛好的 trace；
推理只用 `top_k_ids` 与（仅 C10）`workflow`。单元测试 `tests/test_research_v2_wgm.py`（19 个，0.7 秒），
其中 `test_g1_matches_harness_reference_scorer` 断言 C1 与 harness 内置 `g1_whitened_distance` 逐元素相等；
主表也确实与 harness 报告 §5.1 的 G1 行逐格相同（见 §4 首段）。

## 15. 主要发现（只陈述事实）

1. **C1（主配置）在两个方向都超过文本基线 T2 与 T1(full)**：容差 +16 增量 +0.143 / +0.167（对 T2）、
   +0.200 / +0.500（对 T1(full)），中位 latency 10.5 / 8.0 对 18.5 / 13.0。**判据 4 未触发。**
2. **及时性仍是主要短板**：B1→B2 的 +8 = 0.286、+16 = 0.486、latency 10.5，**判据 1 触发**；
   §6.1 的 17 项门槛只有 7 项两方向同时达到。
3. **routine 的窗口几何不是低维的**：留出重构误差在 r ∈ [1, 128] 上平滑衰减（每翻倍降 17–21%），
   预注册的拐点规则在两个方向、两个层带、8 个 LODO 拟合侧全部退到 r\*=16。**判据 5 触发。**
   低秩残差（C3/C4）在报警层面与 G1 同级或略好，但它**不是**因为低维假设成立。
4. **层带 5–15（middle_late）在 R8/R16 上一致优于 5–11**（C2、C4、C6），FAR 相当。预注册把 5–11
   写死为主配置，因此这只能作为消融记录，不能改判主配置。
5. **G3（kNN）的尺度完全不跨 batch 迁移**（模式 T FAR 0.417–0.673），而 G1 / G2(r≤16) 可以
   （0.102–0.240）。**G2 在 r=32 的模式 T FAR 升到 0.254**，复现了 §2 E19 的秩敏感崩溃——
   但只在跨 batch 绝对阈值下可见，部署侧校准会掩盖它。
6. **resist 臂是最难的负例**：B2→B1 的 resist FAR 0.250（clean 0.075），R+ 定义（C9）**不能**改善；
   排序诊断上 `resist vs clean` 在全部 24 行都 > 0.5。扩大校准池（§12.2）能把它压到 0.125。
7. **失败集中在 programming 与结构化输出**：8 条完全无报警的 drift 中 5 条是代码（SQL/JS/Rust），
   S3 的 programming 域三个候选都是 R16 = 0；LODO 合并容差 +16 = 0.441，差 §6.1 的 0.45 线 0.009。
8. **边界前报警多数是"正确的早"**：C1 的 7 个严格 pre-onset 报警中 5 个是标签/预告句，
   (c)(d) 类只有 2 个（每方向各 1 条 trace，率 0.034 / 0.056）。
9. **B2→B1 的运行点由校准样本量主导**：40 → 80 条校准 trace 把 FAR 从 0.125 降到 0.094、
   resist 从 0.250 降到 0.125。
10. **规范 §1.1 关于 B1 `brief=present` 的说法与数据不符**（40 条 attack 臂中 3 条 drift），
    见 §12.2 的执行偏离。
