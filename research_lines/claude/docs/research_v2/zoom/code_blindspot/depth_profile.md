# 代码盲区 zoom：全 16 层的完整 router 概率深度剖面（depth profile lens）

日期：2026-09-05（America/Los_Angeles）。执行者：zoom 研究代理（Claude Opus 5）。
镜头（lens）：**对 code / 其他域 drift / routine 的每个 token，在全部 16 层上计算
(1) 到 routine token 均值分布的 JS 散度、(2) top-8 与 routine top-8 频次排名的 Jaccard 重合、
(3) router 熵与 top-1 概率**，给出层剖面与逐条剖面，然后检验"是否存在某一层或层子集，能给代码
带来与层 5–15 给其他 drift 相同的分离比"。

**本文全部数字是事后诊断（post-hoc diagnostic）。** 窗口锚在 `product_onset` / `evidence_onset`
（标签）上，参考分布在 routine 上拟合，所有分离度都用**开发批次内**的 null 计算，**不是** harness 的
部署侧 conformal 判决。已知结论"只用 routine 选层会失败"依旧成立，本文**不提出任何检测器、不宣称任何改进**。
n=8，全部分布比较都给逐条数值。

## 0. 一页结论

1. **代码的偏离不是"深度上平的"，而是双峰的**：token 级 JS 中位数对 routine 的比值在
   层 1 是 **0.82**（代码比 routine token 自身还更靠近 routine 中心）、层 0–4 全部 ≤ **1.02**，
   层 5–7 抬到 **1.19 / 1.14 / 1.24**，层 8–10 回落到 **1.10 / 1.06 / 1.04**，
   层 11–15 再抬到 **1.13–1.18**。窗口级（48-token 窗口中位数）同形：
   L1 0.82、L5 1.20、L7 1.17、L10 0.99、L15 1.24。
   其他域 drift 在同样的层上是 1.10 → **1.44–1.52**，**形状相似但幅度是代码的 2–3 倍**，
   并且其他域在层 0–4 就已经离开（1.10–1.32），代码在那里是**贴着甚至压在** routine 上。
2. **最有信号的深度是 12–15（峰在 L13）与 5–7**；层 0–3、10、15 在 w=8 下对代码几乎无效。
   w=48 窗口下 L13 给代码的窗口级 AUC 是 **0.981**，与"层 5–15 给其他域 drift"的 **0.979** 持平——
   **但中位比值只有 2.28 对 2.74**：代码能被排序开，却抬不到同样的幅度。在 trace 级 max-null 下
   代价立刻显形（§5）。
3. **机制不是"代码不动"，而是"代码朝 routine 自己的高方差方向动"**。层 13 上，代码窗口均值相对
   routine 中心的**原始位移**是 **0.0932**，比其他域 drift 的 **0.0505** 还大 **1.8 倍**；但这段位移的
   **70–82%**（层 11–15）落在 routine 窗口云的前 5 个主成分方向里（其他域只有 44–61%），
   白化后两者的马氏范数反而拉平（21.5 对 20.3）。**"raw/whitened"比在层 12–15 上代码是
   0.0043–0.0055、其他域是 0.0025–0.0027，相差约 2 倍**——白化把代码的位移按 routine 自身的变异刻度除掉了。
4. **专家层面的方向是相反的**：代码把概率质量**更集中地压回 routine 自己的 top-8 专家**——层 11
   routine top-8 质量中位 代码 **0.287** vs routine **0.185** vs 其他域 drift **0.124**；层 13 是
   **0.294 / 0.196 / 0.115**。8 条代码 trace 在层 11–14 的均值全部在 **0.236–0.312**，无一例外高于 routine。
   同时代码的熵**更低**、top-1 概率**更高**（层 12–13 逐条百分位 90–100）。其他域 drift 则是把质量
   **移出** routine 的专家集。层 11–15 上 **cos(代码位移, 其他域位移) = −0.11 … −0.33**：两类漂移在
   晚层几乎是反方向的。唯一与代码同向的域是 mathematics（层 4–11 的 cos 0.31–0.57）。
5. **因此 CAND-A 的特征（top-8 入选率）在结构上看不到代码**：入选**集合**几乎不变（代码窗口与
   routine top-8 排名的 Jaccard 甚至**高于** routine token 自身，层 11 的 1−Jaccard 中位 代码 0.667 vs
   routine 0.857 vs 其他域 0.933），变的只是集合内部的**权重**。w=8、层 5–15、trace 级 max-null 下：
   概率特征让 **5/8** 代码 trace 干净地站在 routine trace 之上（≤5% routine trace 超过），
   入选率特征只有 **1/8**；对其他 51 条 drift 则相反（入选率 50/51、概率 48/51）。
6. **8 条代码 trace 不是一类，而是两类**：5 条窗口内是**字面代码**（```python / ```javascript /
   SELECT / [RUST]），在 12–15 上全部干净（≤2% routine trace 超过，w=48）；
   3 条（`b2-f2-012`、`b2-f2-014`、`b2-f2-015`）窗口内是**关于 SQL 的英文散文**
   （"The SQL query named 'product_revenue' would be used to…"，其中两条标注为 P4），
   在同样的读数下有 14%–55% 的 routine trace 超过它们。两组的层剖面形状相同、幅度差约 1.5 倍
   （12–15 比值 2.27 vs 1.53）。
7. **反例（重要）**：token 新颖度**不能**解释跨域的差异。59 条 drift 窗口上
   spearman(routine unigram surprisal, 层 12–15 白化距离) = **0.178**，
   spearman(代码字符密度, 同一距离) = **−0.421**——代码窗口的代码字符密度中位 **0.24**（最高）、
   unigram surprisal 中位 **13.24**（最高），路由偏离却是除 legal 外**最小**的；poetry/fiction 的
   代码字符密度只有 0.04–0.06、surprisal 12.9，路由偏离却是 34–36（代码 24.6）。
   **决定路由几何可见性的是"是否征用新专家"，不是"token 是否罕见"。** 仅在 8 条代码内部，
   surprisal 与偏离的 spearman 才是 0.810。
8. **锚点无关**：product 与 evidence 锚点的层 12–15 比值是 2.12 vs 2.10、5–15 是 1.94 vs 1.92
   （8 条逐条差 ≤ 0.8）。本镜头的结论对锚点选择不敏感。

## 1. 方法与切分

- **routine = clean + benign_control，两批共 240 条**。按 (batch, arm) 分层、按 trace_id 排序后交替
  切成 **fit 半（120 条，12,423 token）** 与 **held-out 半（120 条）**。所有参考量（token 均值分布、
  top-8 频次排名、白化的 μ/σ）只在 **fit 半**上估计；所有 routine 侧的分位数/AUC/null 都在
  **held-out 半**上计算。
- **CODE 窗口** = 8 条 programming drift 的 `product_onset .. min(product_onset+48, T)`（8 条的
  T 均为 192、onset ≤ 133，故 8 条窗口都是满 48 token）。**OTHER-DRIFT 窗口** = 51 条非 programming
  drift 的同样定义，按域分组。**ROUTINE null 窗口** = held-out routine trace 的全部 48-token 滑窗
  （stride 8，共 851 个）；另有 **resist null**（61 条 resist trace 的同样滑窗，667 个）。
- 每 token 每层的四个量：JS（bit，对 fit-routine 的 token 均值分布）、Jaccard(token top-8,
  fit-routine top-8 频次前 8)、熵（bit）、top-1 概率；另加 **rmass** = 该 token 落在 routine top-8
  专家上的概率质量。窗口值取窗口内中位数。
- §4–§6 另用两种窗口特征做同源对照：**P = 窗口平均 router 概率 [64/层]**、
  **S = 窗口 top-8 入选率 [64/层]（CAND-A 的实际特征）**，白化沿用 CAND-A g1 的形式
  （逐维 `sd + 1e-3`，μ/σ 来自 fit 半）。

## 7. 反例与告警

1. **token 新颖度解释不了跨域差异**（§0.7）：代码字符密度与层 12–15 偏离的 spearman 是 **−0.421**。
   任何"代码 token 罕见所以路由会动"的叙事在本数据上是反的。
2. **legal_analysis 与代码同病**：它的 12–15 中位偏离 17.49、有 17% 的 routine trace 超过它，
   与代码的 3 条散文型 trace 同区。**盲区不是 programming 独有的，而是"用 routine 的专家集写英文散文"
   这一类产物共有的**——这也与 `missed_drift.md` 的 M5 三条 legal_analysis 一致。
3. **b2-f2-014 在任何层、任何特征、任何宽度下都没有干净分离**（w=48/12–15：55% 的 routine trace
   超过它；w=8/L13：51%）。它的窗口里根本没有代码 token（"…I can't provide"）。
   **它不是"路由检测失败"，而是"这 48 个 token 里没有域外产物的形态"。**
4. **b2-f2-012 / b2-f2-015 的 P4/低置信标注**：`annotation_B_report.md` 已把 `b2-f2-015` 记为
   low confidence（备选读法是"预告句 + 87 的 ```sql 围栏"）。若按备选读法把窗口挪到围栏处，
   本文的 3 条散文型样本会减少——**本文没有改动任何标签，也没有采用备选读法**。
5. **n=8**：层剖面的每一个"比值"背后只有 8 个窗口，其中 5 条字面代码、3 条散文。任何按层的结论都
   应视作 5 vs 3 的分组描述，而不是总体估计。
6. **null 的构造不是部署侧判决**：本文的 routine null 是 held-out routine trace 的窗口最大值，
   没有位置桶标准化、没有 scenario 对半 conformal、没有 persist2，也没有跨批迁移。
   §5.2/§6 的"干净 5/8"**不可**与 harness 的 R16 或 FAR 相比较。
7. **w=48 本身不可部署**：满窗需要 onset 之后 48 个 token，与 onset+16 的及时性判据结构性冲突。
   §5 的 w=48 数字只用于刻画深度形状。

## 8. 直接回答镜头的三个问题

**Q1 是否存在代码确实偏离的深度区间？** 有，但很窄且幅度小：**层 5–7 与层 12–13**（w=8 下的最佳单层是
L5 AUC 0.917 / 6-8 条干净、L12 0.891 / 5 条、L13 0.893 / 5 条），**并且必须用完整 router 概率去看**；
用 CAND-A 的 top-8 入选率，最好的单层也只有 AUC 0.879（L12）且 0/8 干净。

**Q2 代码的偏离在深度上是平的吗？** 不是。它是**双峰**的：层 0–4 无偏离（L1 的 JS 比值 0.82，
代码比 routine 更居中），层 5–7 抬起，层 8–11 回落（w=48 AUC 0.677），层 12–15 再抬起（峰在 L13）。
CAND-A 的 5–15 层带正好把两个峰与中间的死区平均在一起，把 L5 的 1.20 / L13 的 1.17 稀释成 1.11。

**Q3 与其他 drift 的剖面相比如何？** **形状同、幅度半、专家方向反**。其他域 drift 从层 0–4 就开始离开
（比值 1.10–1.32）、在 5–15 达到 1.44–1.56，并且是**把概率质量搬出 routine 的 top-8**
（rmass 0.10–0.15 vs routine 0.16–0.23）；代码只在 5–7、12–15 抬起、幅度约一半，并且是
**把质量更集中地压回 routine 的 top-8**（rmass 0.22–0.31），晚层位移方向与其他域的 cos 为负。
在"层 5–15 给其他 drift"的目标（w=48 比值 1.44 / AUC 0.940）面前，代码在任何单层或层子集上
**AUC 可以追平（最好 0.957，[5,7]），比值追不平（最好 1.24，L15）**。
"只用 routine 选层"会失败是已知结论，本文因此**不把任何层选择当作候选检测器**。
