# 完备性批评（CRITIC）：代码/SQL 盲区这一轮的存活解释、矛盾与缺口

日期：2026-09-05（America/Los_Angeles）。角色：completeness critic（不跑新实验，只读 6 份透镜报告 + 5 份反驳）。
被审材料：`nn_geometry.md`、`whitening_lens.md`、`token_identity.md`、`joint_vs_marginal.md`、`pertoken_code.md`、
`depth_profile.md`（**第 6 份透镜，没有任何反驳者复核过**），以及 5 份 `refute_*.md`。

**性质声明**：本文只做交叉比对与记账，**没有跑任何新实验、没有重算任何数字**；所有引用数字都注明来源文件。
全部被引材料都是 B1/B2 上的事后诊断（用了 `product_onset` / `domain` 标签），**没有一条是检测结果，本文也不宣称任何改进**。
n = 8（b1 三条、b2 五条），其中 2 条（`b2-f2-014`、`b2-f2-015`，均为 P4）在 `onset..+48` 窗口内**没有代码**，
另 1 条（`b2-f2-012`）窗口前半是散文——**任何"代码正文机制"的有效 n 是 5–6，不是 8**。本文所有排名都按此打折。

## 0. 一页总账

- 6 份透镜里，**只有 1 份（`whitening_lens`）被反驳者判为 refuted=false**；3 份 refuted=true（high）、1 份 refuted=true（medium）；
  `depth_profile` **无人复核**。
- 但四份"被反驳"的报告里，**被推翻的几乎全是因果措辞，不是算术**：5 位反驳者全部独立复算了承重数字，
  最大不一致是 `refute_nn` 的"逐位一致"、`refute_whitening` 的 9.77e-4（float32 舍入）、
  `refute_pertoken` 的 5.3e-07（float64 vs float32）。**这一轮没有发现任何计算错误。**
- 收敛点只有一个，而且非常硬：**CAND-A 的分离力 = "点亮 routine 几乎不用的专家"，代码不做这件事**。
  四个互相独立的镜头（白化十分位、token-id 子空间、逐层边缘未见率、routine-top8 概率质量）在两个 batch、
  逐条 8/8 上给出同一结论，两位反驳者反而**加强**了它。
- 唯一给出"代码在做什么"（而不是"代码没做什么"）的机制来自**无人复核的 `depth_profile`**：
  代码把概率质量**更集中地压回 routine 自己的 top-8 专家**（rmass 0.236–0.312 vs 配对 drift 0.070–0.168，
  routine 中位 0.195，**8/8**），熵更低、top-1 概率更高，晚层位移方向与其他域 drift **反号**（cos −0.11…−0.33）。
  **这条是本轮最重要、也是最未经检验的一条。**
- 最大的空缺不是机制，是**与冻结检测器的连接**：只有 `refute_nn` §6 做了这个拼接，结论是
  "分数落在 routine 散布内"对 CAND-A 的漏检**既不充分也不必要**（`b1-f0-026` g1 1361.5 被干净检出，
  `b1-f1-032` g1 7059.4 未检出；秩逆序 12/135 与 94/294）。**没有任何一份报告解释了 8 条代码 trace 各自为什么没报警。**

## 1. 存活的机制性解释（按证据强度排序）

强度评级口径：①独立镜头数；②是否被反驳者留下；③是否有逐条 8/8（或注明 n=5/6）；④是否跨 batch / 跨锚点 / 跨参照稳；⑤是否被"其他域也这样"证伪。

### E1（最强）CAND-A 度量的是"征用陌生专家"，代码只重排熟专家——所以它在这套度量里几乎无分可得

- **支持**：`whitening_lens` §3（白化能量落在最低方差十分位：other-drift 0.786/0.773 vs code 0.196/0.134；
  冷门专家占用率 τ=0.02：routine 0.0067/0.0078、programming 0.0142/0.0084 = 8 域最低，
  **逐条 0.0072/0.0215/0.0123/0.0055/0.0044/0.0058/0.0040/0.0063**）；
  `joint_vs_marginal` 表 R（逐层边缘未见率 code 29.8× vs other 116.9×，逐条 .008/.025/.007/.011/.002/.000/.000/.014）；
  `token_identity` 的**反驳者** §2（最低方差十分位子空间：code 1.57× vs gk 193×/fiction 148×/poetry 124×/math 37×/cooking 26×/travel 19.5×/legal 19.4×）；
  `depth_profile` §2（1−Jaccard：code 在 L11/L13 是 0.667，**比 routine token 自身的 0.769–0.857 还低**，other-drift 全 16 层 0.857–0.933）。
- **反驳者判决**：`refute_whitening` **refuted=false 并加强**——decile-0 之外 8 个域全部落在 1.29–2.13 的窄带里
  （programming 1.29、legal 1.33、travel 1.57），域间 5–20 倍的差距 100% 来自那 70 个坐标；
  `corr(whtAUC, log d0/rtn) = 0.716/0.787`。`refute_tokenid` **独立得到同一结论并用它反驳了原透镜的因果叙事**。
  `refute_joint` 精确复现 29.84×/116.88×。
- **强度：strong**。四镜头 × 两 batch × 逐条，两位反驳者加强，锚点/窗口/in-sample-vs-held-out 不敏感。
- **必须记的代价（反驳者自己写的）**：这**不是 programming 专属**，而是一条连续谱——travel_planning（d0/rtn 17.3、GAIN 1.63、AUC 0.862）
  就在中间，`b1-f1-058`（travel，P3）GAIN 0.97 落进代码区间。**"gain≈1 是代码签名"不成立。**

### E2（强，但无人复核）代码把概率质量**压回** routine 自己的专家：方向与其他 drift 反号

- **支持**：`depth_profile` §2/§3/§9——routine top-8 概率质量 rmass 逐条中位在 L11 全部落在 **94–100 百分位**
  （.30/.29/.33/.29/.26/.25/.30/.31，routine 中位 .18，other-drift .10）；L13 熵 4.82–5.19（百分位 0/0/0/0/1/9/1/0，routine 中位 5.31）；
  top-1 概率百分位 99/100/100/100/98/52/91/100；**8/8 对配对 drift 的 rmass 更高**（code .236–.312 vs pair .070–.168）；
  层 11–15 上 `cos(code 位移, other-drift 位移) = −0.11…−0.33`。
  旁证：`token_identity` §4.1（code 的上下文残差与 other-drift 残差 cos = **−0.041**，近乎正交，相干度 0.460 vs routine 0.027）；
  `whitening_lens` §2（代码 top-10 偏离坐标的 `mean raw` **全为正**：把 routine 高频专家用得更多）。
- **反驳者判决：无**。`depth_profile` 不在本轮的 5 份反驳名单里。**这是本轮最大的流程缺口**：
  唯一一条"代码在做什么"的正向机制、唯一一条能解释 E1（为什么冷门专家不亮）的上游机制，没有被任何人攻击过。
- **强度：strong-unrefuted**（= 证据形态强，可信度未经对抗检验）。逐条 8/8、两 batch、锚点差 ≤0.8。
- **未检项**：跨 batch 迁移、部署侧 conformal/FAR、以及"是否 routine 自己的工具调用 JSON 窗口也这样"（见 §3 缺口 6）。

### E3（强）盲区是"幅度不足 + 迟到"，不是"没有信号"——但只在 CAND-B / 聚合后成立

- **支持**：`refute_pertoken` §4（CAND-A 逐条 AUC 随窗宽单调上升 0.534→0.621→0.702→**0.751**，
  w=4/8 时 **8/8 高于 routine 中位、位置桶配对后仍 8/8，p=0.0078**；trace 内配对：CAND-B w=4 上 **6/6** 相对自身 onset 前正文为正台阶 +0.13…+0.58，
  配对对照是 +0.59…+0.93）；`refute_pertoken` §2（冻结 CAND-B w=4 persist2：**6/8 全程越界、5/8 窗口内**，窗口内最长游程 9/4/3/2/2，
  冻结 `trace_alarms` 报警段 10/5/4/4/2/1）；`joint_vs_marginal` §5 + `refute_joint` §5.4（效应量 0.94 vs 其他域 2.24 routine-sd；
  48 token 内 8/8 越线、`+16` 内只有 3/8；冻结首报警 +5/−8/无/+22/+18/无/+17/+70）。
- **反驳者判决**：`refute_pertoken` **refuted=true (high)**，专门推翻的就是原透镜"从不产生持续偏移""盲区不在时间轴上"的措辞。
- **强度：strong**，但**必须按候选分开写**：CAND-A 侧原透镜的核心事实全部成立（w=1 pooled 越界 2/384 = 0.0052 vs 对照 173/384，
  唯一两次窗口内越界是 Python docstring 的英文词），CAND-B 侧则明确有持续偏移、只是晚且小。
- **注意**：这条与 E1 不冲突而是互补——E1 说"为什么幅度小"，E3 说"小到什么程度、什么时候到"。

### E4（中强）代码的逐层边缘完全不动，而跨层联合被打破的程度与所有 drift 相同

- **支持**：`joint_vs_marginal` §1–§4 与 `refute_joint` §1 的逐条复现（g1 窗口中位 1.60× routine，逐条 1.78/2.11/1.95/1.41/1.32/1.21/1.04/1.78；
  边缘 surprisal 1.06×；6/8 条**零窗口**越过 routine 的 (1−0.0211) 分位；相邻层 top-1 对未见率 7.29×，逐条 9.41/11.25/6.88/7.70/5.69/3.29/5.36/9.87，8/8 高于 routine）。
- **反驳者判决**：`refute_joint` **refuted=true (medium-high)**，但保留的正是这条描述，并给出正确表述：
  **"所有 drift 都同等程度打破跨层联合（独立性零模型下 code 9.53× vs other 10.01×，51/51 其他 drift ≥ 代码最小值）；
  代码的特殊之处是它同时几乎不动边缘（1.60× vs 6.35×）。"**
- **强度：moderate-strong**。逐条 8/8，但它在信息上**与 E1 高度重合**（"边缘不动"≈"不征用陌生专家"），
  不应作为独立证据计数。
- **被推翻的部分**：「新颖性住在联合里」「熟专家新组合率是唯一代码领先的量」（分解为 1.97× 边缘机会 × 1.23× 条件率，
  按条件率 programming 排第 3，落后 cooking 5.60×、fiction 5.33×）、「A 证明代码更依赖联合」（`corr(log A, log marginal) = −0.836`）。

### E5（中）代码的位移方向 = routine 自己的 prose↔工具调用 JSON 模态轴（**方向成立，因果不成立**）

- **支持**：`refute_whitening` §3.3（`cos(code 平均原始偏离, routine structured 模态轴) = 0.781/0.765`，**8 域唯一**，
  其余 −0.34…+0.25；逐条 0.708/0.818/0.791/0.793/0.803/**−0.141**/**0.416**/0.755 → **6/8**）；
  `whitening_lens` §5 反向反事实（只用 structured routine 拟合白化 → code 比值 0.78、AUC 0.478/0.502、落在 routine 第 38 百分位）；
  `nn_geometry` §2–§3 + `refute_nn` §1.2（PC1 = prose–JSON 轴，解释方差 0.1999/0.1983，`|cos(u, PC1)| = 0.942/0.955`；
  6 条代码正文 trace 的最近 routine 邻居 94–100% 是工具调用 JSON）；`token_identity` §6.1（代码 top-15 原始位移维里 13 个的 routine 最常用类是 `code_symbol`）。
- **反驳者判决**：方向事实**留下**；两个因果读法**都被推翻**：
  (a) `refute_tokenid` §2——在那条高方差轴上代码的白化信号**最强**（子空间比值 1.98×，57.6% 窗口越过 routine q90，其余 7 域 1.07–1.45×），
  且 `eff sd` 分离度在 clean 臂参照下塌成 0.093 vs cooking 0.092 而盲区照旧（0.927 vs 0.986–1.000）→ **"被当噪声预算花掉"是错的**；
  (b) `refute_nn` §4.1——把整个 JSON 叶从参照里删掉，代码只远离 0.0–5.5，B1 甚至与 legal 交错 → **"贴 JSON 叶"不是"代码为何近"的成因**
  （反例：`b2-f4-024` math，90% 邻居是 JSON，d1 = 41.54）。
- **强度：moderate**（作为方向描述）/ **refuted**（作为盲区成因）。

### E6（中）"代码盲区"至少 2/8 是标注-窗口构造，不是路由现象

- **支持**：全部 6 份透镜一致——`b2-f2-014` 窗口内 79.2% 是普通英文词、首个字面代码 token 在 **+81**，
  在每一个统计量上都是最弱的一条（`joint` A=2.45、`whitening` rawR 1.04/0.99、`depth_profile` 55% 的 routine trace 超过它、
  `refute_tokenid` 子空间分位 0.515）；`b2-f2-015` 首个字面代码 token 在 +60、rawR 1.16/1.09。
  `depth_profile` §7.4 记录 `b2-f2-015` 的备选读法把 ```sql 围栏放在 +87。
- **强度：moderate**，但**后果很大**：它意味着若干"8/8"实际上是"6/8 真代码 + 2 条无关样本恰好同向"，
  而 `whitening` 的"原始偏离大"版本本来就只有 5/8、方向版本 6/8（反驳者已明写）。

### E7（中）盲区不是 programming 专属，而是"用 routine 自己的专家写结构化/清单式产物"这一类的共同失效

- **支持**：`pertoken_code` §6.2（`b1-f1-058` travel packing-guide 的 CAND-A/w1 medR −0.039、百分位 42.9，**比 6/8 代码 trace 还平**；
  w=1 下另有 8/51 条非 programming drift 窗口内零越界）；`whitening_lens` §7.1（同一条 trace GAIN 0.97/0.99）；
  `depth_profile` §7.2（legal 12–15 偏离 17.49、17% routine trace 超过，与代码的 3 条散文型同区）；
  `refute_nn` §3（最近的非代码 drift `b2-f3-066` legal d1 25.69，与代码带重叠，边距只有 0.30/0.61）。
- **强度：moderate**。5 个镜头一致，但每个都只有 1–7 条对照样本；没有人做过"结构化非代码产物"的成组对照。

### E8（弱）代码在 WGM 空间里"最近但仍在外面"，并坐在 JSON 叶外缘

- `refute_nn` **refuted=true (high)**：粒度错配（41 窗口中位 vs 单窗口 q95）；同粒度块中位 q95 下
  "g1 低于 routine q95"只剩 **3/8**、"块中位 q95 之上" 6/8；"代码是所有 drift 里最近的"边距 0.30/0.61，
  重采样白化下只在 **21/40（B1）、27/40（B2）** 次成立，换全 16 层带**两批都破**，把 3 条 P3 算进来也破。
- **强度：weak**。作为"代码 vs 其他 drift 的相对位置"的描述可用；作为盲区机制不可用。

### E9（强，负结果）token 新颖度 / 词表复用**不是**机制

- `token_identity` 假设一被自己否定（共享 id 的代码 token 偏离 routine 的 id 质心 0.0449 vs held-out 0.0178 = 2.5×，
  只有 45.0% 落在 routine 自身 q90 散布内）；假设二的"决定性"被 `refute_tokenid` §4 否定
  （code 的 novel/known 比值 **1.106** = routine 自身的 **1.102**；`pearson(聚合类条件 JS, 新 token 最近类 JS) = 0.925`；
  该量的域排序就是"难/易"排序，8 条代码里夹着 8 条非代码）；
  `depth_profile` §7.1 独立否定（`spearman(代码字符密度, 12–15 偏离) = −0.421`，`spearman(unigram surprisal, 偏离) = 0.178`）。
- **强度：strong**（作为排除项）。两个镜头、两个反驳者一致。

## 3. 回答"代码/SQL 为什么难分"还缺什么

### 3.1 结构性缺口

1. **没有把机制接到冻结检测器的漏检上（最大缺口）。** 只有 `refute_nn` §6 做了拼接，结论是否定的：
   干净检出的最小 g1 是 949.3/1361.5，未检出的最大 g1 是 8913.4/7059.4，秩逆序 12/135 与 94/294。
   **缺的是：8 条代码 trace 各自漏警的逐条归因分解**（分数水平 / 位置桶标准化 / 校准半 / persist2 / onset 前报警 / +16 及时性各贡献多少）。
   `missed_drift.md` 的 M1–M5 做了分类，但没有做"若分数为 X 则是否报警"的反事实。**没有这一步，任何"机制"都停在分布层。**
2. **`depth_profile` 没有被复核。** 它承载 E2（唯一的正向机制）与 X10（唯一与既定结论冲突的可分性主张）。
   本轮的对抗覆盖率是 5/6，缺的正好是最关键的一份。
3. **没有跨 batch 检验任何存活机制。** E2（rmass/概率锐化）、E4（联合未见）都只在批内验证；
   `joint` 自己承认同族未见转移统计量在模式 T 下 FAR = 1.000，`fcm_report` §0.3 已证。
   **"批内可分"到"跨批可用"的那一步，本轮零证据。**
4. **没有"结构化非代码产物"的成组对照。** E7 全靠 `b1-f1-058`（n=1）与 legal（n=7）。
   要判定盲区是"代码"还是"用 routine 专家写的结构化产物"，需要一组清单/表格/JSON 类非代码 drift，本数据里没有被专门切出来。
5. **没有专家身份层面的对齐检验。** 三份镜头都断言"代码走的是 routine 工具调用 JSON 的那批专家"，
   但**没有人检验同一个表面 token 在两种上下文里是否路由到同一个专家**
   （例如代码里的 `(` 与工具调用里的 `(`、代码的缩进与 JSON 的缩进）。`token_identity` §4 的 id 条件偏离 2.5×
   反而暗示**不是同一批**。这是一个可直接回答、却没人做的判别性检验。
6. **没有 routine 自身工具调用窗口的逐条基线。** `whitening_lens` §5 给了分布层（structured routine 原始比值 1.236/1.182、
   `refute_whitening` §3.1 给了 structured-vs-all 的 rawAUC 0.633/0.612），但没有"某条 routine trace 的 JSON 段在每个统计量上得几分"的逐条表——
   而这正是判断"代码 = 加强版 JSON"还是"代码 ≠ JSON"的对照。
7. **P4 污染没有被系统性剔除后重算。** 只有 `depth_profile` 做了 5 vs 3 分组（12–15 比值 2.27 vs 1.53）。
   **缺一份"只用 5–6 条字面代码 trace"重算的全部头条表。**
8. **n=8 上几乎没有零模型。** 只有 `refute_pertoken` 做了逐 trace 符号检验（最小可能双侧 p = 0.0078），
   `refute_whitening` 做了 59 条 drift 的 GAIN 排名（代码占 1–3、5–9 名）。
   其余"8/8""6/8"全部是裸计数，没有置换/重采样零模型（`refute_nn` 的 40 次重采样是唯一的例外，且结果是**否定**的：21/40、27/40）。

## 4. 单个最有判别力的补充分析（**未执行**）

**把 E2（唯一正向机制）放到冻结的部署口径下做一次跨 batch 检验，并同时解掉 X10。**

具体：用**只在 routine 上拟合**的统计量 —— 每层"落在 routine 该层 top-8 专家上的概率质量"（`depth_profile` 的 rmass，
**方向取反**：分数 = 质量越集中越高，而不是距离越大越高），w=8、层 5–15，走**冻结 harness 的完整部署路径**
（位置桶标准化 + scenario 对半 conformal + persist2 + 模式 D **与模式 T**，α=0.10，routine=cb），
在两个方向（B1→B2、B2→B1）上报告：8 条 programming 的逐条 `first_alarm_end`、总体/benign/resist 三条 FAR，
以及非 programming drift 的 R16 变化。

**为什么它最有判别力**：

- 存活解释里，E1/E4/E5 都是"代码**没有**做什么"（不征用陌生专家、不动边缘、方向撞上 routine 自己的模态轴），
  它们**共同预测**：任何以"离 routine 多远 / 有多新颖"为统计量的读数都救不回代码——这一族已经被 15 个概率反事实 + F1/F8a + G3 kNN 反复证否。
  只有 E2 预测存在一个**反号**的可用量（"比 routine 更 routine"），而现有全部候选都取绝对值或平方距离，**结构上无法表达它**。
- 它同时决定 X10：`depth_profile` 的 5/8 究竟是真信号，还是批内 trace-max null 的产物。
- 它的两种结局都直接可用：若跨批成立 → 盲区的正确描述是"方法族只测发散、不测收敛"，这是一句可写进适用范围的机制陈述；
  若跨批崩掉（如 F6a/F6b 的模式 T FAR=1.000）→ E2 降级为批内现象，本轮的结论就收敛到"CAND-A/B 这一族对代码没有可用信号"，
  B3 的数据设计必须换方向。
- **代价与前置条件**（必须写明）：rmass 是一个**下界更容易被 routine 自身工具调用窗口触发**的量，
  benign/resist 臂 FAR 是它最可能失败的地方；因此该检验**必须**同时报三条 FAR 与非 programming R16，
  并且必须先按 §3.2 剔除 2 条 P4 重算一遍逐条数字（有效 n=6）。**本文没有运行它，也不预判结果。**

次优候选（若上者不可行）：§3.1 缺口 5 的专家身份对齐检验——同一表面 token（`(`、`,`、缩进、`"`）在代码上下文与 routine 工具调用上下文里的
逐层 top-1 专家是否相同，逐条给 8 条代码 trace 的重合率。它能一次性判定 E5 与 E2 的相容性，但它不改变任何检测口径的读数。
