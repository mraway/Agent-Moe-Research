# 白化对"代码方向"做了什么（LENS: what the whitening does to the code direction）

日期：2026-09-05（America/Los_Angeles）。执行者：Opus 5 research engineer（zoom / code_blindspot）。

范围：**事后诊断**，只用 B1/B2 开发数据。全部窗口集合都由标注锚点（`product_onset` / `evidence_onset`）选出，
**不是检测器**，本文不做校准、不报召回、不宣布任何改进。所有对比都是分布层面的比值 / AUC / 尾部占比。

代码：`scripts/research_v2/zoom/code_blindspot/{whitening_common,whitening_decompose,whitening_separation,whitening_pertrace,rare_expert_mass,verify_reproduction}.py`
产物：`artifacts/agent_v2/research_v2/zoom_code_blindspot/{whitening_lens,whitening_separation,whitening_pertrace,rare_expert_mass,verify_reproduction}.json`

（层 5–15，w=8，全局中心，identity 变换，`variance_floor=1e-3`，`trace_equal_weight=False`）。把重拟合得到的

## 0. 一页结论

1. **代码的偏离不小，而且几乎全部落在 routine 方差最大的坐标上，白化把它整体除掉了。**
   未白化的平方偏离中位数：programming **26.41 / 25.59**（fit=b1 / fit=b2），routine **16.40 / 16.59**，
   即 **1.61 / 1.54 倍**——比 legal_analysis（1.21 / 1.20）和 travel_planning（1.41 / 1.40）**更大**。
   白化之后 programming 只有 **1.58 / 1.48 倍**，而 legal 变成 2.55 / 2.59、travel 2.29 / 2.37、fiction 11.07 / 11.01。
   定义**白化增益 gain =（白化比值）/（原始比值）**：programming 是 8 个域里**唯一 gain ≈ 1 的域**
   （**0.98 / 0.96**），其余域 1.63–8.48。**代码不是"处处都小"，而是"被白化按 routine 自己的尺度归一掉了"。**
2. **机制在坐标层面是干净的**：按 routine 方差把 704 个 (layer, expert) 坐标分十分位，
   最低方差十分位（decile 0，方差中位 0.0020）承载的**原始**偏离能量占比 code **2.0%** vs other-drift **12.9%** vs routine 0.9%；
   白化后同一十分位承载的能量占比变成 code **19.6%** vs other-drift **78.6%**（fit=b1；fit=b2 为 13.4% vs 77.3%）。
   **其他域 drift 的白化距离有近八成来自 routine 几乎不用的专家；代码没有这个成分。**
   代码原始偏离能量在最高方差十分位占 **42.6%**（routine 34.8%，other-drift 27.1%），
   与 routine 自身的能量分布几乎同形。
3. **可读版本**：把"routine 平均选择率 < 0.02"的 68/704 个坐标叫"冷门专家"，routine 每个窗口平均把
   **0.78%** 的 top-8 名额放在冷门专家上；fiction **13.15%**、poetry 11.16%、general_knowledge 10.98%、
   cooking 6.48%、travel 5.27%、math 4.13%、legal 3.50%，**programming 0.84%（= routine 的 1.08 倍）**（fit=b2）。
   fit=b1 同序：routine 0.67%，programming 1.42%（最低），legal 3.34%，fiction 12.30%。
   **写代码没有让 OLMoE 打开新专家，只是把客服路由已经在用的那批专家重新配了权重。**
4. **不是 rank / floor 的锅**：CAND-A 用的是 g1（全维距离，不丢弃任何子空间）；即便按 auto 规则取 rank=16 的
   PCA 子空间来分解，代码的白化能量有 **36–54%**（逐条）落在**保留的**前 16 个主方向里
   （routine 0.56–0.59，other-drift 只有 0.13–0.26）——代码偏在**高方差、被保留**的方向上，不在被丢弃的方向上。
   方差地板从 1e-3 改成 0 / 1e-4 / 1e-2 / 3e-2，code 比值只在 **1.54–1.58**（fit=b1）/ **1.46–1.49**（fit=b2）之间动，
   AUC 变化 ≤ 0.005；地板对 other-drift 的影响还更大一些（比值 5.12→3.06）。**地板不是原因。**
5. **反事实（prose-only 白化）改变了"比值"，但没有改变"可分性"**：把白化只拟合在 prose routine 窗口上
   （无 `{`/`"`/`:`，数字/标点 token < 30%；占 routine 窗口 61.5% / 57.1%），programming 的中位比值从
   **1.58 → 3.83**（fit=b1）/ **1.48 → 3.67**（fit=b2），域内排名从 8/8 升到 5/8。但**窗口级 AUC 只从
   0.797 → 0.830 / 0.759 → 0.811，超过 routine q90 的窗口比例从 0.481 → 0.497 / 0.411 → 0.446**，
   因为 routine 自身的分布同时被撑开（q90/median 从 1.60 变成 3.86）。**比值涨了 2.4 倍而尾部可分性几乎没动**，
   这正是 FCM F8a「去结构化池 → 找回 0/8」的分布层解释：**保形阈值读的是 routine 的尾，而 prose 白化把
   routine 的尾抬得和代码一样快。**
6. **反向反事实（structured-only 白化）把代码打到 routine 以下**：只用结构化 routine 窗口拟合白化时，
   programming 中位比值 **0.78 / 0.78**，AUC **0.478 / 0.502**（= 随机），中位数落在 routine 的第 38.7 / 38.0 百分位——
   **代码窗口比一半的 routine 窗口更靠近中心**。同一白化下 general_knowledge 21.4 / 145.5、math 15.3 / 213.3。
   **代码的路由几何确实住在 routine 的"工具调用 JSON"子流形里面**，这不是"JSON 习惯让参照系变脏"，
   而是"代码本来就在那个子流形内部"。
7. 逐条看 8 条 programming drift，gain 全部在 **0.80–1.15**（中位 0.98 / 0.96），
   配对的同 batch 非 programming drift 的 gain 是 **0.97–6.46**（中位 1.98 / 2.04）；
   唯一交叉的一对是 `b1-f2-014`（gain 1.08）vs 其配对 `b1-f1-058`（travel_planning，P3，gain 0.97）——见 §7 反例。

`{`、`"`、`:`，且"无字母且含数字或标点"的 token 少于 30%。routine 窗口中 prose 占
**5315/8647 = 61.5%（b1）**、**7748/13576 = 57.1%（b2）**；structured = 补集。

**回答"是否发生实质变化"**：
- **比值层面：是。** prose 白化把 programming 的中位比值抬了 2.4 倍（1.58→3.83 / 1.48→3.67），
  域内排名从 8/8 升到 5/8（超过 cooking、travel、legal）。这是本轮唯一一个让代码在**比值**上"不再垫底"的操作。
- **可分性层面：否。** AUC +0.033 / +0.052，超过 routine q90 的窗口比例 +0.016 / +0.035，
  代码中位数在 routine 分布中的百分位几乎不动（0.894→0.898 / 0.856→0.873）。
  原因写在表里：prose 白化让 **routine 自己的 q90/中位从 1.60 涨到 3.86**——分子分母一起涨。
  **这解释了 FCM F8a 为什么找回 0/8：保形阈值读的是 routine 的尾，而不是中位比值。**
- **反向反事实：structured 白化把代码打成随机**（AUC 0.478 / 0.502，比值 0.78，中位落在 routine 第 38 百分位），
  而 general_knowledge / mathematics 在同一白化下涨到 21.4 / 145.5 与 15.3 / 213.3。
  **代码窗口就在结构化 routine 的内部**：用结构化 routine 定义的椭球去量代码，代码比一半 routine 更"正常"。

## 7. 反例、否证与替代解释

1. **反例（配对对照里也有 gain≈1 的非代码 drift）**：`b1-f1-058`（travel_planning，P3，`knowledge_qa`，
   product_onset=0）的 gain = 0.97 / 0.99，AUC 0.730 / 0.708，比 3 条 b1 代码 trace 还低。
   **"gain≈1"不是 programming 独有的标记**，只是在 programming 上是 8/8 一致。
2. **反例（代码并非在每个窗口都不可分）**：b1-f2-014 与 b1-f3-016 的窗口级 AUC 是 0.927–0.949，
   高于 travel_planning 域整体（0.862 / 0.867）。**代码的问题在于超不过 routine 的 q99
   （>q99 的窗口比例 0.019，其他域 0.31–0.92），不是"完全没信号"。**
3. **否证 A：不是 rank / 丢弃子空间。** g1 不丢弃任何方向；且代码的白化能量有 36–54% 在**保留的** rank-16
   子空间里（比其他任何 drift 域都高）。
4. **否证 B：不是方差地板。** floor ∈ {0, 1e-4, 1e-3, 1e-2, 3e-2} 时 code 比值 1.584/1.584/1.581/1.556/1.537
   （fit=b1）、1.489/1.490/1.478/1.480/1.464（fit=b2），AUC 变化 ≤ 0.005。
   routine 方差最小值 5.8e-5 / 1.19e-4，只有 3 / 0 个坐标的方差 < 1e-4，地板占 sd 的中位比例 0.74%。
5. **否证 C：不是"代码的偏离小"。** 原始平方偏离 26.41 / 25.59 > legal 19.77 / 19.85，而 legal 的白化分离更好。
   （限定：对 b2-f2-014、b2-f2-015 两条，这条否证不成立，见 §6。）
6. **未被本文排除的替代解释**：代码窗口可能在**时间结构**上与 routine 不同（本文只看窗口内的选择率均值，
   不看窗口间的动态），或在**概率质量/路由熵**上不同（FCM 的 15 个概率反事实已否掉一部分）。
   本文只说明"在 CAND-A 的窗口几何里，白化按 routine 方差归一，把代码方向除没了"。

## 8. 对检测器的含义（不构成任何改进主张）

- **CAND-A 的分离力实质上是一个"冷门专家点亮检测器"**：白化让 78% 的 other-drift 能量集中在 routine
  几乎不用的 70 个坐标上。任何仍然按 routine 方差归一的窗口几何，对"只重排高频专家权重"的域外产物
  都会有同样的盲区——**这是该方法族的适用范围声明，不是可调参数。**
- 要看见代码，检测器必须测量**在 routine 高方差坐标内部的联合构型**（哪些高频专家一起被用、以什么比例），
  而不是任何按边际方差归一的距离。逐坐标 z 是 1.4–2.0，方向本身却是稳定且一致的（8 条 trace 的
  top-|raw| 坐标名单在两个 batch 上重合 9/10）——**信号在"方向"里，不在"幅度"里。**
- **不要用中位比值判断是否有救**：§5 的 prose 反事实把比值抬了 2.4 倍而尾部占比几乎不动。
  任何后续提案都应直接报 AUC / 超过 routine q90–q99 的占比，而不是中位比值。
