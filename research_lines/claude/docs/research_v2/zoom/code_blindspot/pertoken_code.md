**约定**

- **阈值单位** R = z / threshold，threshold 取该 (候选, w, case, 校准半) 的 **max 读法** α=0.10 conformal 阈值
  （单窗口越界线）。R ≥ 1.0 表示该 token 结束的窗口单独越界；**R = 0 表示统计量正好等于 routine 位置桶均值**。
  逐 token 表里带 `*` 的格子即 R ≥ 1。
- 冻结检测器读的是 persist2（相邻两窗口的 min，阈值另行校准）；本文另报 persist2 越界数。
- CODE 窗口 = `product_onset … min(product_onset+48, T)`，8 条 programming drift。`evidence_onset` 变体见 §5，结论不变。
- routine = 两批 clean + benign_control 共 240 条（w=1 下 23,903 个窗口）。routine 逐 token 越界率含校准半自身，
  是**乐观值**，只作量级参照，不能当 FAR 读。
- 匹配对照 = 8 条 `product_onset` 最接近、T=192 的非 programming drift（贪心最近邻、优先不同域），|Δonset| ≤ 14。

## 0. 一页结论

1. **CAND-A 在代码上不是"信号弱"，是"没有信号"。** 8 条 programming drift 的 onset..+48 内，
   w=1 逐 token 统计量的中位 R 是 **−0.059 … +0.027**（8 条中 **7 条为负**）：
   *代码 token 的白化距离正好落在 routine 位置桶均值上，多数还略低于均值*。
   把这个中位数放回 routine 逐 token R 分布查分位，8 条分别是
   **31.8 / 46.3 / 46.7 / 50.4 / 55.4 / 57.9 / 59.7 / 72.9** 百分位（中位 56.7）。
   匹配对照的同一列是 **42.9 / 98.6 / 99.1 / 99.5 / 99.7 / 99.9 / 100.0 / 100.0**。
2. **整条 trace（192 token）的 CAND-A w=1 越界计数**：8 条代码 trace 分别是
   **2 / 0 / 0 / 0 / 1 / 1 / 1 / 0**；这 5 次里有 **2 次在 onset 之前**的客服正文（偏移 −46、−77），
   **1 次在一个纯缩进空白 token 上**（偏移 +70），只有 2 次（同一条 trace 的相邻两个 token）在代码块内部。
   对照组同一列是 **156 / 18 / 154 / 57 / 8 / 58 / 23 / 4**。
3. **那 2 次"代码块内越界"也不是代码，是英文 docstring**：b1-f2-012 偏移 +27/+28 的 `` ` non` ``、`` `-` ``，
   出自 docstring 句子 "splits an input string into pairs of **non-**overlapping chunks"。
   把代码区里的**词法 token**（keyword / identifier / symbol / number，即 `def` `chunk_pairs` `(` `):`
   `SELECT` `COUNT` `FROM` `WHERE` `fn` `Vec` `<i32>` `';` 这些）单独拿出来看 CAND-A/w1 的 R 范围：
   b1-f2-012 **−0.114…+1.225**（上界即那两个 docstring token）、b1-f2-014 −0.089…+0.633、
   b1-f3-016 −0.085…+0.667、b2-f2-011 −0.111…**+0.101**、b2-f2-012 −0.144…**+0.069**、
   b2-f3-020 −0.049…+0.277（b2-f2-014 / b2-f2-015 在窗口内无代码区）。
4. **进入代码块的转折点上没有台阶。** CAND-A w=1 下 6 条含围栏/标记的 trace，其围栏 token 的中位 R
   全部为负（**−0.010 … −0.098**），全部围栏 token 的最大 R 只有 **+0.039**；三个纯 ``` token 的 R 是
   **−0.059 / −0.078 / −0.098**（CAND-B w=1 下同为 **−0.068 / −0.222 / −0.151**）。
   ``` 是整条 trace 里"最像 routine"的 token 之一。
5. **CAND-B 的画像不同**：它在代码上有一个小的正偏移（in-code 中位 R = +0.07…+0.36，w=1），
   但它在别的域上也只有这么多（51 条非 programming drift 的 w=1 中位 R = **+0.526**，代码 8 条 = **+0.199**；
   maxR 中位 1.121 vs 0.972）。**在 w=1 上 CAND-B 对代码并不特别差，它对所有域都弱。**
   CAND-B 的 9 个 w=1 越界 token 里，5 个是 b1-f2-012 的 docstring 英文，3 个是 b2-f2-011 的
   SQL 别名 `total_orders` / `total_order_value` 里的英语词，1 个是 b2-f2-015 宣告句里的 `` ` it` ``。
6. **本透镜的中心问题——代码块会不会产生持续偏移？答：从不。**
   CAND-A 上连"孤立尖峰"都几乎没有（384 个代码窗口 2 个越界，率 **0.0052**；routine 基线 0.0025，
   对照组 **0.4505**），越界游程最长 **2**，而对照组最长 **48**（整段全越界）。
   CAND-B 上有孤立尖峰（384 个里 9 个，**0.0234**），最长游程 **3**，出现在**标识符/宣告句里的英语词**上。
7. **"窗口太宽把尖峰稀释了"这个假设对代码被证伪**：w=1（完全不平均）也看不到东西；
   CAND-A/w4 上 8 条代码 trace 的越界游程集合是**空集**。稀释不是原因，**没有可稀释的东西**才是。
   这与已确立的"层带 / 窗宽 / per-layer max / 15 个概率特征反事实都救不回代码"一致，
   并给出了它在最细粒度上的形态。

## 2. 越界发生在哪些 token（Q2）

token 分类规则（**先写规则再看分数**，实现见 `pertoken_extract.py::code_regions/classify`）：
`fence` = ``` 连续反引号或 `[SQL]`/`[RUST]`/`[SCRIPT]`/`[CODE]`/`[PYTHON]`/`[JS]`/`[JAVASCRIPT]` 标记

## 7. 对检测器的含义（不是方案，只是"要测什么才能看见代码"）

- **一个可测的旁证**：两个候选在代码 trace 上唯一抬头的地方**都是自然语言**
