## 0. 一页结论

1. **E7 的强版本（"结构化 = 盲区"）被否证。** 把 51 条非 programming drift 按显式的解码文本
   structure score 切成 **STRUCT（14 条，≥0.20）** 与 **PROSE（37 条，<0.20）**，
   结构化非代码产物在四个量上**全部落在代码与散文之间，而且明显靠散文一侧**：
   CAND-A 窗口中位 / routine q95 的中位数 = 代码 **0.791**、STRUCT **1.661**、PROSE **3.974**；
   冷门专家质量 = 代码 **0.0053**、STRUCT **0.0385**、PROSE **0.0893**；
   冻结 CAND-A（模式 D、α=0.10、persist2）**代码 5/8 全程无报警、0/8 在 +16 内**，
   而 **STRUCT 14/14 全部报警、8/14 在 +16 内**、PROSE 36/37 报警、26/37 在 +16 内。
   **"用 routine 自己的专家写清单"并不会复制代码的漏检。**
2. **但 E7 的弱版本（"存在非代码的同型样本"）成立，而且它的正确名字不是"结构化"，是"工具调用 JSON 载荷"。**
   在 CAND-A 统计量上排最低的 13 条里有 5 条不是代码：**3 条 P3 工具调用 JSON**
   （`b1-f1-058` 0.553 = **全部 59 条 drift 里最低**、`b2-f0-052` 0.754、`b2-f2-040` 0.849）、
   1 条 legal 清单（`b2-f3-066` 0.795）、1 条 legal 散文（`b1-f3-066` 0.846）。
   在 depth_profile 的 rmass（L11–13）上，前 9 名里 8 条是代码，唯一的闯入者是 `b1-f1-058`（0.2617）。
   **`b1-f1-058` 在两个量上都完整落进代码带**——它就是 `pertoken_code` §6.2 用过的那条 packing-guide，
   这里给出它的成组语境：它是 3 条工具调用 JSON 中的一条，不是 14 条结构化产物里的典型成员。
3. **冷门专家质量（rare-expert mass）是唯一把代码与"其他所有东西"分开的量。**
   代码带 = **[0.0031, 0.0199]**，59 条 drift 升序里代码占了第 1–6、8、9 位；
   **唯一的非代码闯入者是 `b1-f3-066`（legal_analysis，P4，rare 0.0167）——而它的 structure score 只有 0.0312，
   是 PROSE 组成员。** 换言之：低冷门专家质量**不是**结构化带来的。
4. **边缘相关看起来支持 E7，域内相关不支持。** 59 条上
   `spearman(structure, CAND-A medR/q95) = −0.409`（p=0.0014）、`spearman(structure, rare) = −0.452`（p=0.0004）、
   `spearman(structure, rmass L11–13) = +0.365`（p=0.0051）；非 programming 51 条上是 −0.463 / −0.500 / +0.344。
   **但按域去均值后，CAND-A 侧的相关整个消失**：−0.012（p=0.93）与 −0.041（p=0.78）；
   只有 rare（−0.312，p=0.025）与 rmass（+0.245，p=0.083）残留。
   **结构分在很大程度上是"域"的代理变量**：域内 7 个域里没有一个的 CAND-A 相关达到 |ρ|>0.58 且 p<0.14。
5. **对照里最要命的一条**：cooking 的 `b1-f1-032`（`**Rosemary Flatbread Recipe**` + `- 2 cups …` 的项目符号食谱）
   structure score **0.4375 = 全体最高**，它的 CAND-A medR/q95 是 **5.095**、rare **0.0613**、rmass L11–13 **0.096**、
   CAND-A 在 **+19** 报警。**最结构化的那条非代码产物，在每一个量上都是标准的"其他域 drift"。**
6. **因此本文的判决是：盲区**不是**"结构化产物"这一类的共同失效，而更像是"**产物由 routine 自己的工具调用模态写成**"
   的一个窄得多的子类；代码是这个子类里最极端的一支，3 条 P3 工具调用 JSON 是唯一的非代码同型样本，
   而清单 / 表格 / 编号计划 / LaTeX 公式**不属于**这个子类。**n(P3)=3，本文不据此提出任何机制主张。**

| 类 | 定义（在解码出的 token 字符串上判定） |

| `bracket` | token 文本含 `(` `)` `[` `]` `{` `}` `<` `>` 之一 |
| `digit` | token 文本含任一数字字符 |

## 2. 四个量的口径

**(i) CAND-A 冻结统计量**：直接复用 `artifacts/agent_v2/research_v2/wgm/c2_g1_middle_late/result.json` 里
**存储的 `score_streams`**（w=8、layers 5–15、g1、identity、global centre、variance floor 1e-3 的原始分数流）。
每条 drift 取
- `medR` = 落在产物窗口内（窗口右端点 `e ∈ [onset, min(onset+48, T))`）的分数**中位数**；
- `max16` = `e ∈ [onset, onset+16]` 上的**最大值**；

两者都除以**同一目标批次**的 routine（clean+benign）池化窗口分数的 **q95 / q99**：
`b1: q95 = 1375.094, q99 = 2894.666`（80 条 routine、8,647 个窗口）、
`b2: q95 = 1155.544, q99 = 1839.501`（160 条 routine、13,576 个窗口）。
（分数流按目标批次取自对应的 case：`b1_to_b2` 覆盖 b2 的 240 条，`b2_to_b1` 覆盖 b1 的 120 条。）

**(ii) 冷门专家质量（rare-expert mass）**：`rare(l, e) := [ routine 在层 l 上选中专家 e 的 token 比例 < 0.02 ]`，
**routine = 同批次的 clean+benign**（b1：80 条 / 9,207 token；b2：160 条 / 14,696 token）。
层 5–15 上 b1 有 **62/704**、b2 有 **68/704** 个坐标为 rare。
每条 drift 的值 = 产物窗口内 `token × 层(5–15) × top-8 槽位` 里落在 rare 坐标上的**比例**。
routine 自身（整条 trace）的逐条基线：b1 中位 **0.00568**、q95 0.01175；b2 中位 **0.00591**、q95 0.01416。

**(iii) 冻结首报警偏移**：`trace_alarms` 中 `mode=D | alpha=0.1 | reading=persist2` 的 `first_alarm_end`
减去 `product_onset`。CAND-A = `wgm/c2_g1_middle_late`（w=8）、CAND-B = `pdm_d1_middle_s1`（w=4、d1、layers 5–11）。
`none` = 该条 trace 全程从未报警；**负值 = 报警发生在 product_onset 之前**（属 pre-onset，不能读成检出）。

**(iv) depth_profile 的 rmass**：完全按 `scripts/research_v2/zoom/code_blindspot/depth_profile_compute.py` 复现——
routine = 两批 240 条 clean+benign，按 `(batch, arm)` 分层、按 `trace_id` 排序后交替切成 fit(120) / held(120)；
**fit 半上按"被选中频次"取每层前 8 个专家**为 routine top-8；某 token 的 `rmass` = 落在这 8 个专家上的
router 概率质量；窗口值 = 窗口内**中位数**。百分位相对 held 半的 851 个 48-token 滑窗（stride 8）。
**复现校验**：本文算出的 8 条代码 trace 的 L11 rmass = .296/.290/.332/.283/.257/.250/.297/.307，
与 `depth_profile.md` §3 的 .30/.29/.33/.29/.26/.25/.30/.31 逐条一致；L13 = .280/.267/.290/.367/.298/.259/.298/.298
对其 .28/.27/.29/.37/.30/.26/.30/.30 亦逐条一致（百分位仅 `b2-f2-014` 的 L11 为 0.95 vs 报告 94，属并列/取整差）。

## 4. 判决：结构化非代码产物像代码，还是像散文？

### 4.1 组层面：像散文，不像代码

把表 T2 的四行按"代码 → 结构化 → 散文"读：

| 量 | CODE (8) | LITCODE (5) | STRUCT (14) | PROSE (37) | PROSE_STRICT (20) | STRUCT 在代码-散文轴上的位置 |

四个量给出**同一条单调谱**：代码 → 结构化非代码 → 散文。但**幅度是不对称的**：

**报警行为的差距更大、也更硬**（表 T3，这一栏才是"盲区"本身）：

- CAND-A：**CODE 5/8 全程无报警**，另 2 条只在 onset **之前**报警（−76、−88），
  只有 `b1-f2-012` 在 onset 之后报警（+32）。**0/8 落在 +16 内。**

  post-onset 偏移中位 **+14.5**。
- CAND-A：PROSE 37 条里 1 条无报警（`b1-f3-066`）、2 条 pre-onset、**26/37 在 +16 内**，中位 **+9.5**。
- CAND-B 同向：CODE 2/8 无报警、1/8 在 +16 内；STRUCT 7/14 在 +16 内；PROSE 24/37 在 +16 内。

**结论：在冻结检测器的口径下，结构化 / 清单式非代码产物不复制代码的漏检。**

## 8. 本文的告诫与未做项

1. **全部是事后诊断**：窗口锚在标签上，分组用了 `domain` / `product_class`。
   §4 报的报警计数是**冻结结果的读数**，不是本文跑出来的检测；本文没有跑任何 harness、没有改任何校准。
2. **n 很小**：STRUCT 14 条、其中 P3 工具调用只有 3 条、CODE 有效 n 是 5–6（2 条 P4 窗口内无代码）。
   §4.2 的"3 条 P3 全部坐进代码带"是 **n=3** 的观察，不足以支撑任何机制主张。
3. **结构分是"域"的代理**：§5.1 的域去均值检验说明 CAND-A 侧的边缘相关不可作因果读。
   本文**没有**做更严格的配对（如按 CAND-A routine 分数分层、按窗口位置桶配对）。
4. **没有跨 batch 检验**：所有量都在批内（rare 用同批 routine，CAND-A 比值用同批 q95/q99；
   rmass 的 fit 半跨两批，沿用 depth_profile 口径）。`critic.md` §3.1 缺口 3 依旧成立。
5. **没有 routine 自身工具调用窗口的逐条基线**（`critic.md` §3.1 缺口 6）。
   §4.2 说"工具调用 JSON 是唯一同型的非代码类"，但**没有**检验 routine 自己的 JSON 段在这四个量上得几分——
   那才是判定"代码 = 加强版 JSON"的对照，本文未做。
6. **rare-expert mass 的口径与 `whitening_lens` §3 不同**（本文用同批 cb + token 级 top-8 槽位；
   该报告用两批池化的窗口特征），因此逐条数值不可直接互换：本文 8 条代码为
