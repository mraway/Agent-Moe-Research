|---|---|---|---|---|

白化保住了 code 在高方差轴上的信号；**盲区来自另外 633 维**——code 在那里与 routine 无异，
于是把一个 71 维的真信号稀释进 633 维的 routine 噪声里（routine 全维 g1 中位 621，其中 549 来自这 633 维）。

阈值不敏感：换成最高 5%（36 维）CODE 2.63× / 分位 0.913、最高 20%（141 维）1.63× / 0.879、
`sd > 0.25`（55 维）2.21× / 0.925——CODE 在四种切法里都排第 1。

### 2.1 "最高方差方向"这个描述本身也不准确

- `eff sd` 的定义是 `‖d‖ / ‖d/sd‖`，即 **1/eff² = Σ (u_i/sd_i)²**（u 为单位位移方向）。
  这是一个**由最小的 sd 主导的调和型平均**，不是"落在高方差维上"的度量。
  证据：legal 有 51.7% 的平方位移在最高方差十分位（8 个域第 2，仅次于 code 的 62.6%），
  eff sd 却只有 0.095；cooking 只有 28.8% 却拿到 0.103。
  在 7 个非 code 域上，`pearson(最高十分位份额, eff sd) = -0.251`（**符号是反的**），
  逐 trace（51 条非 code）也只有 `+0.19`；而 `pearson(最低两个十分位的 z² 份额, eff sd) = -0.98`。
  **对方拿来当机制的那个变量，在它自己的对照集内部没有解释力；真正决定 eff sd 的是"位移在低方差维上有多少质量"。**
- 0.198 也不是"最高方差方向"：它落在 routine 逐维 sd 的 **第 83.5 百分位**（sd 中位 0.135、q90 0.233），
  而 routine 自己单个窗口偏离方向的 eff sd 中位就是 0.162（第 71.7 百分位），随机单位方向是 0.089。
  即 code 的方向只是"比 routine 自己的日常抖动方向再高一点点"，不是极值。
- 对方 §6.1 的 "13/15 top 位移维的 routine 最常选类是 code_symbol" 说的是**原始**位移。
  我按 |z| 重排（`refute_tokenid_dimclass.py`）：code 贡献白化距离最大的两维是
  **L12 E43（sd 0.082，第 1 十分位，routine 最常选它的类是 punctuation，routine 平均入选率 0.022，z=6.24）**
  与 **L9 E5（sd 0.121，第 3 十分位，number，z=4.72）**，两维就占 code 全部 z² 的 21.6%；
  按 |z| 排的 top15 里 code_symbol 只剩 7/15（按原始位移排是 12/15）。
  **"JSON 符号轴"描述的是 code 的原始位移，不是 CAND-A 实际看见的信号。**

### 2.2 CAND-A 对其他域实际上是一个"新专家征用"检测器

gk 的 top-15 |z| 维**全部**落在 sd 最低的十分位，routine 平均入选率 0.0009–0.0094
（L11E48：sd 0.013、routine 入选率 0.0009、z=38.4；L12E35：0.0010、z=31.3），
这 15 维占 gk 全部 z² 的 **87.3%**。相对地 code 的 top-15 |z| 只占 39.9%，且散布在第 1、3、5、6、8、9 十分位。
用 clean 臂做参照时这一点更极端：gk 的 z 位移变成 **721**（sd 触到 1e-3 地板），code 只有 38.5。

**因此对"为什么 code 难"的正确机械描述是：**
> CAND-A 的判别质量几乎全部来自 routine 近乎不用的专家（sd 最低十分位：gk 193×、fiction 148×、
> poetry 124×、math 37×、cooking 26×、travel 19.5×、legal 19.4×，CODE **1.57×**）。
> 诗/散文/知识文会征用 routine 从不点的专家；code 只是把 routine 每天都在用的专家重新加权。
> 不是"信号被白化花掉"，是**在白化能放大的那些维上 code 根本没有信号**。

这和对方 §9 的处方相反：他们要求"沿位移方向的 routine 方差"，而这里显示，
就算把最高方差十分位整个删掉（或整个只留下），code 的排名都不会改善（删掉后 code 分位 0.844→0.806→0.790，
其他 7 域全部上升）。**没有任何"修好白化"的版本能从这 704 维里救回 code**，
这与已确立的 FCM F1/F8a（prose 条件化，programming 0/8）一致。

## 4. 第 2 条腿："新 token" 这个维度没有额外解释力

## 5. 我自己的结果为什么也不是候选配置

§2 的"最高方差 10% 子空间里 code 最可分"是**诊断，不是检测器**：
(i) 它用标签定位了 `product_onset` 窗口；
(ii) 窗口级 code 中位数的 routine 分位是 0.930——**7% 的 routine 窗口比它更远**，trace 级远超 FAR 容差；
(iii) 在这个子空间里其他 7 个域全部退化到 1.07–1.45×、几乎没有窗口越过 routine q90，
     即它是拿全部其他域的召回去换 code 的一点点边际，整体上是**更差**的表示；
(iv) 逐条看 8 条 code 的子空间分位是 0.931/0.956/0.964/0.961/0.911/**0.515**/0.844/0.945——
     b2-f2-014（P4、窗口内 79% 是散文）只有 0.515，n=8 里已经有 1 条不成立。
**不提出、也不评价任何配置。**

## 7. 我这份反驳的告诫

1. **n=8**，且其中 2 条（b2-f2-014、b2-f2-015）窗口内没有代码。§2 的子空间结论逐条是
   0.931/0.956/0.964/0.961/0.911/0.515/0.844/0.945——**6/8 强、1 条中、1 条不成立**。
2. **sd 十分位切分是我选的**；我做了 5%/10%/20%/`sd>0.25` 四种切法，排序不变，但"十分位"没有先验地位。
3. **`sd = std + 1e-3` 是加在 sd 上的地板**（不是方差地板），所以 clean 臂参照下 gk 的 z=721 有一部分是
   地板效应本身。这加强了"CAND-A 的判别力住在近乎不用的专家上"的结论，但也意味着那个数字不该按面值解读。
4. **我的 token 类别规则与对方不同**（我把 fragment 并进 word，code_keyword 集合相同因而同样被英语词污染），
   所以 §4 的绝对值与对方相差 0.002–0.008；比值与排序一致。
5. **我没有重新拟合或重新评价 CAND-A / CAND-B**，本文没有任何 recall / FAR / latency 数字。
6. **"哪个是机制"部分地是叙述问题**：`‖δ‖ = ‖d/sd‖` 是一个恒等式，
   "位移沿高方差方向"与"位移在低方差维上缺席"在算术上互相蕴含。
   我主张后者是更正确的因果描述，依据是三条**可证伪**的差异：
   (a) 高方差子空间里 code 最可分（1.98× vs 1.07–1.45×）；
   (b) 最高十分位的 z 贡献在 8 个域里近乎常数（5.0–8.9）；
   (c) 最高十分位份额在非 code 域内部与 eff sd 相关系数为 −0.25（符号相反）。
   如果只接受 (a)，也已足以否定"信号被花掉"这一措辞。
