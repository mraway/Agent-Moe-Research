# 样本层面审计：组长综合与改进清单

日期：2026-09-05（America/Los_Angeles）

作者：研究组长（Claude Fable 5.1）。六项审计由 Claude Opus 5 执行者并行完成，各自的逐条证据、脚本与产物见：
`missed_drift.md`（漏检解剖）、`false_alarms.md`（误报解剖）、`calibration_anatomy.md`（校准解剖）、
`topic_vs_task.md`（提及 vs 执行、预报警重审）、`timing.md`（命中时延解剖）、`compute.md`（效率与最小表示）。
每项审计都先逐格复现了两个冻结候选的冻结数字（分数流误差 ≤ 1e-6），再做反事实；所有反事实都是
B1/B2 上的事后诊断，用于决定 B3 预注册的内容，不是新的成绩。

审计对象：CAND-A = 白化距离、层 5–15、w=8；CAND-B = 深度链 surprisal、层 5–11、w=4；均为
routine=clean+benign、部署侧 conformal α=0.10、persist2。

## 0. 一页结论

1. **漏检有清楚的三种成因，比例稳定**：渐进漂移（分数上升但在 onset+17…+35 才越线；47%）、代码/结构化输出
   与客服工具调用路由不可分（20%，全部 programming）、标注 onset 晚于域外产物实际开始而被判为"提前误报"
   （18%，其中 2/3 是标注滞后）。两个完全不同的候选漏掉的是同一批 18 条 trace，说明这些是特征层面的边界，
   不是读法或阈值的问题。
2. **误报有可见的产物层成因**：55 条误报中 75% 可归因于提及/拒绝域外话题（35%）、JSON 协议形状输出（25%）、
   逐字复述知识库文章（15%）；clean 臂没有任何一条话题类误报。误报高度集中：31 个 scenario 承载全部误报，
   2 个 scenario 占 22%。
3. **"持续性"不能降误报**：在部署侧 conformal 校准下，总误报率由 α 钉死，任何重新校准的读法只是把误报在
   trace 间重新分配并牺牲及时性；固定阈值的持续门看似降误报，实际只是收紧运行点。这否定了我在综合报告中
   把持续性读法列为改进项的判断。
4. **延迟几乎全部是"阈值余量"**：信号在 onset 当下就开始上升，但要 3–6 个 token 才超过阈值，再加 1 个
   token 的 persist2；中位延迟 ≈ 窗宽。放宽 α 换不到延迟；缩短窗口（w=4）与晚层（L12 最早、最可靠）能换到
   2–3 个 token，代价是 benign/resist 臂误报 +0.02…+0.09。
5. **校准池太小是 B2→B1 方向所有抖动的根源**：每半 40 条时运行点是 4 条 trace 的函数，剔除 1 条 FAR 变
   0.02–0.05；±0.03 稳定需要每半 55–90 条（计入同 scenario 相关约 87 条），位置桶 ≥3 需 ≥60 条。定阈者是
   普通客服流量（散文 45%、JSON 30%），不是退化输出。
6. **效率不是问题**：打分 2.2 / 0.7 微秒每 token，状态 8 KiB / 193 KiB；uint8 与 CSR 压缩无损（12–14×）。
   不应为效率牺牲精度；用 routine-only 统计挑层子集会损失 0.2–0.3 召回。
7. **两个候选互补**：同一 trace 上两者延迟可差 28–64 token 且方向不一；并联（各 α=0.05）在本批次同时改善
   误报（0.098/0.115→0.083/0.094）、+8 召回（0.43/0.50→0.54/0.58）与延迟（8→5），但这是事后选择。

## 2. 三条硬边界（当前方法族无法靠调参解决）

1. **代码与结构化输出**：域外代码的路由落在 routine 工具调用 JSON 的路由区域内（最近邻全是工具调用片段，
   距离小于窗口自身范数；层 5–15 无一层移动）。可能的新方向：以 prefill 侧工具调用上下文或输出形态做条件的
   残差分数（CM 已建 prefill cache）、或概率特征（唯一找回过 1 条的变体）。在 B3 前应把它写进方法的适用范围
   声明。
2. **话题提及**：benign/resist 的误报 16/42 来自提及域外话题，clean 臂 0/13；否定式提及（"不能写概率计算"）
   同样报警。路由分数无法区分"说到"与"做"，持续性也不能（一个 scenario 的三个臂同时击败幅度与持续性规则）。
   这是估计量性质，只能靠意图层/文本信号联合。
3. **渐进漂移的阈值余量**：47% 的漏检是分数在 +17…+35 才越线，22/23 是长回复；延迟由余量主导（3–6 token）。
   能用的杠杆只有窗宽、晚层与更精确的阈值（更大校准池）；每个杠杆各换 2–3 个 token 并付 0.02–0.09 的臂误报。

## 2.1 方案 4（FCM）对代码盲区的机制判定（2026-09-05，`docs/research_v2/fcm_report.md`）

预注册 12 个候选 + 组合器与 3 个敏感性变体，S1 两方向 × 模式 D/T × 两读法 × 两锚点；目标样本去重后 20 条
（共同漏检 18 ∪ programming 8 ∪ 工具产出 3）。在"总误报与 benign/resist 臂不高于冻结候选 +0.02"的容差内，
**没有任何候选找回任何一条**；忽略容差时最多 3/8。机制判定：

| 层次 | 判定 | 关键证据 |
|---|---|---|
| 盲区是 agent 的 JSON 习惯？ | **否** | 去掉 routine 池中的结构化窗口后重跑，programming 仍 0/8（CAND-A 版）或 2/8 但误报越线（CAND-B 版）；代码窗口的 token 结构化占比（0.12–0.20）**低于** routine（0.21–0.24），最结构化的反而是 resist 臂 |
| 形态条件化的参考有效？ | **否**（H-A 被否定） | F1/F2 两方向、两锚点 programming 0/8，整体还劣于 CAND-A；路由侧聚类能识别"不是结构化"（召回 0.95）但不能干净识别"是结构化"（精度 0.57–0.61） |
| 未见专家/未见转移携带信号？ | **分布层成立，报警层不成立** | 未见转移率对代码窗口的中位数是 routine 的 6.0 倍（CAND-A 只有 1.17 倍），但其他域 drift 是 16 倍，代码仍排在同一 conformal 阈值之下；忽略容差可找回 3/8，代价是 resist 臂 0.24–0.31；模式 T 下误报 1.0 |
| 文本规则能否兜底？ | **半成立** | 代码围栏/SQL/编程关键字规则在 301 条 non-drift 上零误报、抓住 7/8 programming drift，但**不及时**（首次命中中位在证据锚点后 +17 token、+16 内 0/8）；"非 action 的 JSON"规则误报 128/301，因为 routine 本身含 JSON |
| 能力边界 | **成立** | 已测并失败的补救：层带/窗宽/逐层 max/概率特征（漏检审计 15 个反事实）、形态条件化、形态 run-length、去结构化池、未见专家；仍有信号但代价过高：未见转移、概率特征 |

结论：代码/SQL 类越界是"只学习 routine 路由流形 + 部署侧 conformal"这一方法族在本 agent 数据上的能力边界，
应写入适用范围声明。仍未被否定、值得在 B3 前评价的两条路：(i) **两阶段读法**——路由报警作 provisional、
零误报的文本规则作 confirm（或对代码类局部放低路由阈值）；(ii) **F9 prefill 条件化**（预测 routine decode 的
结构化比例，只对超出预测的结构化输出计分；CM 的 prefill cache 可直接用）。另有两条协议提醒：形态标签的
定义对 2% 的 token（换行/缩进）极敏感（R16 变动 0.23），任何形态类候选必须先做 token 类规则消融；
`product_onset = 0` 的 trace 在 w=8 + persist2 下结构性不可及时命中，B3 指标应对 onset < w 的 trace 单列。

## 3. 效率结论

- 推理侧路由免费；打分 CAND-A 2.2 µs/token（约 3k flop）、CAND-B 0.7 µs/token（约 20 flop）；状态 8 KiB /
  193 KiB。Python 流式开销 24/50 µs 是解释器成本，不是算术成本。
- uint8 量化状态（A：8448→2112 B）与 CSR 计数表（B：196608→14–16 KB，80–83% 空格共享一个常数）逐 trace
  无损；4-bit 有损（+8 −0.086）。
- 层子集可把 CAND-A 的算子数减 5.5×（如层 12、15），但只有事后挑选能达到；若确需缩减，在 B3 上作为预注册
  的次要分析做穷举（550 个子集约 30 秒/方向）。
