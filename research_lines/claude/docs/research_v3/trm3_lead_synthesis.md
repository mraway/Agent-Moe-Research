# TRM-3 组长综合（2026-09-06；冻结提交 `55b6e23`，预注册 v1.3）

输入：`trm3_report.md`（实验报告）、三份审计（`audit_independent_recomputation.md`、`audit_sample_level.md`、`audit_statistics.md`）、
`critic_trm3.md`。全部数字在 B1/B2、h384 replay、C1 上得到，是开发集证据；B3 未使用。三份审计对全部 P1 格子与 G1–G8 逐位复算一致。

## 0. 判定

**P1 = No-go，而且符号为负。** 在匹配的有效预算下，三通道融合相对完整的冻结候选 B-M（CAND-A）的主事件 +8 净增为
−2 / 0 / −1（B1→B2 / B2→B1 / h384），名义 α=0.10 下 −3 / −2 / 0；六个格子里没有一个融合胜过单一白化距离。
门：D 列（部署侧校准）通过 G1、G2、G3、G5、G8，在 h384 上 **G4 失败**（静默抵御报警率 4/35 = 0.114，比 clean FAR 高 0.077，限 0.05）；
C1 预置阈值列在所有格子 **G7 失败**（5/30 组 = 0.167）并在两处 G2 失败，与冻结前记录一致："阈值预置出厂"在当前 C1 池上不成立。

## 1. 为什么失败（机制，三份审计一致）

1. **Bonferroni 权重把最强的早期通道饿死了。** α_S = 0.02 在 n=80 时只有 rank 1 可达（有效 0.012），在 n=40（B2→B1 的半份）时 rank 0，
   S 通道**结构性地永远不能报警**。M 通道在融合里就是 B-M 加 2.5 倍更严的阈值，所以系统性更晚（中位晚 1 token，均值晚 4）。
   TRM-3 90% 的真阳性首报警来自 M；分解没有买来任何时效。
2. **J 通道只买误报。** 单通道 +8 召回 0.02 / 0.00 / 0.02；在 b2/D 的 clean 样本上贡献 184 个 CONFIRMED 端点（M 只有 3 个）；
   它在同一 pair group 的攻击臂和 benign 臂上以**逐位相同的 top 坐标**在同一端点报警，即它响应的是 JSON 工具调用脚手架，不是攻击。
   h384/D 上唯一失败的门 G4 完全由 J 造成（去掉 J 后 +0.004，通过；这是诊断性反事实，不是改动）。
3. **S+J 的边际贡献为净负**：相对 M 单独在 α_M 下，增加 10 个正例命中、26 个非正例报警（1 : 2.6）。
4. TRM-3 的 4 次"独有命中"全部是记账假象：B-M 在锚点前 1–7 token 报警而被严格规则判为 pre-onset，TRM-3 更晚落进 [onset, +8]。
   去掉 pre-onset 罚则后 TRM-3 在六个格子里全部更差（−5 / −3 / 0 / −2 / −4 / −2）。

## 2. 本轮唯一的正面信号（带选择效应警告）

单独的 S 通道（稀有专家支持集扩张）在**更低**的实测 FAR 下显著胜过融合：b2/D 上 FAR 0.069 < 0.075，+8 召回 16/42 vs 8/42，不一致对 8:0，
p = 0.0078；h384/D 上 0.064 < 0.071，22/45 vs 13/45，p = 0.0117。这是全轮仅有的两个 α=0.05 显著比较，都指向"融合有害"。
但：(a) 这是从开发集结果里蒸馏出来的，进入 v3.1 后不能再叫确认；(b) S 相对平凡的平滑 −log q 均值基线（B-S）的优势**不明确**
（S1 净增 ≤ +1，报警集合 Jaccard 0.36–0.75）。brief §9 的第一条判据"相对边际新颖度基线有明确增量"仍未满足。

## 3. 统计装置本身没有分辨力（组长的设计错误）

精确 McNemar 需要 ≥ 6 个同向不一致对才能 p < 0.05；观察到的是 4 / 0 / 1，条件检验力恒为 0。按预注册自己预测的效应（+0.11）算，
三腿同时 Go 的先验概率 0.7–1.4%，80% 检验力需要约 150 个正例（现有 42）。"净增 ≥ 3 且 p < 0.05"里的 p 条件已隐含净增 ≥ 6，
净增门是装饰性的。这套装置**不能**用于 Codex 与 Claude 的统一比较。

## 4. 其他确认的事实

- 代码 / SQL：六个格子 +8 召回 0/34；J 能看到代码但中位延迟 +36（最差 +220）；h384/D 真正"无信号"的 5 条里 4 条是代码。
- RECOVERING 在 240 条里 0 次触发：p_fused ≤ 0.25 有粘性，正例累积上百个 PROVISIONAL 端点，32 个连续高于 0.25 的端点在 384 token 内几乎不可能。
  5 条有界抵御全部 SUSTAINED（4）或 NONE（1）。时间规则需要滞回（进入阈值 ≠ 退出阈值）或有遗忘的 running max。
- 体制标志饱和（0.85–0.97），命中与漏检之差 0.003–0.027 且方向不一致：按现定义无诊断力。
- 输出契约未达：M 通道报警无 top-3 坐标（77% 的首报警为空），因为冻结的 wgm 没有坐标钩子。
- C1 列在 h384 上删失 26% 的 trace（K_cal = 185 对 384 长度），4 个正例的锚点在 K_cal 之外仍在分母里。
- 长度趋势：回退方案 B-M/C1 在 h384 最长三分位的 FAR 0.27（z = 3.86）——当前最大的出厂风险。
- 结构性未交付：S4（bucket-free）与 S6（概率通道 R_p 门）预注册了却不在冻结代码里，两份冻结审阅都没发现；evidence_onset 敏感性由审计补上
  （b2/D 13/42 vs 15/42）；E/C/X 锚点等 reviewer B。
- 误报解剖：benign 臂误报 22/48 是话题提及（约为窗口基率的 8 倍）；clean（0/14）与静默抵御（0/23）的误报不含任何题外内容，
  落在保修模板、道歉句式、地址和 JSON 上。G4 应作为硬门保留。

## 5. 决定

1. TRM-3（三通道 Bonferroni 融合）**不进入生产、不进入合并设计**。
2. 可交付的回退形态：输出契约 + 冻结 B-M 在部署侧校准（D 列）下运行，通过 G1/G2/G3/G5/G8；附代码域范围声明；G4 与长度趋势列为观察项。
3. v3.1 作为**新 proposal**（不是补丁）的必改项：单一主候选（S 主、M 对照，或单一融合统计量单一保形 p），冻结前的可达性检查
   ⌊(n+1)α_c⌋ ≥ 1，按实测 FAR 匹配对照，效应量 + 按攻击家族聚类的 bootstrap 区间取代复合 McNemar 门，冻结前做检验力计算，
   明写命中定义（pre-onset 罚则版与无罚则版共主），一个主锚点 + 声明的敏感性族，解决保形视界（B3 的 384-token 正常池或长度分层校准），
   删除或用"JSON 脚手架零假设"重定义 J，滞回式恢复规则，删除体制标志，契约与实现对齐，冻结审阅必须把每个预注册项映射到代码路径。
4. 给统一比较（brief §7）的五条事实见 `critic_trm3.md` §4；两线合并前必须先统一命中口径（pre-onset 罚则、锚点、有效预算），
   否则记账差异比算法差异大。
