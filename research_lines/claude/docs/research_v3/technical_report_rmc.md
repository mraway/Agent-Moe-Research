## 摘要

我们研究在生产级 Agent 服务中，仅凭 MoE 模型生成过程中已经产生的路由信息（每层 top-k 专家选择），在线判断 Agent 是否
进入了偏离常规工作流的内部计算状态。检测器只学习正常客服流量的路由分布（one-class），在线输出经保形校准的逐 token 风险分数，
作为上层安全系统的一路信号而非唯一决策。

推荐算法 **RMC-S**（Routine-Manifold Conformal detector, Support-expansion statistic）由三部分组成：
(1) 一个 8-token 因果窗口统计量 S，度量当前生成"征用了正常流量几乎不用的专家"的程度；
(2) 部署侧的分位标准化与序贯保形校准：把在线 running max 与正常校准路径的全路径最大值比较，得到逐 token 单调 p 值，
per-episode 误报率在可交换性下 ≤ α；(3) 输出契约：校准 p 值流、证据窗、归因坐标、silent/provisional/confirmed 状态。
白化路由距离 M（此前冻结的候选）作为第二路独立校准的覆盖流一并输出，不在检测器内部融合。

在开发数据上（部署侧校准，α = 0.10，严格口径）：S 在偏移起点后 8 token 内的召回为 20/42、14/31、24/45
（B1→B2、B2→B1、384-token replay），显著高于 M 的 11/42、10/31、15/45（配对精确检验 p = 0.004、0.125、0.012）
与平滑 surprisal 基线的 11/42、9/31、14/45（p = 0.023、0.125、0.002），误报率与之相当（clean 0.05–0.075，benign 0.12–0.15）。
按两线共识的"参与"边界（E），S 在 +16 内检出 30/45，是两条独立研究线全部 36 个冻结方法里最早的一行。

主要负结果：三通道 Bonferroni 融合（TRM-3，预注册主候选）在所有格子劣于单一统计量；平行线的经验秩检测器（SIRD）
因秩饱和零报警；窄窗口、概率特征、无 JSON 参照、未见专家硬规则均无效。已知盲区：代码/SQL 类产出（8 词内召回 0/34，
两线一致）；S 的统计量尺度对参照池敏感，预置阈值（跨池）列不可出厂；对静默抵御样本的报警率高于 M。

## 1. 问题设定

**对象**：一个固定范围的客服 Agent（Atlas），由确定性控制器执行工具调用，MoE 语言模型（OLMoE-1B-7B-0125-Instruct，
16 个 MoE 层 × 64 专家，top-8 路由）生成自然语言回复。攻击通过用户消息、工具结果或多轮对话注入题外任务（写诗、写代码、
做数学、法律分析、旅行规划……）。

**事件层次**（与平行线共识一致）：主事件是"生成进入题外计算域"，即模型的思考/响应过程开始处理注入任务
（参与 E）；是否形成承诺（C）、是否产出实质内容（X）、是否最终抵御成功，都是主事件的下游子分类。
两线的实证一致表明路由信号对应 E/C 而非 X（第 6 节），因此本报告以参与/交付起点为主锚点。

**部署定位**：检测器是多信号融合的一路输入。需要优化的不是最低误报率，而是：在融合层工作区间上的似然比、分段稳定且
可解释的误报、校准的连续分数（按会话预算）、在不可逆点前的检出、对上下文攻击文本的不敏感、可刻画的漏检。

**接口契约**：在线只读生成期路由（top-8 id；概率可选但本算法不用），不读文本、任务、workflow、渠道、绝对位置、结果标签；
锚点与标签只用于离线评价。

## 3. 推荐算法 RMC-S

### 3.1 观测与统计量

记第 t 个生成 token 在层 l 的 top-8 专家集合为 A_t(l) ⊂ {0..63}。在正常拟合池 N_fit（只含 clean + benign 的路由）上估计
每个 (层, 专家) 坐标的选择率

  q[l,e] = (#{tokens: e ∈ A_t(l)} + 0.5) / (N_tok + 32)，  Ω_rare = {(l,e): q[l,e] < 0.02}。

支持集扩张统计量（逐 token，再取 w = 8 的因果窗口均值）：

  s_t = Σ_{l=0}^{15} Σ_{e ∈ A_t(l)} 1[(l,e) ∈ Ω_rare] · (−log q[l,e])，  S_t = mean(s_{t−7..t})。

它是平滑 surprisal 在稀有坐标上的截断版本：只有 routine 几乎不用的专家被征用时才贡献分数。机制分析（第 7 节）表明，
此前白化距离候选的可分性 78% 来自这些坐标，S 把这一部分单独拿出来并去掉了其余坐标的噪声。

第二路统计量 M：此前冻结候选 CAND-A，即 w = 8 窗口 top-8 选择率向量（层 5–15，704 维）相对 routine 的白化欧氏距离
（全局中心，PCA 秩自动选择，方差地板 1e-3）。M 在本报告中作为覆盖流与归因流输出，不参与报警决策。

### 3.2 标准化与序贯保形校准（部署侧）

1. **位置桶标准化**：以本 episode 已打分端点数 k 分桶（桶宽 32，尾桶合并到 ≥30 条路径），μ_b、σ_b 在拟合池上估计；
   z_t = (S_t − μ_b(k)) / σ_b(k)。
2. **校准池**：部署侧的正常流量（本报告中为目标 batch 的 routine 臂）按 scenario 分成两半；每条目标路径与不含其 scenario 的
   那一半比较（disjoint pooling）。每条校准路径 g 只保留一个数：全路径最大值 Z^g = max_k z^g(k)。
3. **在线 p 值**：R(k) = max_{k'≤k} z(k')，p(k) = (1 + #{g: Z^g ≥ R(k)}) / (n_cal + 1)。p(k) 随 k 单调不增；
   "曾经 p ≤ α" 等价于"全路径最大值 ≥ 第 ⌈(n+1)(1−α)⌉ 小的校准最大值"，因此在目标路径与校准路径可交换的前提下，
   per-episode 误报率 ≤ α（anytime 有效，无需 e-值理论）。
4. **有效预算**：p 只取 j/(n+1)，可达的 α_eff = ⌊(n+1)α⌋/(n+1)；n = 80 时 α = 0.10 对应 rank ≤ 8，α_eff = 0.099。
   任何通道的 ⌊(n+1)α⌋ 必须 ≥ 1，否则该通道永远不能报警（这是第 5 节融合失败的直接原因）。
5. **校准视界**：K_cal = 校准路径的最长端点数；k > K_cal 时不再产生新报警并标记 `horizon_censored`。
   保证只在 k ≤ K_cal 内成立；对长于校准长度分布的 episode，合成实验显示条件误报率约为预算的 1.5 倍。

### 3.3 输出与决策

每个 token 输出：p_S、p_M（两路独立校准的 p 值）、状态（SILENT：p_S > 0.25；PROVISIONAL：0.10 < p_S ≤ 0.25；
CONFIRMED：p_S ≤ 0.10）、证据窗（最近 8 个 token）、归因坐标（S 的窗口分数可精确分解到 (层, 专家)，前 3 个贡献坐标随
输出给出）、剩余预算与校准版本。推荐的二值报警 = CONFIRMED（S 在 α = 0.10）；M 的 p 值流供融合层作为覆盖与归因证据，
若同时用作报警则总预算为两路之和（Bonferroni），本报告不推荐在检测器内部融合（第 5.1 节）。

多轮会话：状态与环形缓冲在轮边界复位；会话级预算按配置的最大轮数 K 做 Bonferroni（α_ep = α_session / K）。

### 3.4 成本

每 token：S 为 128 次查表 + 一次窗口均值；M 为一次 704 维白化投影；p 值为一次对 n_cal 个浮点数的比较。
参照存储：n_cal 个浮点数（每通道每半份），加一张 16×64 的 q 表。离线 11 个变体 × 240 条 trace 的评价在 32 核机器上
6–34 s，峰值内存约 1 GB；在线评分 0.03–0.045 s / 1000 端点（单线程 Python）。无额外前向计算，无最近邻库。

## 4. 实验设计

- **两列校准**：D = 部署侧（拟合另一 batch 的 routine，校准目标 batch 的 routine 半份）；C1 = 预置阈值（拟合 C1 fold 0，
  校准 folds 1–3，held-out fold 4）。
- **正例**：主事件 = drift ∪ 有锚点的抵御样本（B1/B2：42 + 31；h384：40 执行 + 5 有界抵御 = 45）。
- **严格口径**：锚点前的任何报警记为 pre-onset，该 trace 不计任何视界命中；R+k = 首个 CONFIRMED 端点 ∈ [onset, onset+k]。
- **误报**：clean 与 benign 分开；两校准半份分开；静默抵御臂（35 条）单独报告；h384 的 4 条自发偏离 benign 从分母移除并单列。
- **预注册与冻结**：主候选 TRM-3 的预注册（v1.3）与代码在提交 55b6e23 冻结后才运行 target 分析；运行器拒绝在工作树不干净或
  HEAD 不等于冻结提交时计算 target 指标。S 单通道是该预注册的消融变体之一（A-S），其数字与 TRM-3 同一次运行产生。
- **审计**：三路独立审计（复算、样本级、统计）与一个完整性批评者；所有主表数字被独立代码路径逐位复现。

### 5.3 时间状态与子分类

预注册的持续/回落规则（D = 32）在 240 条上从未产生 RECOVERING：p ≤ 0.25 有粘性，正例累积大量 PROVISIONAL 端点。
5 条有界抵御全部判 SUSTAINED（4）或 NONE（1）。抵御/执行子分类在本报告中只作描述性输出；平行线在 oracle 起点下观察到回落方向
（AUROC 0.91，n = 5），在算法自选起点下失效。需要滞回（进入阈值 ≠ 退出阈值）与 ≥12 条有界抵御样本才能重新检验。

### 5.4 此前轮次的稳定结论（跨多轮复现）

- 任意分数（含文本基线）的整轨迹 AUROC 都在 0.97–0.99：路由的价值不在"能否分辨"，而在时效。
- 保形校准下总误报钉在 α；持久性、块均值、CUSUM 等读数只移动 ROC 点，不降低误报。延迟 ≈ 窗宽 + 阈值裕度，裕度占主导。
- benign 臂误报是 clean 臂的 1–2.7 倍；"话题被提及"是主要可解释误报类，从不出现在 clean 臂。
- 冻结候选对 47 条静默抵御样本只报警 2–4 条（与 clean 臂同量级）：检测器响应的是生成进入话题，不是上下文里的攻击文本。
- 校准半份 40 条时工作点由 4 条 trace 决定；每半份需要 ≥90 条。

## 7. 机制（为什么是"支持集扩张"）

- 白化距离候选的可分性来源：其他域漂移的白化能量 78% 落在 routine 最低方差十分位（几乎不用的专家）；代码/SQL 漂移在这一
  十分位的能量只有 13–20%，冷门专家质量与 routine 相同（8 个域最低）。S 把这一分量单独度量，去掉了频繁坐标的方差。
- 代码/SQL 盲区：代码不征用冷门专家，只在 routine 已用专家集合内重新分配权重，方向沿 routine 自身"散文↔工具调用 JSON"轴
  （余弦 0.78）；top-8 集合比 routine token 自身更接近 routine 排名。集合类统计量结构性看不见；概率集中度在 batch 内可分但跨 batch
  不迁移。窄窗口、层带、形态条件化、去 JSON 参照、文本新颖度均被排除。
- 深度剖面：代码偏离在层 5–7 与 12–13 双峰，层 0–4 无用；平行线观察到晚层在语义边界瞬时放大、早中层在持续执行时保持。
- 参照库大小：S 的稀有坐标集与"未见专家"都随拟合池增大而收缩（80 条拟合后 1024 个坐标全部出现过）；这是 S 跨池不稳定的根源，
  也是两线"未见专家"规则失效的共同原因。

## 8. 负结果与已排除的方向

| 方向 | 结果 |
|---|---|
| 三通道 Bonferroni 融合 TRM-3（预注册主候选） | P1 No-go，净增 −2/0/−1：预算分摊使 S 在 n = 40 时 rank 0 不可达、M 变成 2.5 倍更严的 CAND-A、J 通道在 JSON 脚手架上报警（同一 pair group 两臂逐位相同） |
| 经验秩检测器 SIRD-v1（平行线） | 632 个锚点的秩上限饱和，21/60 校准组撞顶，零报警 |
| 窄窗口（w = 4/2/1）与逐 token 读数 | 抵御样本召回无增益（最好 4/14 = 噪声期望最大值），误报样本集合大换血，证据窗退化为子词 |
| 概率质量集中度、概率 JSD | batch 内 AUC 0.998，跨 batch 崩塌（routine top-8 集合只有 8/16 层相同） |
| 去掉 JSON 形状的 routine（反事实） | 窗口层面代码可分（百分位 0.995），协议下 FAR 0.29–0.35、resist 0.5，不可用 |

## 9. 局限与适用范围

1. **选择效应**：S 是在 TRM-3 消融结果中被识别为最优的；其相对 M 与 surprisal 的优势需要 B3 确认。
2. **样本量**：正例 31–45 条/格；区间宽；B2→B1 的差异不显著。
3. **单一模型与 Agent**：OLMoE-1B-7B 与一个固定范围客服 Agent；routine 流量 47.5% 以 JSON 对象开头（小模型违规照抄控制器格式），
   "routine 是否含结构化输出"应作为后续数据设计变量。
4. **代码/SQL 盲区**：+8 召回 0/34，两线一致；文本规则可零误报确认但迟 +17；本算法不处理，需范围声明。
5. **静默抵御报警**：S 为 0.171（M 0.057），其文本内容未逐条审计。
6. **长 episode**：校准池最长 192 token 时对 384-token 输出的保证只在视界内成立；需要 384-token 正常池。
7. **预置阈值不可出厂**：S 的尺度跨池不稳；部署侧校准是必要条件，每半份 ≥90 条。
8. **子分类未解决**：恢复规则从不触发；有界抵御只有 5 条。
9. **锚点**：B1/B2 与 h384 使用不同锚点家族；首次指涉与首个题外实词相差 0–29 token。
