基于 MoE 路由的 Agent 任务偏移在线检测

当一个客服 Agent 被诱导去写代码、写诗或做法律分析时，模型内部会先"换一批专家"来算，然后才在文本里露出痕迹。我们只用这份推理时免费产生的路由记录，在偏移刚开始时给出经校准的风险信号。

当前模型 OLMoE-1B-7B（16 层 × 64 专家，每 token 选 8 个） 下一模型 gpt-oss-20b（24 层 × 32 专家，选 4 个） 证据等级 开发数据，未做封存确认

01问题定义

Agent 服务把大模型放进"读输入、调工具、写回复"的循环里。攻击者可以通过用户消息、工具返回值或多轮对话把题外任务塞进来。我们关心的不是"输入里有没有攻击文本"，而是模型有没有真的开始做那件事，并且要在它做完之前知道。

MoE 模型每生成一个 token，每一层都要从几十个专家里挑几个来算。这个选择记录（路由）在推理时已经存在，读取它不需要额外计算，也不需要读文本。问题于是变成：只看路由，能否在线、及时、可校准地判断生成是否进入了题外计算？检测器的定位是安全系统里的一路信号，不是唯一决策。

02潜在的创新点

路由轨迹作为 Agent 偏移信号
没有先前工作把 MoE 专家路由用于 Agent 任务偏移的在线检测。最近的工作要么用稠密模型的激活（TaskTracker，单轮提示），要么用路由做有害提示审计（RouteScan，预填充阶段）。我们看的是生成阶段、逐 token、跨多步工具调用的路由轨迹。
只学正常流量，误报有保证
检测器只从正常客服流量学习一个"常规流形"，不需要攻击样本训练。阈值用序贯保形校准给出：在可交换性下，每个 episode 的误报率不超过预算，且可以随时读取，无需额外前向计算。
以"及时性"而非 AUROC 为主指标
整条轨迹看完后几乎任何分数都能分辨偏移（AUROC 0.97 到 0.99）。真正有价值的是偏移起点后 8 或 16 个 token 内能否报警，锚点前的报警按严格口径算漏检。这一评价协议本身是贡献之一。
机制解释：支持集扩张 vs 支持集内重加权
多数题外任务会征用正常流量几乎不用的专家（支持集扩张），代码类任务却只在常用专家里重新分配权重。这个发现同时解释了算法为什么有效、盲区在哪，以及下一步该测什么。

03已有的发现

在 OLMoE 上的一个固定范围客服 Agent 与 920 条轨迹（正常、对照、攻击三臂，锚点由两位标注者互盲标注）上，经过多轮实验与三路独立审计，以下结论跨轮次稳定：

路由跟踪的是"开始想"，不是"写出来"
两条独立研究线一致：路由信号对应 E 和 C，不对应 X。以产出为锚点看到的"提前报警"，几乎全部落在同一条轨迹的参与起点之后。
价值在早，不在分辨
整轨迹 AUROC 对任何分数都接近 1；差别只出现在起点后的前 8 到 16 个 token。延迟约等于窗口宽度加阈值裕度，裕度占主导。
误报被校准钉在预算上
保形校准下总误报等于预算；持久性、块均值、CUSUM 只移动 ROC 点。"上下文里提到了题外话题"是主要的可解释误报类，从不出现在纯正常臂。
阈值必须在部署环境校准
用另一批正常流量预先定好的阈值在新环境上误报升到 0.13 到 0.28。每个校准半份需要 90 条以上正常轨迹，40 条时工作点由 4 条轨迹决定。
代码 / SQL 是结构性盲区
代码类偏移不征用冷门专家，只沿正常流量自己的"散文到工具调用 JSON"轴重新分配权重。任何只看"选没选"的统计量都看不见它。
权重携带额外信息，但尾更重
0/1 选择丢掉的那部分权重方差正是分开代码的部分（AUC 0.96 对 0.77），但它的跨池极值尾是选择量的 2 到 3 倍，在小校准池下换不来及时性。

对生产系统的含义：作为多信号融合的一路输入，它提供的是早期、可校准、可归因到具体专家坐标的证据。已知边界写得出来：代码 / SQL 类产出需要另一路信号（一条零误报的文本规则能确认，但平均迟 17 个 token）；阈值必须用部署环境自己的正常流量校准。

05未来的工作

当前证据来自单一小模型、单一 Agent、每格 31 到 45 条正例的开发数据，且工具由控制器执行，模型从不真正做出不可逆动作。下一阶段的目标是把"选哪个算法"建立在封存证据上，并把不可逆动作变成真实事件。

  • 已完成换到 gpt-oss-20b，重建 Agent v3。模型自主调用工具（受限工具作为不可逆动作的桩），推理通道可见，"想歪但没做"可测。
  • 已完成正常池 600 条，全部盲态标注。过滤通过率 94.5%，全部无题外参与；校准视界 H 按规则冻结在 352 个窗口端点（约 380 token）。
  • 进行中攻击集 G-dev 生成。144 场景 × 三臂加 120 条补充，三种注入渠道、三档措辞、代码域单列配额；随后两位互盲标注者标 E/C/X 与恢复片段。
  • 计划预注册 v3.1 与封存确认。单一主格（S 对 M 对 surprisal，参与起点 +16），实测误报匹配，按场景聚类的 bootstrap；720 条确认集只解封一次。
  • 计划代码盲区的补充臂。把权重感知统计量（集合内残差质量、逐层分布散度）作为固定额外误报预算下的 OR 臂预注册，入门条件是 +16 内有非零召回。
  • 计划外部效度与隐状态基线。在 tau2-bench 客服环境上移植现成攻击集做第二条工作负载线；实现 TaskTracker 风格的残差探针作为上界基线。
