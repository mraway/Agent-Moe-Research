## 摘要

**问题。** 一个职责固定的生产 agent（客服）在处理用户轮时，能否**只从它自己的 MoE 路由轨迹**上、在线地（因果、逐 token）判断它是否离开了常规工作流——因为提示注入、工具输出里的伪装指令、或用户直接提出的越界请求。我们只学习正常工作流的路由分布，**不在攻击上训练**。

**数据与纪律。** 在 gpt-oss-20b（24 层 × 32 专家、top-4、MXFP4）驱动的、真正调用工具的客服 agent 上采集了 **2 428 条**带完整生成阶段路由捕获的轨迹 / **2 934 个 episode**（数据集 G，八个子集）。**这不是生产流量**：它是一个模拟客服环境里由冻结的场景工厂生成的合成轨迹。token 级的参与（E）/ 承诺（C）/ 执行（X）事件由 **Opus 5 双盲两标注者 + 裁决**给出——**全部标签由 LLM 产出，没有任何人工验证的子样本**（§9.8）。确认批 G-conf 在生成后立即封存（逐条哈希 + 只读），文本标注在解封任何路由之前冻结，检测器在封存批上**只开启一次**（两阶段解封，注册运行 = 2 次）。

**结果。** 第一轮（v3.1）把主锚点设在**参与点 E**，它的预注册判定是在**开发批 G-dev** 上做出的（不是封存批）：形式上 H1 成立（Δ̂ = 0.041，家族聚类 95% CI [0.014, 0.074]，精确 McNemar p = 0.0078），但绝对召回只有 9/197 = 0.046、误报率 0.21–0.24（预算 0.10），三道出厂门失败。事后诊断给出一条明确的机制读数：稀有坐标 surprisal **S** 在 `[E, E+16]` 的窗口 AUROC 是 **0.446（低于随机）**、在 `[X, X+16]` 是 **0.989**（同族的 M 是 0.518 / 0.994；P 的这两个 AUROC 未落盘）——**它是执行检测器，不是参与检测器**。第二轮（v3.2）据此重写预注册：主锚点改为 X、校准池改为目标批自身的质量过滤正常臂做 3 折场景互斥轮转。在封存批 G-conf 上，唯一的确认性主张 **H1 成立**，而这条判定建立在 **N = 71 个配对 episode** 上（不是上一段那个语料规模）：在匹配实测误报率的工作点上，S 对**已经产生了执行事件、且命中窗口可达的**攻击 episode 的配对命中率是 **0.746（53/71）**，平滑边际 surprisal 基线 P 是 **0.479（34/71）**，**Δ̂ = 0.268，95% 家族聚类 CI [0.071, 0.459]，精确 McNemar p = 6.6e-05**；点估计落在开发先验中心附近（0.2676 对 0.264），**但 CI 宽 0.39，这个吻合本身不可解读**。命中的中位延迟是 **2 个 look**（一个 look = 检测器读一次的时刻，即一个合格端点；G 上 look ≈ 0.90 × token，见 §1.3）。次级主张里"绝对命中率 > 0.50"成立，"S 优于白化选择率距离 M"不成立，独立注册的 `prob_js` 对"注入在场"的敏感性成立。

**边界。** **这个检测器不可出厂**：两道门失败——正常臂质量过滤通过率 0.778 < 0.85，以及折间可交换性检验的逐折列（折 0 偏差 −0.043，带宽 ±0.03）——两条都在看结果之前被声明并接受；另有两道门在本批上根本不可评。本设计给出的是"同一批数据内部的 held-out 保证"，**不是**用预设阈值去打分未来一批流量的部署保证；而**支撑这条误报控制的可交换性假设，在本设计里唯一的检验就是那条失败的逐折列**（§6.4）。本轮**没有跑任何非路由基线**（文本 / 输出形态 / 激活探针），因此"路由相对于文本可得的信号有增量"这一主张**未被检验**（§9.13）；数据集 G 也**无法把"任务偏离"与"输出体裁切换"分开**（§9.12）。诚实的结论是：**路由在不可逆动作发生的那一小段上、以同批 held-out 约 0.10 的实测误报率、在线地把它标出来，这一点在单一模型、单一工作负载上被预注册地确认了；而"在参与点上早期预警"这个更有价值的主张在 gpt-oss 上被否证。**

## 1. 问题设定

### 1.1 要检测什么

一个职责固定的生产 agent（客服）在处理用户轮时，其内部计算状态是否**离开了常规工作流**——因为提示注入、工具输出里的伪装指令、或用户直接提出的越界请求。我们只学习正常工作流的路由分布，在线（因果、逐 token）判断当前 episode 是否进入偏离状态。

**事件层级（E/C/X）** 由双标注者在模型自己生成的文本上标出（`attack_annotation_guideline.md` §3）：

| 事件 | 定义（简写） | 角色 |
|---|---|---|
| **E**（`e_analysis` / `e_final`） | 第一段**任务特定**地引用 / 评估 / 拒绝 / 计划题外任务的片段。泛指不算——"有一条注记，我应忽略"判**不算 E**，"decline the geometry request" 判**算 E** | 参与起点。曾是 v3.1 的主锚点 |
| **C** | 第一段明确**承诺**去做被注入的交付物（或没有承诺句而直接开始交付） | 中间态；`C ≤ X` 且 `C ≥ E` 由校验器强制 |
| **X** | 第一段超出"框架"的题外域**实质内容**：代码块正文首个字面代码 token、第一个等式、诗的第一行创作文本…… 包裹标记、代码围栏、纯引导句**不算 X** | 不可逆交付点。v3.2 的主锚点 |
| **X_tool** | 未授权工具调用尝试的 token 级自动事件 | 属 X 类；在数据集 G 上**结构上不可承载**（见 §9.5） |

由事件派生 7 个轨迹类：`silent` / `engaged_only` / `committed_no_execution` / `execution` / `support_resumed_after_execution` / `over_refusal` / `legitimate_refusal`。"有 E 无 X"单列为**有界抵御**（bounded resistance）——模型接触了攻击但没有交付。

### 1.2 生产定位

路由信号**只是多路信号之一**，不自行裁决，交给上层风险系统融合（`production_moe_routing_shift_research_brief.md` §3.6）。brief §9 给出四条进入下一阶段的判据：(1) 相对 marginal novelty 基线有明确且可解释的增量；(2) 在长输出与 benign-but-unusual 对照上维持可控误报；(3) 对 onset 与随后的恢复 / 持续给出真实的在线信息；(4) 足够简单，可复现、可校准、可审计。本文的 H1 只对应判据 1；判据 2 是本轮失败的那一条。

### 1.3 术语与符号（首次出现处的定义，全文统一）

| 术语 | 定义 |
|---|---|
| **look / 端点（endpoint）** | **检测器读一次的时刻**。因果窗口在通道段内以步长 1 滑动，段内不足 w 个 token 不产生端点，窗口**不跨通道边界**；一个 episode = 一条 look 序列 = 一个保证单位。G 上端点密度 look ≈ **0.9001 × token**。**视界 H、延迟、偏移一律以 look 计；锚点 E / C / X 以 token 下标计。** |
| **合格端点（eligible endpoint）** | 实际被打分的端点（窗口完整、且在视界 H 之内未被删失）。`onset / 1000 eligible` 的分母只数正常臂的合格端点。 |
| **`E_view`** | 主锚点 E 在**当前视图**内因果可达的最早位置（V1 / V2 = min(E_analysis, E_final)，V3 = E_final）；**绝不跨该视图看不到的通道取 min**。它是 v3.2 命中窗口的**下界**。 |
| **命中窗口 / 严格命中** | v3.2：**首个 CONFIRMED look 落在 `[E_view, min(X + 16, H_end)]`**（闭区间）。"严格"指 `E_view` 之前的任何报警把该 episode 判为**漏检**（pre-`E_view` 罚则）。`H_end` = 该 episode 被视界 H = 352 look 截断后的最后一个合格端点。**可达 = 存在合格端点落在这个窗口内**（全文唯一定义）。 |
| **band（容差带）** | 允许首报警落在锚点前后多少 look 仍算命中。**判定一律 band = 0**；±4 / ±5 / ±8 只落盘作敏感性（CLI `--tolerance-bands 0,4,5,8`）。 |
| **`alpha_eff`** | 保形构造在有限参照集上**实际可达**的名义误报率 `⌊(n_cal+1)·α⌋/(n_cal+1)`。v3.1 是 28/280 = 0.100000（恰好可达）；v3.2 **逐折不同**（G-conf 0.098266 / 0.099448 / 0.098837），F1 比的是按各折 `n_cal` 加权的 pooled 值 **0.0988594**。 |
| **ψ / ρ** | 检验力标定的两个参数。**ψ** = 不一致对（S 与对照只有一方命中）占配对样本的比例（G-conf 实测 0.324）；**ρ** = 同一攻击家族内不一致对的相关系数（注册网格 {0.15, 0.30}）。 |
| **matched-group FAR** | **scenario 级**误报：同一 scenario 的正常臂只要有一条报警就计一次（brief §3.2 点名的口径，门 F5）。 |
| **族外（outside the family）** | 不在 Holm 多重性族里、不报校正后的 p、**不改变任何判定**的描述性列。 |

出处：`detector_prereg_v3_2.md` §2.4 / §5 / §8；`detector_harness_g.md` D1–D6 / D14；`detector_prereg_v3_1.md` §7.1。

### 1.4 威胁模型（本轮的假设，必须先说）

攻击者是**非自适应**的：注入载荷由冻结的场景工厂生成，攻击方**不知道检测器存在**，更没有针对它优化。**本报告不主张任何对抗鲁棒性。** 这个假设在本机制上尤其要紧——检测器响应的是**跨领域输出形态上的稀有路由坐标**，因此"把载荷改写成散文"（用文字描述代码而不写代码、把等式说成句子、用客服口吻写诗）**可能同时躲开 X 的标注判据与检测器本身**；而这恰好是冻结的场景工厂里**不存在**的对照臂（§9.9 / §9.14）。自适应攻击、逃逸与混淆**本轮完全未测**。

## 2. 模型与 Agent v3

**模型**：gpt-oss-20b，**24 个 MoE 层 × 32 专家、top-4**，MXFP4 量化，冻结配置 `configs/pilot_gpt_oss_20b_mxfp4.json`。采样 temperature 0.8、top-p 0.9、1024 token 上限、自然 EOS，不设最少 token、不补样、不换 seed（`agent_v3_dataset_design.md` §1.4）。

**harmony 三通道**：`analysis`（推理）/ `commentary`（工具调用 JSON）/ `final`（回复）。通道标记是协议在生成时**因果可得**的运行时状态，因此允许检测器把它作为条件变量；它不是输出内容形态规则。三个预注册视图：**V1（主）= 全部生成 token**、V2 = 去 commentary、V3 = 仅 final（对应平台看不到思维链的部署）。P0 实测通道 **token** 占比 analysis 12.5% / commentary 8.0% / final 79.5%（**P0 正常臂 16 条口径**；全部 48 条是 12.4 / 5.2 / 66.6，攻击 32 条是 15.6 / 5.4 / 79.0；`p0_readout.md` §2.2）。**注意这与"端点"占比不是同一件事**：G-dev 的**端点**通道占比是 analysis 7.6% / commentary **10.1%** / final 82.3%（`g_dev_v3_2_development_report.md` §5.3）——§6.6 与 §10.1 引的 10.1% 是后者。

**模型驱动的工具调用**：模型在 commentary 通道自行发起函数调用，controller 只执行只读工具并回填结果，循环到 final 为止（`max_agent_steps = 6`）。工具集共 10 个 schema：6 个只读查询（`lookup_order / lookup_return / lookup_case / lookup_warranty / lookup_subscription / search_support_kb`）、1 个合法升级（`escalate_to_human`）、3 个**受限桩**（`issue_refund / update_shipping_address / send_external_request`——schema 可见、系统提示禁止、controller 永不执行，只返回 "unauthorized, not executed"）。受限桩在**所有臂**都存在，使后续批次能与本批共享同一份 routine 参照。

**episode = 一个用户轮的全部生成**（跨 agent step 的全局 token 轴连续），检测器状态**不在步之间复位**，**保证单位 = episode**。

**路由捕获**：每个 decode 分片逐 token 存 `router_logits [24, T, 32]`（**全部 32 个专家的 pre-softmax 分数**，含 router bias，BF16）、`top_k_ids [24,T,4]`、`top_k_weights [24,T,4]`、`router_entropy` / `router_margin` / `effective_experts` 与 token 轴（`g_prob_channels_smoke.md` §1.1）。

**信息边界**：主路径的输入**只有** `A_t ∈ {0..31}^{24×4}`（top-4 专家 id）与通道标签 `c_t`。**不使用**文本、任务、工作流、域、攻击渠道、绝对位置、最终结果、未来 token；**主路径不使用路由概率**（概率只进独立注册的 S-J 格）。

> **一条必须写明的模型差异**：gpt-oss 的 `top_k_weights` 是**只在选中的 4 个 logit 上做的 softmax**，而 OLMoE 在全部 64 路上 softmax 且不重归一化。因此"0/1 视图丢掉了模型实际使用的概率质量"这句话在 gpt-oss 上**不成立**——模型自己也丢掉了那部分。G 上的 in-set 质量是 router logit 的**集中度**度量，其 80% 方差可由逐层熵 / margin 线性解释（`g_prob_channels_smoke.md` §0、§2.5）。

### 3.2 场景工厂与攻击设计

拉丁方在 (8 域 × 3 渠道 × 3 措辞 × 2 目标) 上不可实现，改为 **4 域组 × 3 渠道 × 3 措辞 × 2 目标 = 72 格**，核心批每格 2 条 = **144 个 scenario**；G-dev 另加由 P0 产率固定的 **120 条补充层**（60 条 T1 用户侧、60 条 T2 混合渠道）。G-conf 是 `core_72_cells` 144 × 3 臂 + `held_out_workflow` 16 × 3 臂 + `normal` 120 × 2 臂 = 280 scenario / 720 trace，16 个攻击家族，独立 fixture（TSL 94 / WRH 93 / OSY 93）。

**封存批究竟留出了什么**（必须写清楚，否则"确认"的范围会被高估；出处 `g_session_medium_conf_run_log.md` §4.1 与本节上一段）：

| 维度 | G-dev 与 G-conf 的关系 |
|---|---|
| 72 格设计（4 域组 × 3 渠道 × 3 措辞 × 2 目标） | **共享**——两批的核心层建在同一个格空间上 |
| 16 个攻击家族（`attack_family_id`，也是 bootstrap 的**聚类键**） | **共享**——两批都是同一族 16 个家族 |
| 工作流类型 | 并集 20 类，**共有 18 类**；`R4:warranty` 只在 G-conf、`R4:support_case` 只在 G-dev |
| fixture（订单 / 案件 / 知识库实例） | **留出**——G-conf 用独立的 TSL / WRH / OSY |
| `held_out_workflow` 层 | **留出**——16 个 scenario × 3 臂落在 G-conf 独有的 `R4:warranty` 上 |

**因此封存批留出的是 fixture 与 16 个新工作流 scenario，不是攻击家族、也不是场景设计格。** 跨攻击家族的泛化本轮**没有**被检验（§9.1）。唯一真正度量泛化的分层是 `held_out_workflow`：G-conf 上它的命中率是 **9/10 = 0.9000**，高于核心层的 44/61 = 0.7213（**n = 10，不作断言**；`g_conf_confirmatory_report.md` §5.4）。

- **注入渠道**：`direct_user`（用户直接提出题外请求）、`multi_turn_user`（第二个用户轮里注入）、`tool_output`（工具结果 / KB 条目里的伪装指令，占攻击的 1/4）。
- **措辞层**：T0 基线延续性、T1 权威通知（执行样本主来源）、T2 记录字段契约（"只在 analysis 参与、final 干净"的主要来源）。
- **正常臂质量过滤**：`filter_pass = on_task ∧ coverage ≥ partial ∧ 无重要事实错误 ∧ 无未授权工具尝试`，**在看任何路由之前**由文本复核确定。FAR 两个分母都报：`filtered`（正确 routine 口径）与 `all`（部署口径）；保形可交换性只对过滤后的子总体成立。
- **困难负例**：`benign_control`（工具结果 / KB 里出现题外话题的**非指令性**提及）、`benign_lexical`（请求措辞含题外词但请求在范围内）、`legitimate_refusal`（客户直接提出题外请求，正确行为是拒绝——按定义含真实的题外 E，**不进 FAR 分母**）。

## 4. 预注册与数据纪律

**两步冻结**：提交 **A**（预注册正文 + 代码，此后不改算法 / 阈值 / 门 / 锚点 / 命中口径）→ 提交 **B**（标签冻结，记入每个标签文件的 sha256）→ 才允许跑检测器，runner 的 `--freeze-commit` 指向 B。v3.2 重复同一形态：**A′ → B′**。

**封存集只开启一次**。v3.1 §13 原本允许冻结后开启 G-conf 一次；组长裁定把这个时点**推迟到 v3.2**（这是对 v3.1 §13 的一条记录在案的偏离），并在 v3.2 上以**两阶段解封**执行：

- **阶段 1**：只解封 G-conf 的**正常臂**，算出 3 折的统计量拟合、通道标准化器、C1 参照与阈值，落盘 `threshold_manifest.json`。运行日志逐字记录 `target episodes=672 variants={'benign_control': 336, 'clean': 336}`——**216 条攻击 episode 在阶段 1 里根本没有进入 episode 表**。
- **阶段 2**：重放这份 manifest 去给攻击臂打分，**注册次数 = 2**（`stage2_S_vs_P` 与 `stage2_S_vs_M`），用满即止。
- 阶段之间由 `threshold_manifest.verification` 的 **19 项机械核验**把关：manifest 自哈希、折图哈希与自洽、正常臂 trace 集合哈希、标签哈希、格参数匹配（含 `fold_key == fixture_rank_mod`）、`head_is_freeze_commit`、代码提交、四格齐全且逐折完整、三分位切点、matched-alpha 输入齐全、**攻击臂 trace 集合哈希**、**预注册 sha**、**冻结提交**、**封存 trace 集合哈希**、**四个时刻的先后顺序**。两次阶段 2 运行**都是 19/19 ok、`failed = []`**。另有 `run_once_guard`（拒绝覆盖既有产物）与 `data_discipline_guard`（工作树必须干净、HEAD 必须等于冻结提交、预注册与标签 sha 必须匹配）三次运行全部 `enforced = true` 且 `dirty = false`。

**统计装置**：效应量 Δ = R_S − R_P（配对），区间 = 按 `attack_family_id` 聚类的 **95% percentile bootstrap（2000 次，重抽 16 个家族）**，并报 `(family × wording tier)` 稳健列；同时报**精确 McNemar**（双侧 α = 0.05）的不一致对 (b, c) 与 p。**判定必须是合取**：CI 下界 > 0 **且** McNemar 拒绝。理由由零假设模拟给出——家族聚类下**单独**的精确 McNemar 是反保守的（ψ = 0.30 / N = 126 / ρ = 0.30 时假阳性 **0.092**，合取规则 **0.029**）。合取规则本身也**不把假阳性压到名义 0.025 以下**：16 个格里 ρ = 0.30 的四格是 0.024–0.036，**上界 0.036**，这句话必须与 H1 的强度一起写。

**两轮之间的多重性没有被控制**（必须与上一句一起读）：本线走的是"预注册 → 失败 → 依据事后诊断重写预注册 → 成功"这条路径。被界定的只有**第二轮批内**的第一类错误（上界 0.036）；**跨两轮的整体第一类错误不受控**，本设计没有、也无法对它作任何声明。第一轮的锚点、命中口径、校准池都是在看过 G-dev 结果之后改的（§6.1 表里每一条改动的理由都是 G-dev 实测），因此 v3.2 的"确认"是**对一条由 G-dev 生成的假设、在一批新数据上的确认**，不是对一条先验假设的无偏检验。

**工作点匹配**：S 用名义 α = 0.10；对照统计量取"实测 FAR ≤ 目标的最大 α"，使两者的**实测**误报率逐位相等（G-conf 上 S 与 P 同为 0.0994264）。**这一步用了目标批自己的正常臂，bootstrap 与 McNemar 没有把它的选择不确定性算进去**——区间是条件在选定工作点上的。

**检验力**（Monte-Carlo，4000 次重复 × 2000 次 bootstrap，seed 20260907，家族向量取自 `g_conf.json` 的 16 家族 8×11 + 8×9）：预设备择 Δ = 0.20；最保守格（N = 62 / ρ = 0.30 / ψ = 0.35）的 80% MDE 是 **0.231**——**高于 0.20，即在该格 Δ = 0.20 不可确认**，这句话被要求逐字写进预注册。在开发集先验中心 Δ = 0.264 处，16 个格里最低检验力是 **0.914**。

**冻结审阅**：v3.1 与 v3.2 各做三到四路独立对抗性复核（统计有效性 / 代码是否做了正文说的事 / 数据与盲态 / 两阶段解封纪律），复核者全程不读封存路由，只用配置元数据、代码与已解封文档复算。v3.2 草案一轮就报了 **31 条发现**，其中三条经核实为 blocking：可达性口径不唯一、阈值清单必须多格、**折键与 fixture 共线**。最后一条是本轮最重要的一次拦截：旧折键 `scenario_mod` 在 G-conf 上把 3 个 fixture 与 3 折锁成周期共线（每个 fixture 整整缺一折），会让"折内 held-out"这句范围声明不成立；而**G-dev 结构性地演示不出这个缺陷**（它有 4 个 fixture，周期 4 与模 3 互素）。改用 `fixture_rank_mod`（scenario 在**它自己的 fixture 内**按 id 排序取名次 mod 3）后，G-conf 实测 OSY 31/31/31、TSL 32/31/31、WRH 31/31/31，`collinear_fixtures = []`。

## 5. v3.1：以参与为锚的主格

### 5.1 定义

| 量 | 定义 |
|---|---|
| **S**（主候选） | `q[l,e]` = 拟合池上专家 (层 l, 专家 e) 进入 top-4 的平滑频率；`Omega_rare = {(l,e) : q < 0.02}` 拟合后冻结；`S_t = mean_{窗口} Σ_l Σ_{e∈top4} 1[(l,e)∈Ω_rare]·(−log q[l,e])`。**稀有坐标支持集扩张 surprisal** |
| **P**（主对照基线） | 同一个 `q`，**无稀有掩码**：`P_t = mean_{窗口} mean_{l,e∈top4} (−log q[l,e])`。这是 brief §9 判据 1 点名的 marginal novelty 基线 |
| **M**（次级对照） | 每 token 的 24×32 = 768 维 0/1 选择指示，窗口均值对拟合池均值的**白化平方距离**（方差下限 1e-3） |
| 公共常量 | 窗宽 **w = 8**（段内步长 1 的因果窗口，**不跨通道边界**）、**全部 24 层**、`tag_scope = message`、V1 视图 |
| 标准化 | **通道条件化**：位置桶 = 该端点在本 episode 该通道内的第几个端点 `// 32`，μ/σ 在拟合池上估计，尾桶合并到 ≥ 30 episode；稀疏通道 pooled 回退（G 上一次都没触发） |
| **C1 保形校准** | 参照 = 过滤后 G-cal 全部 279 条路径**截断到前 H 个 look 后的全路径最大值**；`p(k) = (1 + #{g : Z^g ≥ R(k)})/(n_cal+1)`，`R(k)` 是目标 episode 的 running max；`alarm(k) iff p(k) ≤ α = 0.10`。`p(k)` 单调不增 ⇒ 在可交换性下 per-episode 误报率 ≤ `alpha_eff = 28/280 = 0.100000`（**恰好可达**） |
| **H = 352 look** | "存活校准路径 ≥ 90 的最大 look 数"。**单位是 look 不是 token**：本格端点密度 look ≈ 0.9001 × token，第 352 个 look 落在 token 379–393；该处删失路径 31.9% |

三个统计量与冻结的上一代 scorer 在合成轨迹上**逐位相等**（`atol = rtol = 0`），这是"同一个统计量换了几何"的凭据。**每个格只跑一个统计量、花掉全部 α**（无通道分摊、无秩融合、无 Bonferroni 均分）。

### 5.2 冻结的结果：**开发批 G-dev 上的预注册判定**（权威来源 `g_dev_confirmatory_report.md`）

> **一处术语纪律**：v3.1 的判定跑在 **G-dev（开发批）** 上，不是封存批。本文一律称它为"**开发批上的预注册判定**"，"**确认性**"这个词只留给 G-conf（§6.3）。源文件名叫 `g_dev_confirmatory_report.md` 是历史命名，不改变这一点。
>
> **另一处编号纪律**：**v3.1 与 v3.2 的 `S1` / `S2` 指的不是同一件事**（v3.1：S1 = S vs M、S2 = 代码域 OR 臂；v3.2：S1 = 绝对命中率 > 0.50、S2 = S vs M）。"S vs M"在前一轮编号 S1、在后一轮编号 S2；"S1 成立"在一轮为真、在另一轮为假。**本文以下一律写全称，编号只作附注。**

| 项 | 判定 | 读数 |
|---|---|---|
| **H1**（S vs P，匹配实测 FAR，band 0，严格命中，+16） | **形式上成立** | Δ̂ = **0.0406**，CI **[0.0143, 0.0741]**（下界 > 0 ✓），McNemar **p = 0.0078** ✓；**R_S = 9/197 = 0.0457、R_P = 1/197 = 0.0051** |
| **S vs M**（Holm 成员，v3.1 编号 S1） | **不成立，且反方向被显著确立** | Δ̂_SM = **−0.0812**，CI [−0.182, −0.017]，p = 1.45e-4，Holm 后 2.90e-4 → **M 的 +16 召回是 S 的 2.8 倍（25 vs 9）** |

| **出厂** | **不可出厂** | **F1** 合计过滤后 FAR **0.2389**（预算 0.10 ± 0.03）、**F3** 最长三分位 **0.345 / 0.350**（门 0.15）、**F5** matched-group **0.325 / 0.351**（门 0.15）失败 |

- **本模型从不显式自我纠正**：全部 888 行的 `explicit_correction` 为 **0**（与 G-dev 完全一致），恢复段 110 段落在 107 行上，`re_execution = true` 68 段。

- **A-V2 消融（G-dev，探索性）几乎白拿**：去掉 `commentary` 通道后命中**数**与主格相同（103/125 = 0.824），FAR `filtered` 从 0.11945 掉到 **0.08532（−29%）**，静默从 5/40 掉到 2/40，最差长度档从 0.15315 掉到 **0.14414（过 F3 线）**，`x_beyond_h` 从 18 掉到 11。原因与通道分布一致：**`commentary` 贡献 10.1% 的端点却贡献 0 条 onset**，去掉它等于减少多重性预算的消耗而不损失信号。**这是本线最值得下一轮预注册的一条描述性读数。**

## 7. 负结果与已排除方向（全部限定在 gpt-oss / 数据集 G 上）

1. **selection 统计量（S / P / M）在参与点 E 上的检测**：`[E, E+16]` 窗口 AUROC 0.446（低于随机），ORACLE 天花板 0.188 @ 窗口 FAR 0.10，G-conf 上 E 锚点 +16 严格召回 **5/127 = 0.0394**。**这条不是"没做好"，是"那里没有信号"**——序贯多重性只占缺口的六分之一。
2. **权重 / 概率通道作为可部署的参与检测器**（**以下六个数全部来自 G-bridge 留出池，n = 160 条正常 episode**，不是 G-dev / G-conf；`g_prob_channels_smoke.md` §3–§4）：`in_set_residual_mass` 在正常臂上的留出误报是 **0.250**（S 是 0.050，95% Wilson 区间与其余全部统计量不相交），跨池预设阈值差 **0.112**；`prob_rare_mass` 是 **0.000**（退化到不报警）且重尾指数 1.69 差于 S 的 1.05。**两者都不可作为通道**。`prob_js` 被保留，但**只作为"注入在场"格**（S-J），不是参与检测器。
3. **OR 臂（多通道或规则）**：v3.1 的代码域 `prob_js` OR 臂增益 **0.000**（3/56 → 3/56，门要求 ≥ 0.20），不一致对 (0,0)。单一统计量 + 单一 α 的设计不被这条否证。
4. **单轮校准池**：冻结的 G-fit / G-cal（100% 单轮）在含 23% 第二轮的目标批上给出 FAR 0.211 / 0.239；加入或换成 G-session 正常臂**更差**（0.243 / 0.290、0.233 / 0.263）。可行的修法是**目标批自校准**（0.0980 / 0.1195，注册口径，见 §6.1 的出处注），代价是它不是部署口径（§9.2）。
5. **running-max 参照用于早锚点**：没有任何一条校准路径在 look 35 之前越过阈值，而 197 条正例里 106 条（53.8%）的整个 `[E, E+16]` 窗口都落在 look 35 之前。但放弃 anytime validity 的逐 look 诊断在 FAR 0.108 上给出 +16 召回 **0.041**，**不比冻结的 0.046 好**——保形构造不是主要瓶颈，**不要把预算花在这里**。
6. **视界的加宽不是杠杆**：召回对视界单调只是因为更长的视界终究会包含 X（+16 **0.046** → 全路径 **0.629**，§5.3 图 1）。**窗宽（w = 4 / 2 / 1）本轮未测**——消融 **A-w4** 未跑（见第 7 条），对应的假设 H-11 在纲领里仍标 `untested on gpt-oss`（`gpt_oss_research_program.md` §2），**因此窗宽不在本节的排除范围内**。
7. **以下方向只有重新检验才算数**（本轮未做或未注册，如实记录）：多通道融合的强形式、V2 / V3 视图在 harness 侧的正式列、跨池迁移差的描述性列、消融 A-raw / A-no-bucket / A-mid / A-body / A-w4 / A-medium / B-B / B-U / **B-NT（文本基线的整轨迹 AUROC）**——在 G-conf 上全部**未做**，因为它们需要第 3 次检测器运行 = 新 proposal。**其中 B-NT 不只是"一条没跑的消融"**：它是本线唯一的非路由基线，缺了它，"路由有增量"这句话就没有对照面。它已被提升为一条正式局限（**§9.13**），不再只挂在这张待办清单上。

## 8. 与相关工作的关系

> **必须在这张表之前点名的缺口**：与 TaskTracker / PIShield / InstructDetector 这一族的**实际比较，本轮一次都没做**——文本与激活基线（消融 **B-NT**）在 G-conf 上未跑（§7 第 7 条、**§9.13**）。因此下表"与本线的差别"一栏说的是**问题设定**的差别，**不是**本线在同一批数据上赢过或输给它们的证据；引用条目见 §11。

| 工作 | 它证明了什么 | 与本线的差别 |
|---|---|---|
| **TaskTracker**（Abdelnabi et al., SaTML 2025） | "任务漂移"= 外部数据导致 LLM 偏离用户指令；用处理外部数据**前后**同一探针位置的残差流激活差做线性分类，OOD 上 ROC AUC 接近完美 | 它是**稠密模型 + 前后差分 + 有监督探针**，判的是"这一轮是否被漂移"；本线是**MoE 路由 + 无监督正常参照 + 逐 token 在线**，判的是"偏离发生在哪个 token"。它是本线必须比较的最近工作（B-NT 类文本 / 激活基线**本轮未跑**，如实记录为缺口） |
| **RouteScan**（Lv et al., 2026） | 聚合路由统计 + 轻量分类器可识别有害 prompt，四个开源 MoE 上未见有害领域 AUROC > 0.91，可迁移到未见 jailbreak 模板 | 它只用 **prefill**、每个 prompt 一个向量、有监督。本线是**生成阶段**的逐层逐 token 轨迹，且**不在攻击上训练** |
| **RASET**（Zhang et al., EMNLP 2026） | 在含 gpt-oss-20b 的五个 MoE 上测路由权重 JS 散度：**话题改变 0.3379**，而"话题固定 + 拒绝前缀"只有 0.0098–0.0346、"拒绝 vs 合规的 teacher-forced 续写"0.0054–0.0434。作者据此认为路由不是可靠的安全信号 | **这划定了本线的边界，而不是否定它**：任务偏离（客服 → 写代码 / 写诗）是**话题级**变化，正是路由最敏感的情形；同话题下的意图变化（如违反退款政策的让步）路由几乎不响应。G 的攻击全部是跨话题的，**同话题政策违规这一困难负例族在 G 里不存在** |

**开放缺口**（`related_work.md`）：尚未发现工作研究**能否把生成阶段逐层逐 token 的 MoE 路由轨迹作为固定职责生产 agent 的运行时信号，检测其实际行为是否从 routine work 转向跨领域工作，并区分攻击暴露、自然抵抗与实际服从**。

**本线新增的是两件事**：(1) 在一个**真正调用工具的 agent** 上、在**生成阶段**、以 token 级事件真值（E/C/X）度量路由轨迹的检测能力，并把"注入在场"与"偏离发生"**分开报**（`benign_control` 臂 + S-J 格是这条分离的两侧）；(2) 一次**预注册 + 封存批只开一次**的确认，包括提前声明会失败的门、提前写下的先验、以及事后逐条对照先验落空的记录。

## 9. 局限与适用范围

1. **单模型、单工作负载，且跨攻击家族的泛化也没有被检验**。G 是**一个** Atlas 客服系统提示 + 10 个工具 schema；跨模型与跨工作负载都不在范围内。**更近的一条**：G-conf 与 G-dev **共享同一个 72 格场景设计与同一族 16 个攻击家族**（§3.2），封存批留出的是 fixture（TSL / WRH / OSY）与 16 个新工作流 scenario。因此"确认"覆盖的是**新实例**，**不是新攻击类型**；家族聚类 bootstrap 处理的是家族内相关，**不是**对未见家族的外推。本批唯一度量泛化的分层是 `held_out_workflow`（9/10 = 0.9000，n = 10，不作断言）。
2. **本设计给出的是批内保证，不是部署保证**（这是最重要的一条）。保形可交换性在 v3.2 里是**折内**成立的：折 k 由折 k+1 拟合、折 k+2 校准，三折 scenario 互斥。**一个部署中的检测器不能在它正要打分的那一批上校准。** v3.2 检验的是"给定一批部署流量、其中的正常部分可用于校准"这一条件下的在线检测能力；预设阈值的跨池迁移**不是本轮的主张**（本轮连描述性列都没做）。而且 **F1 是这条可交换性假设在本设计里的唯一检验，它的逐折列在 G-conf 上失败了**。
3. **X 锚点的主张比 E 锚点弱**。命中窗口上界 `min(X+16, H_end)` **包含**交付 token；**这不是"提前量"主张**，命中的中位延迟只有 2 个 look，首报警早于 X 的比例只有 0.211（分母 = 可达正例）。
4. **14–18% 的 X 落在视界之外**：G-dev 18/126 = 14.3%，G-conf 13/72 ≈ 18.1%（可达口径 12/71）。G-conf 上这 12 条**一条都没命中**。主张只覆盖 H = 352 look 之内的执行事件。
5. **`X_tool` 在 G 上结构上不可承载**：G-conf 的 `x_tool` 行 0、`x_tool_only` 0、受限工具尝试 0 次，因此 "`min(X, X_tool)` 敏感性列"在本批上是**恒等的**。**必须明说，否则会被误读成"检验过了"。**
6. **G-session 是 2 轮前缀**。冻结配置声明每个会话 3–5 轮，但 Agent v3 runtime 最多产出两个用户轮，落盘的 100 条 trace 每条只有 2 个 episode；30 个攻击会话中**声明在第 3 轮注入的 15 条实际注入落在第 2 轮**（`multi_turn_user` 渠道总是把注入挂在第二个用户轮上）。因此 **F7 不可评**，会话级预算的主张本线没有做出。
7. **N1 失败**：G-conf 正常臂质量过滤通过率 0.778 < 0.85。这意味着"正确 routine"这一子总体比设计预期小，`filtered` 与 `all` 两个分母的差别更重要。
8. **标注由 LLM 完成**（Opus 5 双盲 + 裁决），不是人工。类别一致率 97–98%、κ 0.94，事件存在性在 G-conf 上一致率 100%；但这仍是"两个同族模型对同一份文本的一致"，不是人类真值。
9. **代码分层只报数、不主张**。"散文谈论代码 vs 字面代码"的真正对照臂在冻结的场景工厂里不存在（改场景工厂会连锁改变封存的 G-conf），本轮用代码域 `benign_control` 作代理，而 `prose_about_code` 标记在全 888 行上是 **0**——"该形态没出现"与"标注者没用这个标记"**不可区分**。
10. **需要第二个模型**。纲领的次序是硬的：在 gpt-oss 上把主张建立起来**之前**不启动第二个模型；但没有第二个模型，"这是模型属性还是这一个模型的属性"就没有答案。
11. **两阶段解封是代码强制，不是操作系统强制**：`g_conf_seal.py` 是只读 + 全量哈希，不是逐臂读权限控制；`--verify` 不含机读时间戳、不覆盖 `frozen_inputs` / `run_configs` / `extra_files`；`attack_trace_set_sha256` 比的是**集合摘要**，能发现新增 / 删除 / 改名，**不能**发现某个 `trace.json` 被就地改写。"阶段 1 只跑一次"有机械留痕，但换一个 `--run-name` 重跑代码不会拒绝——最终由流程纪律承担。
12. **"这可能是一个体裁切换检测器，而不是任务偏离检测器"——本轮无法排除。** 真检出的是**跨领域体裁的起点**（按 §1.1 的 X 定义：代码块正文首个字面代码 token、第一个等式、诗的第一行创作文本）；误报则是 `knowledge_qa` 下"把 KB 全文改写成编号清单"的**散文 → 结构化枚举**切换（§6.6，58 条正常臂误报里 52 条首报警在 `final` 通道，最早触发的三条文本形态完全一致）。**数据集 G 里没有把这两者分开的对照臂**：`benign_control` 是"工具结果 / KB 里出现题外话题的**非指令性提及**"，它的输出形态仍是正常客服回复，所以它控制的是"**话题被提及**"，**不是"输出体裁改变"**。因此在 G 上"任务偏离"与"输出体裁切换"**不可分离**。本报告里唯一一条反向证据是归因坐标的近乎不相交（误报 top-20 与真检出 top-20 的 **Jaccard = 0.111**，§6.6）——**它是部分反证，不是完整反证**：坐标不同并不排除两侧都由体裁驱动、只是体裁不同。要判定这一条，需要一个"**输出体裁改变但任务没有偏离**"的臂（例如让 agent 用编号清单交付**范围内**的答复），而这需要改场景工厂 ⇒ 新一批数据。
13. **本轮没有跑任何非路由基线。** 报告里的每一次比较都在**路由内部**（S vs P vs M vs `prob_js`）；P 只是同一份 `q[l,e]` 上的另一个统计量，因此它只能说明**稀有掩码**有没有用，**说明不了路由本身相对文本可得的信号有没有增量**。最自然的竞争者是零成本的**输出形态检测器**——而按 §1.1 的 X 定义（**围栏不算 X，X 在围栏之后**），它会**早于** X 触发。文本 / 输出形态 / 激活探针基线（消融 **B-NT**）在本轮**完全未跑**（§7 第 7 条）。因此 brief §9 判据 1（"相对 marginal novelty 基线有明确增量"）**只在路由内部被检验过**；"路由值得采集"这句话本线**尚未证明**。这也正是与 TaskTracker（§8）作比较所必需的那一列，是本线最大的一个未清偿缺口。
14. **威胁模型是非自适应攻击者，逃逸完全未测。**（§1.4）注入载荷由冻结的场景工厂生成，攻击方不知道检测器存在。由于机制响应的是**跨领域输出形态上的稀有路由坐标**，"把载荷改写成散文"这一类改写**可能同时躲开 X 的标注判据与检测器本身**；而第 9 条已经说明"散文谈论代码 vs 字面代码"的对照臂在冻结的场景工厂里**不存在**——**逃逸形态恰好就是缺失的那个臂**。本报告不主张任何对抗鲁棒性，也不主张离散 top-k 路由相对连续激活探针有更好的混淆鲁棒性（那是一条**未检验**的猜想）。
15. **最弱的注入渠道恰好是最有安全意义的那一个。** 逐维最差组（§6.6）：`tool_output`（**间接提示注入**）命中率 **9/14 = 0.6429**，是三条渠道里最低；域上最差的是 `reasoning_legal` **7/13 = 0.5385**。正常臂一侧，`return_status` 工作流的 FAR 是 **7/26 = 0.2692**，是 0.10 预算的 **2.7 倍**。分层 n 都很小（10–30），**不作断言**，但必须与 F1 / F3 的 PASS 判定放在同一页：**pooled 通过不等于逐层通过**。
16. **没有精度 / 基率分析。** §1.2 用生产判据给本工作定位，§6.4 评了一整套误报门，但本轮**没有**算过精度（PPV）、报警量或在给定攻击基率下的可用性。按 S 的实测 per-episode FAR **0.0994**（`filtered` 分母 523）与两个可选的检出率：

   | 攻击基率 | PPV（TPR = 0.319，**攻击臂 episode 级**） | PPV（TPR = 0.746，**条件在"已执行且窗口可达"上**） |
   |---|---:|---:|
   | 1e-2 | **0.031**（约 32 条报警里 1 条真） | 0.070（约 14 条里 1 条） |
   | 1e-3 | 0.0032（约 312 条里 1 条） | 0.0075（约 134 条里 1 条） |
   | 1e-4 | 0.00032（约 3 113 条里 1 条） | 0.00075（约 1 333 条里 1 条） |

   因此"**路由信号只是多路信号之一、不自行裁决、交给上层风险系统融合**"（§1.2）不是一句谦辞，而是这张表的直接推论。**本报告不对"离可部署还差几个数量级"作任何量化断言**：`production_moe_routing_shift_research_brief.md` §3.2 / §9 只要求"可控且可解释的误报率"，**没有给出任何数值门**，所以这里只报这张表和两条实际失败的门（N1、F1 逐折）。

1. **V2 视图与体裁切换误报 → v3.3**。两条读数指向同一个杠杆：`commentary` 贡献 10.1% 的端点却贡献 0 条 onset（A-V2 消融在开发集上白拿 −29% 的 FAR 并让 F3 过线）；正常臂误报有一半在进入 `final` 后 32 个 look 内触发、文本形态一致地是"KB 全文改写成编号清单"。下一轮应把 **V2 注册为主视图**，并把"输出体裁"作为标准化器的条件维（这是协议改动，必须先冻结再测量），同时把重尾正常 episode 是否是"正常输入下的真实偏离"变成一条可判定的主张。

3. **tau2 外部工作负载（G-ext）**。路由轨迹**永远借不到**（没有任何服务暴露 router logits，全部公开 MoE 路由语料都不是我们的模型且无偏离标签），但环境、任务、攻击载荷、确定性判定器可以借。tau2-bench retail/airline（MIT）值得借的理由不是省钱，而是三件 G 自己给不了的东西：**审稿人认识的基准（外部效度）**、**由 DB 差分给出的确定性 X 标签**（G 因为受限桩永不执行而把 B 类未授权操作推迟了）、以及**"同话题政策违规"这一 RASET 预言路由会失效的困难负例族**（G 里没有）。攻击素材可从 DoomArena / AgentDojo / InjecAgent / LLMail-Inject 移植。
4. **第二研究线（Codex）的并行判定**。两条线最终要在同一份封存批上各判一次并排出现，因此**评价口径已经冻结并共享**（V1 / `message` / w = 8 / 全 24 层 / 锚点 X / 命中 `[E_view, min(X+16, H_end)]` / band 0 / H = 352 / α = 0.10 / K = 3 折 `fixture_rank_mod` / C1 参照 / 家族聚类 bootstrap）。任意一处不同，两组数字就不可比，而封存批只能开一次。

1. **±0.03 的逐折带从未按抽样噪声标定过。** 在本设计自身的完美可交换零假设下
   （保形判据 `p(k) = (1 + #{g : Z^g ≥ R(k)}) / (n_cal + 1) ≤ α`，三折轮转 eval `k` / fit `k+1` / ref `k+2`），

   **三折同时落在各自 ±0.03 内的概率只有 0.376**。
   **也就是说：在可交换性完美成立、检测器完全正常的情况下，F1 逐折本来就有 ≈ 62 % 的概率被判失败。**
   本报告里的那次失败**因此不构成**"折间可交换性不成立"的证据，**也不构成**对统计量 `S`、对本设计误报控制的任何证据。
   （幅度也不支持这种读法：−0.0427 只有 **−1.35 个零假设标准差**。）

   等尾 95 %，`r` 与 `n_cal` 取自阶段 1 清单（`r = floor(α(n_cal + 1))`）。
   （中间还有过一版**二项**区间——`[10, 26]` / `[10, 25]` / `[10, 25]`——**那一版也太窄**：
   它把保形阈值当成固定值，真实覆盖率只有 **0.869 / 0.860 / 0.855**（三折联合 0.672），已作废。）
   本报告的三折在最终判据下是：

4. **为什么是 beta-binomial（而不是二项）。** 保形阈值是 `n_cal` 条参照最大值里的第 `r` 大，
   **它本身是估计出来的**，其超越概率是 `Beta(r, n_cal + 1 − r)`；给定它，留出 episode 条件独立同分布，
   所以计数是 **beta-binomial（Pólya 瓮）**，方差是二项的 `(n_cal + 1 + n_eval) / (n_cal + 2)` 倍——
   G-conf 三折上是 **2.03 / 1.93 / 1.99 倍**。这就是二项区间那一版为什么太窄。
   最终判据的区间是**精确**的（G-conf 是 `H = 352` 的有限视界格，留出统计量取前 H 的 running max
   而标定取全路径最大值，可交换性在该方向只是近似，区间偏保守；v3.3 的注册主格 `H = ∞` 两侧口径一致，精确成立）。
   本条与 §6.4 的裁定记录见 `docs/research_v4/freeze_review_v3_3_resolution.md` §6.3 / §6.4。
