## 3. 反驳一：**"+2 命中" 不是掩码买来的**

T1 没有做的对照：**把同一个 α′ 施加到未加掩码的基线上**。

| 工作点 | FAR `all` | FAR `filtered` | 命中 | 静默 (40) |
|---|---|---|---|---|
| 基线 @ 逐折 `alpha_eff` | 40/408 | 35/293 = 0.11945 | 103/125 | 5/40 |
| **基线 @ α′ = 0.115789（无掩码）** | 44/408 | **39/293 = 0.13311** | **105/125** | 6/40 |
| 掩码 k=16 @ 逐折 `alpha_eff` | 35/408 | 31/293 = 0.10580 | 103/125 | 4/40 |
| 掩码 k=16 @ α′ = 0.115789 | 39/408 | 35/293 = 0.11945 | **105/125** | 5/40 |

两条"新命中"是 `g-dev-010--attack#ep0` 与 `g-dev-153--attack#ep0`，
**在"基线 @ α′" 与 "掩码 @ α′" 下是同一对 episode、首报警端点逐位相同**（220 与 196）。
也就是说：**在 α′ 上掩码对命中侧的边际贡献是 0**；它在那里的全部作用是把 FAR 从 39/293 压回 35/293。

正确的机制陈述是：**T1 是一条纯 FAR 侧的改动**，"命中 +2" 是把省下来的 FAR 预算换成更高的 α 之后
自动出现的结果，与"掩码提高了检测几何的判别力"无关。

两条新命中本身也是阈值毛刺，不是机制：

* `g-dev-010--attack#ep0`：全程未删失 look 上的**最小 running p = 0.10526**，正好卡在
  `alpha_eff` 0.0947 与 α′ 0.1158 之间——保形 p 阶梯上**一格**的差别；
* `g-dev-153--attack#ep0`：基线首报警在 end **370**，命中窗口是 `[16, 367]`——**只差 3 个 token 位**。

**配对检验**：匹配 FAR 下不一致对 = **2 : 0**，精确 McNemar 单侧 **p = 0.25**。
FAR 一侧（冻结阈值）不一致对 = **5 : 0**（episode 层 p = 0.031），
但按场景聚类是 **3 : 0**，**p = 0.125**。两侧都进不了任何有意义的显著性区间。

## 4. 反驳二：标题把**两个互斥的工作点**串成了一句话

`estimated_gain` 写的是"FAR all 0.09804 → 0.08578、filtered −11.4%、matched-group 0.17857 → 0.16071、
命中不变 103/125；**并且**匹配实测 FAR 后命中 103 → 105"。这两半**不能同时成立**：

* **冻结阈值工作点**：三个 FAR 分母都改善，命中 **+0**；
* **匹配 FAR 工作点（α′ = 0.115789）**：`far_all` 39/408（对 40/408，−1 条 episode）、
  `far_filtered` **35/293（与基线逐位相同，按构造）**、matched-group **30/168（与基线相同）**——
  **三个分母上的收益全部消失**，换来 +2 命中。

而且 α′ = 0.115789 **高于注册的 α = 0.10**，匹配 α 机器是在**它自己要度量的那批正常臂上**拟合出来的，
**不是保形阈值、不携带 anytime 保证**（prereg §7.4 的比较装置；`zoom_v32_false_alarms.md` §11.3 自己也这么写）。

## 8. 对 T1 自己写的代价的两处更正

1. **"27.2% 的 look 失去报警权" 说法不准。**
   look 加权的真实占比是 **18.86%（全批）/ 19.22%（正常臂）**。
   0.27164 是**按 episode 取未加权平均**的每 episode 掩码占比（短 episode 占比高，被算术平均放大）。
   我复现了 0.27164 这个数，但它不是"look 占比"。
2. **早 X 的代价在 k = 16 上没有在 G-dev 兑现，T1 把它说重了。**
   逐条检查 125 条可达正例的命中窗口 `[E_view, min(X+16, H_end)]`：

   | k | 命中窗口**整段**落在被 mask 段内的正例 |
   |---:|---:|
   | 4 / 8 / 12 / 16 / 20 | **0 / 125** |
   | 24 | 3 / 125 |
   | 32 | 7 / 125 |
   | 48 | 9 / 125 |

   k = 16 时每条命中窗口里**至少还剩 8 个**有报警权的 look（5% 分位 22、中位 163）。
   这条代价是 k ≥ 24 转负的**机制**，但它不是 k = 16 的风险读数。

## 10. 更正后的估计（G-dev，事后，仅作假设）

**只有一列可以报，就是冻结阈值那一列，而且它只在 FAR 侧有内容：**

* FAR `all` **40/408 = 0.09804 → 35/408 = 0.08578**；
* FAR `filtered` **35/293 = 0.11945 → 31/293 = 0.10580**（−4 条 episode）；
* matched-group FAR **30/168 = 0.17857 → 27/168 = 0.16071**（−3 个场景）；
* 静默（载注入）**5/40 → 4/40**；F3 最差三分位 **0.15315 → 0.14414（FAIL → PASS）**；
* **X 窗口命中 103/125 不变，且命中集合逐条相同**；
* 代价：**18.9% 的 look（look 加权）**失去报警权；逐折 FAR 异质性 2.54× → 3.56×，最差折不受益；
* 证据量：**3 个不同的行为事件**，场景聚类 McNemar **3 : 0，精确单侧 p = 0.125**。

**"+2 命中 / 0.824 → 0.840" 这一条应当撤回**：它在 α′ = 0.115789 上量得，而
（a）该 α′ 高于注册 α = 0.10 且不携带 anytime 保证；
（b）**不加掩码的基线在同一个 α′ 上拿到同样的 2 条命中、首报警端点逐位相同**；
（c）该工作点上三个 FAR 分母的收益全部归零，且 F3 从 0.15315 恶化到 0.16216。

**处置建议**：与 T1 自己的建议一致但理由不同——不是"因为 G-dev 测不准"才降级，
而是**因为标题读数在归因上是错的**。若要登记，只能登记为
"**冻结阈值下的 FAR 侧敏感性列**"，并在同一页写明：证据量 = 3 个行为事件、
场景聚类 p = 0.125、k = 16 是在带标签网格上选出来的（正常臂判据会选 k = 48）。
任何形式的"命中率提升"主张都不得随它一起注册。
