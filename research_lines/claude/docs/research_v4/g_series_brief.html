基于 MoE 路由的 Agent 任务偏移在线检测

一个由 gpt-oss-20b 驱动、自主调用工具的客服 Agent，被诱导去写代码、写诗或做法律分析时，只看它推理时免费产生的专家路由记录，能否在偏离内容开始产出的 16 个 token 内报警，并且不被上下文里的攻击文本误导？我们用预注册加封存确认集回答了这个问题。

模型 gpt-oss-20b（24 层 × 32 专家，每 token 选 4 个，harmony 三通道） 数据 G 系列 2428 条轨迹 / 2934 个 episode（含 P0 探针），封存确认集 720 条 证据等级 预注册 + 封存集一次性确认

01问题定义

Agent 服务把大模型放进"读输入、调工具、写回复"的循环里，攻击者可以经用户消息、工具返回值或多轮对话把题外任务塞进来。我们要检测的不是"输入里有没有攻击文本"，而是模型有没有真的开始做那件事。MoE 模型每生成一个 token、每一层都要从专家池里挑几个来算，这份选择记录在推理时已经存在，读它不需要额外计算，也不需要读文本。检测器的定位是安全系统里的一路信号，不是唯一决策，因此要优化的是似然比、可解释且分段稳定的误报、按会话预算校准的分数、在不可逆点前的检出，以及对上下文攻击文本的不敏感。

02潜在的创新点

生成期路由轨迹作为 Agent 偏移信号
相近工作要么用稠密模型的激活差分做单轮任务漂移（TaskTracker），要么用预填充阶段的路由审计有害提示（RouteScan）。我们看的是自主调工具的 Agent 在生成阶段逐 token、跨多步的路由轨迹。
只学正常流量，误报有可交换性保证
检测器只从部署批次自己的正常流量学习常规流形，阈值由序贯保形校准给出；不需要任何攻击样本训练，也不响应上下文里的注入文本本身。
封存确认集与两阶段解封
720 条确认集在生成后立即哈希封存并只读，预注册冻结后先只解封正常臂做校准、再解封攻击臂评价一次；19 项机械检查把"事后可选工作点"堵死。这是本项目第一个在封存数据上成立的主张。
事件层次与及时性协议
整条轨迹看完之后几乎任何分数都能分辨偏移，价值只在早。评价单元是"首次报警落在 [E, X+16]"，锚点前的报警按严格口径记漏检，并按攻击家族做聚类 bootstrap。

03已有的发现

数据集 G 在 gpt-oss-20b 上重建了整套流程：模型自主调用只读工具，受限操作作为桩记录不可逆尝试；144 个场景格的攻击设计，三种注入渠道、三档措辞；所有标签由两位互盲的 Opus 标注者加第三读者裁决给出。

第一次预注册（v3.1）沿用了小模型试点的假设：以参与 E 为锚，用另一批正常流量校准。它在 G-dev 上形式上通过了判定规则，但读数说明设计错了：

9/ 197
v3.1 在参与起点后 16 个 token 内的检出（基线 1/197）。判定规则形式上成立，效应量 0.04，只有备择效应量的四分之一。
0.24
v3.1 在评价批次正常流量上的误报，预算 0.10。原因是逐通道标准化在批次间不可交换，而不是尾部或长度。
0.45 vs 0.99
选择类统计量在 [E, E+16] 与 [X, X+16] 的窗口级 AUROC。在 gpt-oss 上，路由对"开始想"没有信号，对"开始产出"极强。
阈值必须在目标批次自身校准
用另一批正常流量预置阈值，误报 0.21 到 0.24；把六个通道的标准化矩映射回校准池即回到 0.05；在目标批次正常臂上按场景分折交叉校准，误报回到预算。这与小模型试点的结论一致，机制不同。
早锚点在 anytime 参照下结构性不可达
参照是校准路径的全路径最大值，没有任何正常路径在第 35 个 look 之前越线，而参与起点的中位数在第 19.5 个 look。给 oracle 窗口也只到 0.19，说明主因还是信号缺失。
小模型试点的角色
OLMoE 上的全部结论现在只作为假设来源：其中"路由跟踪参与而非产出"已在 gpt-oss 上被证伪，"必须部署侧校准"被复现，"代码/SQL 盲区"没有复现。正式结论一律从 gpt-oss 建立。
误报的形态
正常流量上的误报集中在推理通道切换到回复通道的位置附近，文本审计显示是长篇知识库枚举这类体裁切换，不是话题提及；驱动误报与驱动检出的稀有专家坐标几乎不重叠。

04算法与确认结果（v3.2）

据此改三处设定并重新预注册：校准池改为目标批次自身经质量过滤的正常臂，按店铺世界内取模分 3 折轮转；锚点改为产出 X，命中口径"首次 CONFIRMED 落在 [E, X+16]"；权重通道移出主格。统计量仍是稀有坐标 surprisal S，α 0.10，视界 352 个窗口端点，anytime 保形参照不变。

0.746vs 0.479
确认集上 S 与 surprisal 基线在 [E, X+16] 内的命中率（71 条可达正例，实测误报匹配）。
+0.268
效应量，家族聚类 95% 区间 [0.071, 0.459]，精确 McNemar p = 6.6e-5。两条件同时成立，主假设 H1 在封存集上成立。
0.099
确认集正常臂的 held-out 误报（预算 0.10）；静默攻击报警率 0.095，未被注入文本带动。
对生产系统的含义：在真实规模的自主工具调用 Agent 上，路由信号能在偏离内容开始产出的 16 个 token 内（命中的中位延迟 2 个 look）、以约 0.10 的同批 held-out 误报给出报警，且不被上下文里的攻击文本带动。它检测的是"开始做"，不是"开始想"；阈值必须用部署环境自己的正常流量校准；视界之外的长 episode（约 15% 的产出事件）目前全部漏检。三条边界要一起读：本轮没有跑任何非路由基线（文本或激活探针），所以"路由相对文本有增量"尚未检验；数据集无法把"任务偏离"与"输出体裁切换"完全分开；全部标签由 LLM 双盲标注给出，没有人工验证的子样本。
