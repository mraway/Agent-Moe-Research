## 0. 一页结论

| 项 | 判定 | 关键读数 |
|---|---|---|
| **H1**（主格 S vs P，实测 FAR 匹配，band 0，严格命中，+16） | **成立（按 §1.2 的两条件规则）** | Δ̂ = **0.0406**，95% 家族聚类 CI **[0.0143, 0.0741]**（下界 > 0 ✓），精确 McNemar 双侧 **p = 0.0078** < 0.05 ✓；R_S = 9/197 = 0.0457，R_P = 1/197 = 0.0051 |

| **出厂判定** | **不可出厂（not shippable）** | **F1 / F3 / F5 FAIL**，F7 不可评；F2 / F4 / F6 / F8 PASS |

**三句话**：
1. H1 在预注册写死的两条件规则下**成立**，但它成立的方式与预注册的设想相反——不是 S 达到了 0.45–0.60 的召回，
   而是 **P 几乎完全不工作（1/197）而 S 只工作了一点点（9/197）**，Δ̂ = 0.041 只有预设备择 0.15 的四分之一、
   低于 §8.2 模拟网格的最低格（Δ = 0.10），也低于 §18 先验中心 0.10–0.15 的下界。
2. **在同一个实测误报率上，被预注册当作"次级对照"的 M 显著优于主候选 S**（Δ_SM = −0.081，Holm 后 p = 2.9e-4），
   即"S 不比其它几何更早"这条核心假设的一半在 G-dev 上被反向证据击中；同时 M 的名义误报率 0.297、
   pre-onset 报警率 10.6%，它的"更好"是买在一个本设计不接受的工作点上。
3. **出厂门失败三条（F1 合计 FAR 0.239 对预算 0.10、F3 最长三分位 0.345/0.350 对 0.15、F5 matched-group 0.325/0.351 对 0.15）**，
   因此本轮的结论是"机制主张在预注册规则下成立、但该检测器在 G-dev 上不可出厂"，两者必须并列陈述、不可互相替代。

### 1.1 H1 的判定（按 §1.2 的字面规则）

> 条件一：家族聚类 95% percentile bootstrap **下界严格大于 0** → 0.014286 > 0 ✓
> 条件二：精确 McNemar **双侧** α = 0.05 拒绝 → p = 0.0078125 < 0.05 ✓
> **两条件同时成立 = H1 成立。**

**H1 成立**。方向与预注册写死的备择方向一致（S > P）。

### 1.2 对照预设备择 0.15 与 §8.2 检验力表的报告义务

§1.2 规定："无论判定为何，都必须给出 Δ̂ 与其区间，并对照 §8.2 的检验力表说明该 Δ̂ 处本设计的检验力"。

- **Δ̂ = 0.0406 落在 §8.2 模拟网格（0.10 / 0.125 / 0.15 / 0.20）的**最低格之下**。**
  在最接近的一格 Δ = 0.10 上，两条件规则的检验力是：N = 177 时 **0.646（ρ = 0.15）/ 0.535（ρ = 0.30）**，
  N = 264 时 **0.805 / 0.628**。实际 N = 197 介于两者之间，因此该格的先验检验力大致是 **0.55–0.70**。
  在 Δ̂ = 0.041 这个量级上，本设计的先验检验力**远低于**这个区间——即"如果真值就是 0.041，本研究本来大概率查不到它"。
- **80% 检验力的最小可检出效应（MDE）**：N = 177 时 0.118（ρ = 0.15）/ 0.138（ρ = 0.30）；N = 264 时 0.100 / 0.128。
  **Δ̂ = 0.041 只有 MDE 的三分之一左右。**
- **为什么在这样的效应上仍然拒绝了**：因为不一致对是 **(8, 0)** 的极端单向分布——P 在 197 条正例上只命中 1 条，
  S 命中 9 条且完全包含 P 的那 1 条。精确 McNemar 在 b = 8 / c = 0 上给出 2^-7 = 0.0078，
  和效应量的绝对大小无关。这是**规则的正确执行，不是效应量大**。
- **§8.3 的零假设模拟**给出的合取规则假阳性率是 0.013–0.037（8 个格），因此这次拒绝不是已知的反保守区间造成的。
- **对照 §1.2 的报告义务措辞**：Δ̂ 落在 0.10 以下而两条件都成立，**H1 按规则成立**，
  但**结论的强度必须按"该效应量处先验检验力不足"叙述**：本研究**没有**证明 S 是一个可用的早期检测器，
  它只证明了"在同一实测误报率上，S 在 +16 窗口内比 P 多命中 8 条 / 197"。

### 1.3 对照 §18 的先验（同一表在 §9 逐条展开）

| 量 | §18 先验 | 实测 | 差 |
|---|---|---|---|
| R_S(+16) | 0.45–0.60 | **0.0457** | 低约 **10 倍** |
| R_P(+16) | 0.35–0.50 | **0.0051** | 低约 **70 倍** |

它在 G 上是一个**执行（X）检测器**而不是参与（E）检测器。

### 2.1 S1：S vs M（`holm_S1_S_vs_M/result.json`）

| 量 | 匹配列（判定用） | 名义列（α 同为 0.10） |
|---|---|---|
| S 的工作点 / 实测 FAR | α = 0.10 / **0.238908**（filtered） | 同左 |
| M 的匹配工作点 / 实测 FAR | **α = 0.0392857** / **0.238908**（逐位相等） | α = 0.10 / **0.331058** filtered、**0.296569** `all` |
| R_S(+16) / R_M(+16) | 9/197 = 0.045685 / **25/197 = 0.126904** | 9/197 / **27/197 = 0.137056** |
| **Δ̂_SM = R_S − R_M** | **−0.081218** | −0.091371 |
| 95% 聚类 CI（描述性，不进 Holm 判定） | **[−0.181818, −0.016949]**（上界 < 0） | [−0.194444, −0.022472] |
| 精确 McNemar | only_S = 1、only_M = **17**、both = 8、neither = 171、discordant = 18、**p = 1.44958e-4** | p = 4.00543e-5 |

**读法（必须完整陈述）**：
- S1 的主张是"**M 的 +16 配对召回不高于 S**"，其成立条件是"Holm 校正后 p < 0.05 **且方向为 S > M**"。
  校正后 p = 2.899e-4 满足前半条，**方向不满足**（M 高于 S，Δ̂ 为负、CI 整段在 0 以下）。
  因此 **S1 不成立**，且**反方向的差异被显著确立**：在**同一个实测误报率 0.2389** 上，
  M 的 +16 召回是 S 的 **2.8 倍**（25 vs 9），只有 1 条正例是 S 命中而 M 未命中。
- **这直接击中 §1.1 核心假设的第二半**（"也预测 M（白化选择率距离）**不比** S 更早"）。该预测在 G-dev 上被反证。
- **但 M 的"更好"买在一个本设计不接受的工作点上**（必须随此结论一并陈述）：
  M 在名义 α = 0.10 上的 `all` FAR 是 **0.296569**、filtered **0.331058**（S 是 0.210784 / 0.238908）；
  M 的 **pre-onset 报警率 0.106**（S 与 P 都是 **0.000**），因此 M 在严格命中口径下从 no-penalty 的 48/197 掉到 27/197；
  M 的 `benign_lexical − clean` 差是 **0.135417**（S 是 0.067708），已逼近 F2 的 0.10 门；
  M 的每 1000 合格端点 onset 数是 **1.3505**（S 0.9599）。
  换句话说：**这一比较的结论不是"M 可以出厂"，而是"S 相对 M 没有它被选中的那个优势"。**
- **匹配工作点的选择不确定性未计入区间**（§16.4 第 10 条）：`matched_alpha` 取"实测 FAR ≤ 目标的最大 α"，
  这一步用了目标池的正常臂；上述区间是**条件在选定工作点上的**。

### 10.1 误报为什么是预算的 2.4 倍：通道标准化的位置/尺度漂移

- **不是视界或 look 预算**：G-dev 正常臂比 G-cal **更短**（中位 240 vs 338 token、211 vs 296 look），
  长度匹配的参照反而让 FAR 更差（0.270）。
- **不是少数重尾**：整个 `final` 通道的 `z` 分布**变宽**（sd 1.016 → 1.291）且**整体右移**（均值 +0.03 → +0.21）。
- **ORACLE 重标准化**：只纠正**每个统计量六个数**（目标正常臂逐通道的均值与 sd，映回校准矩），
  再跑**完全相同**的 running-max 检验：**FAR 0.211 → 0.047（S）、0.186 → 0.059（P）**，
  **双双落进 0.10 预算之内**，代价只是约 0.06 的全路径召回，**+16 召回一点不变（仍是 0.046）**。
  **即：F1 的超额几乎全部是标准化失配，不是重尾、不是流氓子群、不是 H。**
- **失配的一半来自校准池里根本没有的子群：multi-turn 的第二轮**（`ep1`）。
  `ep1` 的 FAR 是 **0.385**（37/96）对 `ep0` 的 **0.157**（49/312）；`ep1` 的 `final` 通道 sd 是 **1.503** 对 1.016。
  **G-fit / G-cal 是 100% 单轮，G-dev 有 23% 是第二轮。** 只看第一轮也还有 0.157 / 0.188，仍然超预算。
- 同一事实解释了为什么 G-bridge 是 0.05、G-cal 是 0.097 而 G-dev 是 0.21：
  G-bridge 正常臂中位只有 109 个生成 token（153/160 落在最短档）且全是单轮，**够不到失配所在的深 `final` 段**。

### 10.2 +16 召回为什么是 0.046：**在 E 处根本没有信号**

- **窗口级 AUROC（控制 look 位置）**：S 在 `[E, E+16]` 上是 **0.446**——**低于随机**。
  同一测量在 `[X, X+16]` 上是 **0.989**，93% 的窗口在报警阈之上，**112 条首次报警里有 70 条落在 `[X, X+16]` 内**
  （中位偏移 +2 token）。
  **在数据集 G 上，这个路由统计量是执行（X）检测器，不是参与（E）检测器。**
  这与预注册从 ecx §2 带进来的判断（"路由信号对应 E/C，不对应 X"）**相反**。
- **running-max 的结构性下界**：参照集是 279 条路径的**全路径**最大值，与 `k` 无关。
  **没有任何一条校准路径在 look 35 之前越过阈值**，而 **197 条正例里有 106 条（0.538）的整个 `[E, E+16]` 窗口
  都落在 look 35 之前**。在那里报警需要一次瞬时冲进逐 look 零分布的前 0.1%。
- **但这不是主要原因**：放弃 anytime validity 的逐 look 诊断在 FAR 0.108 上给出 +16 召回 **0.041**，
  **不比冻结的 0.046 好**。缺失的 95 个百分点的召回分解为：
  **序贯多重性 / running max ≈ 14 点**（0.046 → ORACLE 窗口 0.188，且 FAR 更低），
  **E 处无信号 ≈ 81 点**（0.188 → 1.0），**约 6 : 1**。
- **两个失败几乎独立**：§10.1 的 ORACLE 重标准化把 FAR 修到 0.047，**+16 召回仍然是 0.046**。
  **修好校准买不到早期召回。**
- **ORACLE 窗口天花板**（告诉检测器 E 在哪里，无序贯多重性、无 anytime validity、无校准误差）：

### 10.5 诊断给出的 v3.2 方向（**建议，不是决定；本报告不裁定**）

1. **把校准池匹配到部署混合**（G-fit/G-cal 100% 单轮 vs G-dev 23% 第二轮）——最便宜、实测效应最大（FAR 0.21 → ~0.05 量级），
   且**保形论证完好**；代价是新的正常池生成。
2. **标准化器条件化在通道 × 位置桶之外再加一维**（轮次索引 / 是否有对话历史 / 稳健尺度）——**这是协议改动，必须先冻结再测量**。
3. **不要把 v3.2 的预算花在保形构造上**：逐 look / 逐桶参照牺牲 anytime validity，实测在 +16 上买到 ≈ 0。

   注册 X 作为第二锚点 / 用 `final` 通道首 token 作廉价代理，注意 194/198 的 E_view 在 `analysis` 里，该代理会晚得多）
   **都改变 H1 的内容，都不能在看到哪个赢之后再选**。
5. **若目标是参与点的早期检出，S 是错的统计量，`prob_js` 是候选**（见 §10.4），
   但它需要同时解决工作点问题（第 3 项），成本约 +24%/token、拟合 ~25 s。
6. **窗宽 / 视界的微调不是杠杆**（见 §10.3）。
