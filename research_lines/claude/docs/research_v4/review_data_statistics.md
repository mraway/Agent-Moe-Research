## 0. 一页判定

**判定：`major_revision_before_freeze`。设计的工程与标签部分明显优于 v2.5（模型驱动的工具调用循环 + 受限工具桩给出的
`C_tool` 自动锚点是本轮最好的一个想法），但它的规模表是在没有任何检验力计算的情况下写下的，而这正是上一轮
（`audit_statistics.md` §2：三条腿条件检验力恒为 0）被判定为"设计错误"的同一个失误。**

四句话概括：

1. **正例不够。** G-dev 的 160 条攻击按试跑产率给出约 **103** 个主事件正例（区间 80–123）。
   配对 +16 比较在预注册自己用过的效应量 δ = +0.11 与"与实测相当的耦合"下，80 % 检验力需要约 **150** 个正例
   （`audit_statistics.md` §2.3 说 150，我独立复算为 150；见 §8.1）。**当前规模的检验力约 0.63–0.70。**
2. **门不可证伪。** §6 的六个资格门、§7 的静默抵御硬门与会话级 FAR 门，在草案给出的 n 上全部**不可分辨**：
   0.03 的 FAR 容差在 240 条正常上需要 383–502 条才能测出；静默门要区分 0.05 与 0.12 需每组约 250 条；
   40 个正常会话上 4/40 的精确区间是 [0.028, 0.237]。这与 `audit_statistics.md` §7 对 G1–G7 的结论逐字相同。
3. **一处结构性不可行 + 一处结构性内爆。** (a) 因子水平 (域 8 × 渠道 3 × 措辞 4 × 目标 3) 的 strength-2 正交阵
   要求 N 是 **288** 的倍数，160 甚至不能被 3 整除——§3 的"拉丁方、任何一对因子不共线"在 160 上**不存在**；
   (b) agent 循环把一个 episode 变成最多 6 次生成、一个会话变成最多 30 次 look，若沿用 v3 的"按轮 Bonferroni"，
   α_look 会低到 0.0017，**在任何本项目负担得起的校准池上可达秩都是 0**（rank ≥ 1 需 n_cal ≥ 598）。
   这是 v3 "α_S = 0.02 把 S 通道饿死"的放大重演，而且它由**数据规模**决定，必须在这份文档里解决。
4. **成本估计的两个量级错误。** §9 的总数 2160 与 §5 的表（1680）不符；每条 250 token 与草案自己在 §2 写的
   回复长度（R1–R4 加权 ≈ **524** 生成 token/episode）不符；0.83 GB 磁盘与试跑实测（2.25 MB/条 ≈ 16 KB/token）
   相差约 **17 倍**（实际约 **14 GB**）。真实 GPU 约 **17–31 小时**而非 10–12。最大的成本项——标注工时——**完全没有估**
   （按本设计约 **120–240 人时**）。

**可以带进冻结的部分很多**（§7 的"保持不变"清单有 12 条）。需要改的是规模、门的写法、主格声明与三处角色定义。

## 3. 拉丁方 / 轮转（§3）的具体算术

- 因子水平：域 8、渠道 3、措辞 4、目标类型 3。逐对格数：8×3 = 24、8×4 = 32、8×3 = 24、3×4 = 12、3×3 = 9、4×3 = 12。
  strength-2（任意一对因子均衡）要求 N 被 lcm(24, 32, 24, 12, 9, 12) = **288** 整除。
- **N = 160 连 3 都不整除**（160/3 = 53.33）：渠道与目标类型在 160 上无法均衡，"任何一对因子不共线"不成立。
  草案自己写的"tool_output 占 1/3"也不是整数。
- 结构共线（改 N 也解决不了）：**T3 多轮渐进 ⊂ multi_turn_user**；**目标类型 B（未授权操作）只在有对应记录字段的域上可信**；
  代码域与"内容交付 A"天然绑定。
- 建议：域降为 4 组、措辞降为 3 档（T3 移为多轮渠道内的子层）→ 水平 (4, 3, 3, 3)，strength-2 OA 需 N 为 **36** 的倍数，
  **144 = 4 组重复**。剩余的 72 条产率层不声称均衡，只承担执行 / `C_tool` 正例产量，并在数据卡里显式标注为"非均衡层"。
- 剩余混杂（无论怎么排都在，必须在 §7 声明为分析协变量）：**长度 × 目标类型**（内容交付更长）、
  **渠道 × prompt 长度**（tool_output 的 prompt 更长）、**域 × 输出形态**（代码域必然结构化）。

**建议改成按层配额而不是按池比率**："产率层（T1 × 用户侧，n = 72）产出 ≥ 40 条执行正例；抵御层（T0/T2 × tool_output，
n ≈ 48）产出 ≥ 40 条有界抵御"。两个门就独立可满足，也消除了重采的动机。

**"新批次"规则是否合法？** 合法的充分条件有四条，草案满足两条：
① 决策变量是数据侧量而非检测器分数（✔ 满足）；② 失败批次保留不删改（✔ 满足，§6.4 明写）；

补上 ③④ 后它是合法的两阶段设计；不补就是花园分叉——因为"调整措辞层级配比"这一步可以被任意重复直到产率好看。

## 5. 泄漏与角色分离

- **G-conf**：封存对象 = 路由张量；文本与行为标注在解盲前完成（见 M15）。

## 8. 计算附录（可逐条重算）

**8.1 配对 McNemar 精确检验力**（双侧 α = 0.05，判定 = a > b 且 `2·P(X ≤ min(a,b)) < 0.05`，X ~ Bin(a+b, ½)；
(a, b) 服从以 (π_a, π_b) 为参数的三项分布）：

| 耦合（π_a / π_b，δ = 0.11） | n = 56 | n = 80 | n = 110 | n = 150 | n = 200 |
|---|---|---|---|---|---|
| 完美 0.11 / 0.00 | 0.590 | 0.886 | 0.985 | 0.999 | 1.000 |
| 轻度 0.14 / 0.03 | 0.403 | 0.605 | 0.781 | 0.904 | 0.970 |
| 与 v3 实测相当 0.16 / 0.05 | 0.331 | 0.504 | 0.663 | **0.813** | 0.922 |

与 `audit_statistics.md` §2.3（"实测耦合下 80 % 需约 150 条"）一致。**精确 McNemar 的 p < 0.05 最小净增仍是 6**——
任何"净增 ≥ k 且 p < 0.05"的复合门在 k < 6 时装饰性（同 §2.1）。

**8.2 G-dev 正例产量**：160 攻击 = tool_output 53 + 用户侧 107。
试跑 gpt-oss：tool_output E = 2/6 ≈ 0.33，用户侧 E = 4/4（探针）/ 2/2（B2 措辞）≈ 0.80。
